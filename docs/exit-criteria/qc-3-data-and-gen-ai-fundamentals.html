Week 4 · Day 1 — Cloud computing concepts

  • qc3.cloud-computing.R01 Required Can define cloud computing and describe its essential characteristics (on-demand self-service, broad network access, resource pooling, rapid elasticity, measured service).
  • qc3.cloud-computing.R02 Required Explain the benefits of using "the cloud" in terms of each cloud service model (IaaS, PaaS, SaaS)
  • qc3.cloud-computing.R03 Required Can describe the public, private, hybrid and multi-cloud deployment models and name a situation that suits each.
  • qc3.cloud-computing.R04 Required Can describe the main challenges of adopting cloud computing (cost control, security and compliance, vendor lock-in, latency, skills) and how an organisation plans for them.
  • qc3.cloud-computing.R05 Required Can explain how cloud services are priced (pay-as-you-go, reserved and committed use, free tiers, charges for compute, storage, queries and data egress) and estimate the cost of a small workload.
  • qc3.cloud-computing.R06 Required Know the difference between a Region and Availability Zone
  • qc3.cloud-computing.R07 Required Can list and explain common GCP services
  • qc3.cloud-computing.P01 Preferred Can name the main data services of AWS, Azure and GCP (object storage, relational and NoSQL databases, data warehouse, data pipeline) and match a service on one provider to its equivalent on the other two.

Week 4 · Day 2 — Big data fundamentals

  • qc3.big-data.R01 Required Can explain the 5 V's of Big Data and describe how they influence data warehouse design.
  • qc3.big-data.R02 Required Can describe the components of a big data system (ingestion, storage, processing, analysis, visualisation) and the role of each.
  • qc3.big-data.R03 Required Can describe a typical big data architecture, including batch and streaming paths, and explain why distributed storage and processing are needed.
  • qc3.big-data.R04 Required Can explain the benefits of big data for an organisation (better decisions, new products, operational efficiency) with an example of each.
  • qc3.big-data.R05 Required Can describe the challenges of big data (data quality, integration of sources, storage and processing cost, privacy and governance, skills).
  • qc3.big-data.R06 Required Can describe the stages of the data lifecycle (generation, collection, storage, processing, analysis, sharing, archival, deletion) and what happens to data at each stage.
  • qc3.big-data.R07 Required Can distinguish structured, semi-structured and unstructured data, give examples of each, and explain how each type is stored and queried.
  • qc3.big-data.R08 Required Can compare common data file formats (CSV, JSON, XML, Parquet, Avro, ORC) by structure, schema handling, compression and typical use, and choose a format for a given workload.

Week 4 · Day 3 — Data warehousing & BigQuery

  • qc3.data-warehousing.R01 Required Can explain the differences between OLTP and OLAP, including their respective use cases.
  • qc3.data-warehousing.R02 Required Can distinguish between Data Warehouses and Data Lakes, and describe the key differences in their architecture and use cases.
  • qc3.data-warehousing.R03 Required Can describe common components of data warehouse architecture and how they interact.
  • qc3.data-warehousing.R04 Required Can define a data mart, explain how it relates to a data warehouse, and describe when a dependent or independent data mart is appropriate.
  • qc3.data-warehousing.R05 Required Can describe common data quality problems (missing values, duplicates, inconsistent formats, invalid values) and the cleansing steps that fix them before data is loaded into a warehouse.
  • qc3.data-warehousing.P03 Preferred Understands different data storage and data warehouse vendors, and can compare cloud-based versus on-premises data warehouse solutions in terms of scalability, cost, and maintenance.
  • qc3.data-warehousing.P07 Preferred Can explain what denormalization is, why analytical stores denormalize where transactional databases normalize, and the trade-off in storage, query speed and update cost.
  • qc3.bigquery.R01 Required Understands BigQuery architecture, including the separation of storage and compute, slot usage, and how queries are executed.
  • qc3.bigquery.R02 Required Can create a dataset in a cloud data warehouse, explain how datasets group tables, and set its location and default table expiration.
  • qc3.bigquery.R03 Required Can create tables, managing schema, and understanding table structures within BigQuery, and set IAM roles and permissions for datasets and tables.
  • qc3.bigquery.R04 Required Can create, modify, and manage table schemas, including adding columns, updating data types, and setting table expiration.
  • qc3.bigquery.R05 Required Can load data into BigQuery using multiple methods (UI, CLI, and load jobs), including using custom schemas.
  • qc3.bigquery.R07 Required Able to write and execute basic SQL queries in BigQuery to retrieve and analyze data.
  • qc3.bigquery.R09 Required Use BigQuery UI and the bq command-line tool effectively.
  • qc3.bigquery.S01 Stretch Implements advanced data transformations, including window functions and recursive queries.

Week 4 · Day 4 — Dimensional modeling

  • qc3.data-warehousing.R06 Required Can define what a data model is and explain its role in organizing, storing, and retrieving data in a data warehouse.
  • qc3.data-warehousing.R07 Required Can explain what data modeling is for and how a model moves from business requirements to tables.
  • qc3.data-warehousing.R08 Required Can explain dimensional modeling concepts, including fact tables, dimension tables, and measures, to create basic data models.
  • qc3.data-warehousing.R09 Required Can explain the purpose and benefits of dimensional modeling in data warehouse design, and differentiate it from entity-relationship modeling.
  • qc3.data-warehousing.R10 Required Can compare different schema designs and identify suitable use cases for each.
  • qc3.data-warehousing.R11 Required Can describe a star schema (a fact table surrounded by dimension tables), identify the grain of the fact table, and design one for a given business process.
  • qc3.data-warehousing.R12 Required Can describe a snowflake schema, explain how it differs from a star schema, and state when the extra normalization is worth its join cost.
  • qc3.data-warehousing.P01 Preferred Can explain and apply key best practices in data warehouse design, including schema design, data quality, and performance optimization.
  • qc3.data-warehousing.P02 Preferred Define and distinguish between conceptual, logical, and physical data models.
  • qc3.data-warehousing.P04 Preferred Can explain how to choose the appropriate Slowly Changing Dimension (SCD) type based on how the data changes and business reporting needs.
  • qc3.data-warehousing.S02 Stretch Can elaborate on all types (0-6) of slowly changing dimensions
  • qc3.data-warehousing.S03 Stretch Can apply dimensional modeling concepts to create basic data models, including designing fact tables, dimension tables, and measures.
  • qc3.bigquery.R08 Required Performs basic data transformations within BigQuery, such as aggregations, joins, and filtering.
  • qc3.bigquery.R10 Required Understands common table partitioning strategies and can explain how partitioning affects cost and performance.
  • qc3.bigquery.P01 Preferred Uses partitioning and clustering to optimize data storage and retrieval and optimize complex queries using query caching

Week 4 · Day 5 — ETL & ELT pipelines

  • qc3.data-warehousing.R13 Required Can describe the ETL (Extract, Transform, Load) process and its role in data warehousing.
  • qc3.data-warehousing.R14 Required Can compare ETL and ELT, explain where the transformation runs in each and why cloud warehouses favour ELT, and describe the steps of a pipeline that loads a source into a warehouse (extract, stage, transform, load, validate, log).
  • qc3.data-warehousing.P05 Preferred Can explain the impact of using staging areas in large-scale ETL pipelines.
  • qc3.data-warehousing.P06 Preferred Can explain the impact of using an Operation Data Store (ODS) in large-scale ETL pipelines.
  • qc3.data-warehousing.P08 Preferred Can explain how a pipeline handles bad records, reruns and incremental loads so that a run can be repeated without duplicating or losing data.
  • qc3.data-warehousing.S01 Stretch Can evaluate trade-offs between different data warehouse architectures and propose an appropriate design for a given business scenario.
  • qc3.bigquery.R06 Required Exports and imports data to and from BigQuery, using various file formats, and destination/source (Google Cloud Storage and Google Sheets)
  • qc3.bigquery.P02 Preferred Can use parameterized queries for better reusability and security.
  • qc3.bigquery.P03 Preferred Uses BigQuery Data Transfer Services to automate the transfer of data from external sources.
  • qc3.bigquery.P04 Preferred Query external data sources like Cloud Storage or Cloud SQL using federated queries
  • qc3.bigquery.P05 Preferred Creates and manages BigQuery Connections (GCS, Cloud SQL, AWS S3) to enable federated or external querying.
