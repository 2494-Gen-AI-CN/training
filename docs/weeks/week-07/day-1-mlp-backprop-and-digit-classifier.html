Multi-layer perceptrons, backprop & digit classifier: how a network learns, and a first full build

Last week ended on one sigmoid neuron built, compiled and fitted in Keras, and this page assumes only that model and its compile, fit and evaluate lines. It explains what a loss is, how gradient descent and backpropagation use it to train every weight, and why one neuron fails on XOR while one hidden layer succeeds. It then builds a digit classifier on MNIST in a project's order: a held-out test set, training curves read in TensorBoard too, a confusion matrix, precision and recall, the wrong digits, one improvement and the limits. Afterwards you can work one backprop update by hand, read training and validation curves together, and walk an interviewer through a model you built.

Loss

Loss: one number for how wrong a model is

Last week's sigmoid neuron was compiled with a loss and trained with fit, and both got one line each. This step opens up the loss, because the rest of the page leans on it: gradient descent lowers it, backpropagation shares it out among the weights, and the digit classifier is trained on it.

Mean squared error, when the answer is a number

A model makes a prediction, and the training data holds the target, the right answer for that row. A loss function turns the gap between the two into one number, and training tries to make that number smaller.1 Lower is better, and 0 means every prediction was exactly right. Which loss you use depends on the kind of answer the model gives.

When the answer is a number, such as a price or a temperature, the usual loss is mean squared error, or MSE. It averages the squared differences between targets and predictions.2 Squaring makes a miss above and a miss below both count as positive, and it makes a big miss cost far more than a small one.

Run in Colab

import numpy as np
import tensorflow as tf

y_true = np.array([3.0, 5.0, 2.5, 7.0, 4.0])
y_pred = np.array([2.5, 5.0, 4.0, 8.0, 3.0])

print((y_pred - y_true) ** 2)
print(f"numpy MSE {np.mean((y_true - y_pred) ** 2):.3f}")
mse = tf.keras.losses.MeanSquaredError()
print(f"Keras MSE {float(mse(y_true, y_pred)):.3f}")
[0.25 0.   2.25 1.   1.  ]
numpy MSE 0.900
Keras MSE 0.900

The first line holds each squared miss. The third prediction is 1.5 off and costs 2.25, while the first is 0.5 off and costs 0.25: three times the miss, nine times the cost. The five costs add up to 4.5, and 4.5 divided by 5 is 0.9. The Keras loss object returns the same number. Because of the squaring, one wild prediction can dominate the average, so a single bad row can make a decent model look poor.

Cross-entropy, when the answer is a class

When the answer is a class, the model outputs a probability, and the loss asks how much probability went to the true class. Binary cross-entropy is the loss for two classes.3 For a row whose true label is 1, it is minus the logarithm of the predicted probability. That is close to 0 when the model says 0.9, and it grows fast as the probability heads towards 0.

Run in Colab

bce = tf.keras.losses.BinaryCrossentropy()
for p in [0.9, 0.6, 0.1]:
    by_hand = -np.log(p)
    keras_value = float(bce([[1.0]], [[p]]))
    print(f"true 1, predicted {p}: numpy {by_hand:.3f}, Keras {keras_value:.3f}")
true 1, predicted 0.9: numpy 0.105, Keras 0.105
true 1, predicted 0.6: numpy 0.511, Keras 0.511
true 1, predicted 0.1: numpy 2.303, Keras 2.303

Confident and right costs 0.105, unsure costs 0.511, and confident and wrong costs 2.303, about twenty times the first. That steep cost for a confident mistake is why cross-entropy is the loss for classes. The cell calls the loss once per prediction on purpose. A Keras loss averages over the batch it is given,3 so passing all three rows in one call would print their mean, about 0.973.

Last week's "binary_crossentropy" string was this number, averaged over each batch of rows. You recognise the choice of loss in a compile line:

  • loss="mse" when the model predicts a number2
  • loss="binary_crossentropy" when it predicts one of two classes with a sigmoid output3
  • metrics=["accuracy"] beside either one, which is reported each epoch but is not the number training lowers1
Takeaways
  • A loss is one number for how wrong the predictions are; lower is better.
  • Mean squared error suits a numeric answer and punishes big misses most.
  • Cross-entropy suits a class and costs most when the model is confident and wrong.
Say it in an interview

A loss function turns how wrong the model is into one number, and training tries to push it down. If the model predicts a number I'd use mean squared error, the average squared miss. If it predicts a class I'd use cross-entropy, which is small when the true class gets a high probability and very large when the model is confident and wrong.

Gradient descent

Gradient descent: small steps downhill

A loss says how wrong the model is. Gradient descent is how training makes it less wrong: it changes each weight by a small step in the direction that lowers the loss, then does it again, many times.

Downhill on one weight

Take the smallest model there is: one weight w, and a prediction of w * x. The data is x = 1, 2, 3, 4 with targets y = 2.0 * x, so the best weight is 2. Every candidate w has an MSE, and drawn against w those losses make a bowl: high at 0, zero at 2, and rising again past 2.

The slope of the bowl at the current w says which way is downhill. A positive slope means the loss rises as w grows, so w should shrink, and a negative slope means it should grow. You can find the slope without any calculus: move the weight a hair each way and see how much the loss changes. That is the centred nudge, (loss(w + 0.001) - loss(w - 0.001)) / 0.002.

Plain gradient descent then updates the weight as w = w - learning_rate * g, where g is the slope: a small step against it.4

Run in Colab

x = np.array([1.0, 2.0, 3.0, 4.0])
y = 2.0 * x

def line_loss(w):
    return np.mean((w * x - y) ** 2)

def slope(w):
    return (line_loss(w + 0.001) - line_loss(w - 0.001)) / 0.002

w = 0.0
for step in range(6):
    print(f"step {step}: w = {w:.3f}, loss = {line_loss(w):.3f}, slope = {slope(w):.3f}")
    w = w - 0.05 * slope(w)
step 0: w = 0.000, loss = 30.000, slope = -30.000
step 1: w = 1.500, loss = 1.875, slope = -7.500
step 2: w = 1.875, loss = 0.117, slope = -1.875
step 3: w = 1.969, loss = 0.007, slope = -0.469
step 4: w = 1.992, loss = 0.000, slope = -0.117
step 5: w = 1.998, loss = 0.000, slope = -0.029

At w = 0 every prediction is 0, so the misses are 2, 4, 6 and 8, and their squares average to 30. The slope is −30, negative, so the update adds 0.05 × 30 = 1.5 and w moves to 1.5. The last line of the loop is the whole method. Near the bottom the bowl flattens, the slope shrinks, and the steps shrink with it, so w settles at 2 without being told where 2 is.

The learning rate is the step size

The learning rate multiplies the slope before the step is taken.4 Too small and training crawls. Too large and each step overshoots the bottom of the bowl, lands higher up the far side, and the loss bounces or grows instead of falling.4 The cell runs ten steps at three rates.

Run in Colab

for rate in [0.01, 0.05, 0.2]:
    w = 0.0
    for step in range(10):
        w = w - rate * slope(w)
    print(f"rate {rate}: w = {w:.3f}, loss = {line_loss(w):.1f}")
rate 0.01: w = 1.606, loss = 1.2
rate 0.05: w = 2.000, loss = 0.0
rate 0.2: w = -2046.000, loss = 31457280.0

At 0.01 the weight is still at 1.606 after ten steps. At 0.05 it reaches 2. At 0.2 the first step takes w from 0 to 6, four past the target where it started two short of it. Every later step doubles the distance and flips the side, so the loss explodes.

Learning rateWhat the loss doesWhat to try
too smallfalls slowly and is still falling at the enda larger rate or more epochs

too largebounces, or climbsa smaller rate

In someone else's code, tf.keras.optimizers.SGD(learning_rate=0.01) is this same plain update with its step size spelled out.4 The string "adam" in a compile line is a refinement of it that step 5 names.

Takeaways
  • Gradient descent steps each weight against its slope, again and again.
  • The slope can be measured by nudging the weight a hair each way.
  • The learning rate is the step size: too small crawls, too large overshoots and diverges.
Say it in an interview

Gradient descent works out which way each weight should move to lower the loss, the slope, and takes a small step the other way, over and over. The learning rate is the size of that step. Too small and training crawls; too large and it overshoots the minimum, so the loss bounces around or blows up.

Perceptron limits

The limit of one perceptron: XOR

Last week's perceptron learned the AND table, and its page showed that the learning rule never settles when the two classes cannot be split by a straight line. This step names the classic table where that happens. It is the reason networks have hidden layers.

Four points no straight line separates

XOR, short for "exclusive or", outputs 1 when exactly one of its two inputs is 1. Its four rows are (0, 0) → 0, (0, 1) → 1, (1, 0) → 1 and (1, 1) → 0, and no single straight line splits the 1s from the 0s.5

Picture the four points on the corners of a square. The two 1s sit on one diagonal and the two 0s on the other, so any line that puts both 1s on one side takes at least one 0 with them.

A perceptron is a linear classifier: it draws one straight line and labels each point by the side it falls on.5 The best any line can do on XOR is three points out of four, an accuracy of 0.75. The cell below checks that by brute force. It tries every line whose two weights and bias lie on a grid from −2 to 2 in steps of 0.2, which is 21 × 21 × 21 = 9,261 lines.

Run in Colab

X_xor = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], dtype="float32")
y_xor = np.array([0, 1, 1, 0])

best = 0.0
values = np.linspace(-2, 2, 21)
for w1 in values:
    for w2 in values:
        for b in values:
            pred = (X_xor @ np.array([w1, w2]) + b >= 0).astype(int)
            best = max(best, np.mean(pred == y_xor))
print("best accuracy of any line tried:", best)
best accuracy of any line tried: 0.75

The line inside the loop is last week's perceptron. X_xor @ np.array([w1, w2]) multiplies each row's two inputs by the two weights and adds them, giving one sum per row, and >= 0 is the step. np.mean(pred == y_xor) is the share of rows the line gets right. No line on the grid beats 0.75.

One sigmoid neuron trained on XOR

Swapping the step for a sigmoid does not help. A sigmoid output with no hidden layer still has a straight decision boundary.6 Its output is a probability, but the line where that probability crosses 0.5 is straight. The cell trains last week's one-neuron Keras model on the four rows. The learning rate is set to 0.05 by hand so that four points train in a few hundred steps.

Run in Colab

tf.keras.utils.set_random_seed(42)
neuron = tf.keras.Sequential([
    tf.keras.Input(shape=(2,)),
    tf.keras.layers.Dense(1, activation="sigmoid"),
])
neuron.compile(optimizer=tf.keras.optimizers.Adam(learning_rate=0.05),
               loss="binary_crossentropy", metrics=["accuracy"])
neuron.fit(X_xor, y_xor, epochs=300, verbose=0)
print(neuron.evaluate(X_xor, y_xor, verbose=0))

The cell prints [loss, accuracy]. The loss is about 0.693, minus the log of 0.5: the neuron gives every point a probability of about 0.5. That close to 0.5, rounding decides which side of the cut each point lands on, so the accuracy can print 0.25, 0.5 or 0.75, never 1.0.

Accuracy stuck below 1.0 on these four points means the model cannot learn the table, so more epochs will not help.5 A single neuron can only learn what one straight line can split, however long it trains. The property it lacks is called linear separability: two classes are linearly separable when one straight line, or one flat surface in more dimensions, puts them on opposite sides.

Takeaways
  • XOR's 1s and 0s sit on opposite diagonals, so no straight line splits them.
  • One neuron draws one straight boundary, so its best on XOR is three of four points.
  • More epochs cannot fix a model that cannot draw the needed shape.
Say it in an interview

A perceptron is one neuron: a weighted sum plus a bias, through a step or a sigmoid. Whatever its weights, it draws one straight line, so it can only separate classes that are linearly separable.

It cannot do XOR. The two 1s are on one diagonal of the square and the two 0s on the other, so the best line gets three of four right. Adding one hidden layer with a non-linear activation fixes it.

MLP

Multi-layer perceptrons: a hidden layer and what it adds

A multi-layer perceptron, or MLP, is a network of Dense layers with at least one hidden layer between the input and the output. A layer is hidden because its outputs are neither the inputs you supply nor the answer you read: they are numbers the network makes for its own use.

One hidden layer solves XOR

An MLP, one or more hidden layers with a non-linear activation, can learn decision boundaries that a single linear unit cannot.7 The smallest one for XOR puts four tanh units between the two inputs and the sigmoid output. Tanh, from last week, squashes a sum into the range −1 to 1. The cell differs from the single neuron's by one line, the hidden Dense(4, activation="tanh").

Run in Colab

tf.keras.utils.set_random_seed(42)
xor_mlp = tf.keras.Sequential([
    tf.keras.Input(shape=(2,)),
    tf.keras.layers.Dense(4, activation="tanh"),
    tf.keras.layers.Dense(1, activation="sigmoid"),
])
xor_mlp.compile(optimizer=tf.keras.optimizers.Adam(learning_rate=0.05),
                loss="binary_crossentropy", metrics=["accuracy"])
xor_mlp.fit(X_xor, y_xor, epochs=300, verbose=0)
print(xor_mlp.count_params())
print(xor_mlp.evaluate(X_xor, y_xor, verbose=0))

The first line prints 17. A Dense layer holds one weight per input per unit plus one bias per unit,6 so the hidden layer has 2 × 4 + 4 = 12 and the output layer 4 × 1 + 1 = 5. The second line is [loss, accuracy]: with this seed the loss falls to about 0.003 and the accuracy reaches 1.0, all four rows right, where the single neuron stayed at a loss of 0.693.

Why the hidden layer needs a non-linear activation

Last week's page showed that two weighted sums in a row collapse into one: 3x + 1 followed by 2z + 4 is just 6x + 6. Whole layers behave the same way. Without a non-linear activation, stacked Dense layers collapse into one linear map, which draws one straight boundary again; relu and tanh supply the bend.8 A network of ten Dense layers with no activations would still fail XOR.

With the bend in place, the hidden units re-describe the four points. Each point goes in as two numbers and comes out of the hidden layer as four new ones, and in that new description one straight line does separate the 1s from the 0s.7 The output neuron draws that line. So a hidden layer is a learned change of coordinates, chosen by training so that the last layer's job becomes easy.

Each layer's activation follows from what it has to produce:

LayerActivationWhy
hiddenrelu or tanhsupplies the bend that stops the layers collapsing
output, two classessigmoidone probability between 0 and 1
output, ten classessoftmaxten probabilities that sum to 18

Width has a cost. More hidden units fit more shapes, but on a small training set they also memorise its rows, noise included.9 That memorising is overfitting, and step 7 produces it on purpose.

A multi-layer perceptron is a stack of fully connected layers with at least one hidden layer between the input and the output. The hidden layer has to have a non-linear activation like ReLU or tanh, because without it the layers collapse into one linear map and you're back to a single straight boundary.

What the hidden units learn is a new description of the input, where the classes become separable by a line that the output layer can draw. That's how one hidden layer of four units solves XOR.

Backprop

The backpropagation algorithm

Gradient descent needs a slope for every weight. With one weight, nudging it was cheap. The digit classifier later on this page has 101,770 weights, and backpropagation is how a network gets all of their slopes at once.

One training step: forward, loss, backward, update

Backpropagation computes the slope of the loss with respect to every weight by passing it backward through the network, layer by layer, and an optimizer then applies the update.13 One training step has four parts, and training repeats them for every batch:13

  1. Forward pass: the batch goes through the layers, input to output, and becomes predictions.
  2. Loss: the predictions are compared with the targets, giving one number.
  3. Backward pass: starting at the loss, each layer works out its own weights' share of the loss and hands the rest back to the layer before it.
  4. Update: every weight takes a gradient-descent step against its slope.

A weight's slope is also called its gradient: how much the loss would change if that weight moved a little. The output layer's weights touch the loss directly. A hidden weight affects the loss only through the layers after it, so its slope is built from theirs. That is why the pass runs backward, from the loss towards the input.

In code, one call to model.fit(...) runs all four parts for every batch, epoch after epoch. Older TFLearn tutorials do the same with tflearn.regression(...) followed by tflearn.DNN(net).fit(...), which in Keras is compile then fit.

Why passing the loss backward beats nudging each weight

Step 2's centred nudge also finds slopes, and it approximates the same numbers backprop returns.13 Its cost is the problem. Each weight needs two extra forward passes, one with the weight a hair up and one a hair down. For 101,770 weights that is 203,540 forward passes for a single update. Backpropagation gets every slope from one forward pass and one backward pass through the same layers.

Backprop has a requirement of its own. Every layer must be differentiable, which means it has a slope, and so must the loss; a step function gives no slope.13 The step is flat everywhere except at its jump, so nudging a weight changes nothing and the slope comes out as 0, with no direction to move. That is why networks trained this way use sigmoid, tanh and ReLU instead of the perceptron's step.

Backprop finds the slopes; the optimizer takes the step

Backprop and gradient descent are two halves of one training step. Backprop supplies the slopes, and the optimizer decides how far to move each weight. Plain gradient descent, SGD in Keras, moves every weight by the learning rate times its slope.4 Adam, the optimizer behind every "adam" string on this page, is gradient descent whose step size adapts for each weight.14

PartIts jobWhere it appears in Keras
lossone number for how wrong the batch wasloss= in compile
backpropagationa slope for every weightinside fit, with no line of its own
optimizerthe step each weight takesoptimizer= in compile

The learning rate sits inside the optimizer. It scales every step, so the same backprop slopes give a timid update at 0.001 and a reckless one at 1.0.

Takeaways
  • A training step is forward pass, loss, backward pass, update, repeated for every batch.
  • Backprop gets every weight's slope in one backward pass, where nudging needs two passes per weight.
  • Backprop finds the slopes; the optimizer, scaled by the learning rate, takes the step.
Say it in an interview

Backpropagation is how a network works out which way each weight should move. You run the batch forward, compute the loss, then pass the loss backward layer by layer, so every weight gets its share of the blame as a slope. The optimizer then moves each weight a step against its slope, and the learning rate sets how big that step is.

Nudging weights one at a time would need two forward passes per weight, so this is much cheaper. Backprop gets all the slopes from one forward and one backward pass.

Backprop by hand

Understanding backprop on a two-weight network

The algorithm is easier to trust once you have pushed numbers through it by hand. This step uses the smallest network that still has a hidden layer: one input, one hidden unit and one output, joined by two weights, with no bias and no activation.

The forward pass and the loss

The input is x = 2.0 and the target is 1.0. The hidden weight is w1 = 0.5 and the output weight is w2 = 1.5. The forward pass multiplies its way through. The hidden value is h = w1 × x = 1.0, and the prediction is w2 × h = 1.5. The squared-error loss for this one row is (1.5 − 1.0)² = 0.25.

The prediction is too high, so both weights should shrink: a smaller w1 makes h smaller, and a smaller w2 scales h down. An update that subtracts the slope does exactly that when both slopes are positive.4

Each weight's slope, and why w1's is larger

The cell finds each slope with the centred nudge, holding the other weight still, then takes one step at a learning rate of 0.02.

Run in Colab

x_row, target = 2.0, 1.0
w1, w2 = 0.5, 1.5

def pair_loss(w1, w2):
    h = w1 * x_row
    prediction = w2 * h
    return (prediction - target) ** 2

print(f"prediction {w2 * w1 * x_row}, loss {pair_loss(w1, w2)}")
slope_w2 = (pair_loss(w1, w2 + 0.001) - pair_loss(w1, w2 - 0.001)) / 0.002
slope_w1 = (pair_loss(w1 + 0.001, w2) - pair_loss(w1 - 0.001, w2)) / 0.002
print(f"slope w2 {slope_w2:.3f}, slope w1 {slope_w1:.3f}")
w2 = w2 - 0.02 * slope_w2
w1 = w1 - 0.02 * slope_w1
print(f"w2 {w2:.2f}, w1 {w1:.2f}, prediction {w2 * w1 * x_row:.2f}, loss {pair_loss(w1, w2):.3f}")
prediction 1.5, loss 0.25
slope w2 1.000, slope w1 3.000
w2 1.48, w1 0.44, prediction 1.30, loss 0.091

The second line holds the two slopes, and both are positive, as the reasoning above expected. w1, the weight furthest from the output, gets the larger one. Nudge the prediction itself and the loss moves by 1.0 per unit; that is the share of the loss arriving at the output.

  • w2 multiplies h = 1.0 on its way to the prediction, so its slope is 1.0 × 1.0 = 1.0.
  • w1's change reaches the prediction twice multiplied: by x = 2.0 into h, then by w2 = 1.5 out of it. Passed back, its share is 1.0 × 1.5 × 2.0 = 3.0.

That is the chain of slopes backprop follows: an earlier weight's slope is multiplied by every weight it passes on the way back. You can see it here without a derivative: it is the multiplications of the forward pass run in reverse.

One update and the new loss

The update is plain gradient descent, each weight minus 0.02 times its slope.4 So w2 becomes 1.5 − 0.02 × 1.0 = 1.48 and w1 becomes 0.5 − 0.02 × 3.0 = 0.44. Run forward again: h = 0.44 × 2.0 = 0.88, and the prediction is 0.88 × 1.48, about 1.30. The loss falls from 0.25 to about 0.091, which is the third line of the output.13

The prediction moved from 1.5 towards 1.0 without passing it, so this step did not overshoot. That depends on this row and the rate of 0.02, and at a large enough rate the same slopes would carry the prediction past the target. Repeat the step and the loss keeps shrinking, which is all fit does, for many weights and many rows at once.

TensorFlow finds the same slopes

This check is optional. tf.GradientTape records the operations inside its with block, and tape.gradient(loss, variables) returns the slopes.13 It is the machinery fit uses on every batch.

Run in Colab

w1_t = tf.Variable(0.5)
w2_t = tf.Variable(1.5)
with tf.GradientTape() as tape:
    loss_t = (w2_t * (w1_t * 2.0) - 1.0) ** 2
grad_w2, grad_w1 = tape.gradient(loss_t, [w2_t, w1_t])
print(f"slope w2 {float(grad_w2):.1f}, slope w1 {float(grad_w1):.1f}")
slope w2 1.0, slope w1 3.0

The slopes come back in the order the variables were passed in, w2 first, so 1.0 and 3.0 match the nudges exactly. This example is small: with no activation and no bias it shows the bookkeeping and leaves out the full behaviour of a real Dense layer.6 Writing a whole training loop around the tape is Thursday's page.

Takeaways
  • Forward pass: h = 1.0, prediction 1.5, loss 0.25.
  • Slopes are 1.0 for w2 and 3.0 for w1, because w1's share passes through w2 and x.
  • One step at learning rate 0.02 drops the loss from 0.25 to about 0.091.
Say it in an interview

Take one input of two, a hidden weight of 0.5 and an output weight of 1.5. The forward pass gives a hidden value of 1 and a prediction of 1.5 against a target of 1, so the squared error is 0.25. The prediction is too high, so both weights need to come down.

The output weight's slope is 1. The hidden weight's slope is 3, because its effect is multiplied by the output weight and the input on the way back. At a learning rate of 0.02 the weights become 1.48 and 0.44, and the loss drops to about 0.09.

Build

Build: an MLP digit classifier, in a project's order

The problem, the dataset, the split and preprocessing

The problem is to read a handwritten digit from its pixels, the job a post office or a bank does when it reads forms. The dataset is MNIST: tf.keras.datasets.mnist.load_data() returns 60,000 training and 10,000 test images of 28 × 28 pixels, each labelled with its digit, 0 to 9.15

The test set is held out now and used once, at the end; every choice before then is made on the validation data. The validation rows are the last 6,000 training images: the model is scored on them during training but never learns from them.

Run in Colab

(x_train, y_train), (x_test, y_test) = tf.keras.datasets.mnist.load_data()

The model, with a reason for each choice

Run in Colab

    tf.keras.Input(shape=(784,)),

The summary's total is 101,770 parameters: 784 × 128 + 128 = 100,480 in the hidden layer and 128 × 10 + 10 = 1,290 in the output.6 Each choice has a reason:

ChoiceReason
one hidden Dense(128)the simplest MLP: one hidden layer at a common starting width
relu in the hidden layerthe bend that stops the two layers collapsing into one
Dense(10, activation="softmax")ten probabilities that sum to 1; argmax picks the digit17

Training with both curves on one chart

Passing validation_data=(x_val, y_val) to fit reports val_loss each epoch on rows the weights are never updated from, and History.history holds both curves.1 batch_size=128 means one update per 128 rows, so one epoch is 422 updates.

Run in Colab

import matplotlib.pyplot as plt

def plot_history(history, metric="loss", title=""):
    """Draw the training and validation curves of one metric on one chart."""
    plt.plot(history.history[metric], label="training")
    plt.plot(history.history["val_" + metric], label="validation")
    plt.xlabel("epoch")
    plt.ylabel(metric)
    plt.title(title)
    plt.legend()
    plt.show()

history = digit_model.fit(x_tr, y_tr, epochs=10, batch_size=128,
                          validation_data=(x_val, y_val),
                          callbacks=[tf.keras.callbacks.TensorBoard(log_dir="logs/fit")],

Both lines fall and stay close together: that is a network learning. Overfitting on purpose

Train the same shape on only the first 1,000 rows for 50 epochs, against the same 6,000 validation rows.

Evaluation

Evaluating a classifier on the validation data

A validation accuracy of 0.97 says how often the model is right. It does not say which digits it gets wrong, or whether it ignores one of them. This step looks underneath that number, still on the validation rows.

The confusion matrix

A confusion matrix is a table of true classes against predicted classes, so it shows which classes get mistaken for which. confusion_matrix(y_true, y_pred) puts the true classes on the rows and the predicted classes on the columns.22

Run in Colab

from sklearn.metrics import confusion_matrix, ConfusionMatrixDisplay

val_pred = digit_model.predict(x_val, verbose=0).argmax(axis=1)
cm = confusion_matrix(y_val, val_pred)
ConfusionMatrixDisplay(cm).plot()
plt.show()

predict returns 6,000 rows of ten probabilities. argmax(axis=1) picks, for each row, the column holding the largest probability, which is the predicted digit. The chart is ten by ten. The diagonal counts correct answers, and every other cell counts one kind of mistake: the cell at row 4, column 9 counts 4s read as 9s. Read the largest off-diagonal counts first.

Precision, recall and F1 for one digit

To score one digit, ask a yes-or-no question of every image: is it a 5? A true positive (TP) is a 5 called 5, a false positive (FP) is another digit called 5, and a false negative (FN) is a 5 called something else.

  • Precision is TP / (TP + FP): of the images called 5, the share that really are 5s.23
  • Recall is TP / (TP + FN): of the real 5s, the share the model found.23
  • F1 combines precision and recall into one number, their harmonic mean, an average pulled towards the smaller of the two, so it is high only when both are.23

With made-up counts: the model calls 100 images 5, 95 of them are 5s, and there are 105 real 5s. Precision is 95 / 100 = 0.95, recall is 95 / 105, about 0.905, and F1 is about 0.927.

Run in Colab

from sklearn.metrics import precision_score, recall_score, f1_score

is_five_true = y_val == 5
is_five_pred = val_pred == 5
print(f"precision {precision_score(is_five_true, is_five_pred):.3f}")
print(f"recall    {recall_score(is_five_true, is_five_pred):.3f}")
print(f"F1        {f1_score(is_five_true, is_five_pred):.3f}")

The two == 5 lines turn the digit labels into True or False for "is a 5". Each score lies between 0 and 1, and higher is better. Precision below recall means the model invents 5s more often than it misses them; the reverse means it misses more. Averaging these scores over all ten digits is week 8's topic.

When accuracy misleads

5s are about one image in eleven. A model that always answers "not 5" is right about ten times in eleven without looking at a single pixel.

Run in Colab

always_not_five = np.zeros_like(is_five_true)
print(f"accuracy {np.mean(always_not_five == is_five_true):.3f}")
print(f"recall   {recall_score(is_five_true, always_not_five):.3f}")

The accuracy comes out at about 0.91 and the recall at 0.000: it never finds a 5.23 On an unbalanced problem, where one class is rare, accuracy rewards ignoring the rare class. Recall counts the misses, so it exposes the trick at once.

Error analysis: the digits it gets wrong

The last check is to look at the mistakes themselves. The helper draws images in a grid with a title under each.

Run in Colab

def show_image_grid(images, titles, columns=5):
    """Draw 28 by 28 images in rows of `columns`, each with its title."""
    rows = int(np.ceil(len(images) / columns))
    plt.figure(figsize=(2.2 * columns, 2.4 * rows))
    for i, (image, title) in enumerate(zip(images, titles)):
        plt.subplot(rows, columns, i + 1)
        plt.imshow(image.reshape(28, 28), cmap="gray")
        plt.title(title)
        plt.axis("off")
    plt.show()

wrong = np.where(val_pred != y_val)[0][:15]
show_image_grid(x_val[wrong], [f"true {y_val[i]}, predicted {val_pred[i]}" for i in wrong])

np.where(val_pred != y_val)[0] gives the positions of the wrong rows, and [:15] keeps the first fifteen. Each image is reshaped back to 28 by 28 to be drawn. Read the grid for what the mistakes share:

  • digits written in a less common way, such as a 7 with a crossbar read as a 3 or a 9, or a 1 with a flag and a foot read as a 2;
  • 3s, 5s and 8s that differ by a few pixels of loop;
  • strokes much thicker or thinner than usual, and some tilted digits.

A shared cause is something an improvement can target.

Takeaways
  • A confusion matrix shows which digits get mistaken for which.
  • Precision asks how many called 5 are 5s; recall asks how many 5s were found.
  • Always answering "not 5" scores about 91% accuracy with a recall of 0.
  • The misclassified images show what the mistakes have in common.
Say it in an interview

Accuracy hides which mistakes the model makes, so I look at a confusion matrix, true classes against predicted, and then precision and recall per class. Precision is how many of the things I flagged were right; recall is how many of the real ones I found. F1 combines them and is only high when both are.

Accuracy misleads when classes are unbalanced. If fives are one in eleven, a model that never says five gets about ninety-one percent accuracy and finds none of them.

Build

One improvement attempt, the test set once, and limitations

The build ends the way a project should: one change measured fairly, one look at the test set, and a plain note on what the model cannot do.

One change, measured on the same validation rows

Change one thing, so that any difference has one cause. Here the change is a second hidden layer of 64 ReLU units, fitted exactly as before. The validation rows stay fixed, the last 6,000 of the training images, and that is what makes the before-and-after comparison fair.1 A results list keeps one row per trained model, with the numbers evaluate returns on the validation data.

Run in Colab

import pandas as pd

results = []
val_loss, val_acc = digit_model.evaluate(x_val, y_val, verbose=0)
results.append({"model": "784-128-10", "val_loss": val_loss, "val_accuracy": val_acc})

deeper_model = tf.keras.Sequential([
    tf.keras.Input(shape=(784,)),
    tf.keras.layers.Dense(128, activation="relu"),
    tf.keras.layers.Dense(64, activation="relu"),
    tf.keras.layers.Dense(10, activation="softmax"),
])
deeper_model.compile(optimizer="adam", loss="sparse_categorical_crossentropy",
                     metrics=["accuracy"])
deeper_model.fit(x_tr, y_tr, epochs=10, batch_size=128,
                 validation_data=(x_val, y_val), verbose=0)

The table has two rows, one per model. Compare val_loss first, since it is the number training lowered; the row with the lower one is the model you keep. Then write one plain sentence: it helped, it did not, or the gap is too small to matter. On 6,000 rows an accuracy gap of 0.001 is six images.

On these settings the second layer did not lower the validation loss (about 0.10 against 0.08), so the first model is kept. "It did not help" is still a result, and its row stays in the table. A gap this small can tip the other way on another library version. Other levers, such as more epochs or a different learning rate, are Friday's page.

What the model cannot do

It reads only digits like MNIST's: centred, about the same size, and white on a black background, so a dark digit on white paper or one in a corner is outside what it learned. Flattening each image into 784 numbers throws away which pixels are neighbours, and a convolutional network keeps that.24

Takeaways
  • Change one thing and compare it on the same validation rows in a results table.
  • Choose the kept model on validation loss, then evaluate it on the test set once.
  • The model reads centred MNIST-style digits only, and flattening loses which pixels are neighbours.

Then I tried one change, a second hidden layer, compared both on the same validation rows, kept the better one and scored it on the test set once. Check yourself

Check yourself

Ten questions, at least one per step. Answer each out loud before you open it.

Five predictions miss their targets by 0.5, 0, 1.5, 1 and 1. What is the mean squared error, and which miss costs the most?

The squared misses are 0.25, 0, 2.25, 1 and 1, which add up to 4.5, so the MSE is 4.5 / 5 = 0.9. The miss of 1.5 costs 2.25 on its own, because squaring makes big misses count far more than small ones.

One model gives the true class a probability of 0.9 and another gives it 0.1. What is each one's cross-entropy, and why is the gap so large?

About 0.105 and 2.303. Cross-entropy is minus the log of the probability given to the true class, so it grows fast as that probability heads towards 0, and a confident wrong answer costs the most.

From the first epoch, the training loss bounces up and down and then climbs. What is the likely cause, and what do you change?

The learning rate is too large: each step overshoots the bottom of the loss and lands higher on the far side. Lower the learning rate.

Why can a single sigmoid neuron not learn XOR, however many epochs it trains?

One neuron draws one straight boundary, and XOR's 1s and 0s sit on opposite diagonals of a square, so the best any line can do is three points of four. Accuracy stuck below 1.0 means the model is not able to draw the shape, not that it needs more training.

A colleague stacks three Dense layers with no activation and is surprised it still fails XOR. What do you tell them?

Without a non-linear activation, stacked Dense layers collapse into one linear map, which draws one straight boundary. A hidden layer with ReLU or tanh supplies the bend, and four tanh units are enough for XOR.

Name the four parts of one training step, and say why backprop is cheaper than nudging every weight.

Forward pass, loss, backward pass for the slopes, then the update. Nudging needs two extra forward passes per weight, over 200,000 for the digit classifier, while backprop gets every slope from one forward and one backward pass.

On the network with x = 2.0, w1 = 0.5, w2 = 1.5 and target 1.0, why does w1 get a slope of 3 when w2 gets 1?

w2 multiplies the hidden value 1.0 on its way to the prediction, so its slope is 1.0. w1's effect is multiplied by x = 2.0 and then by w2 = 1.5, so passed back its share is 1.0 × 1.5 × 2.0 = 3.0. One step at learning rate 0.02 drops the loss from 0.25 to about 0.091.

Training loss keeps falling while validation loss turns and rises. What is happening, and what would you do?

The model is overfitting: it is memorising the training rows instead of learning the pattern. Stop at the epoch where validation loss was lowest, which is what early stopping automates, or use fewer hidden units.

A model that always answers "not 5" scores about 91% accuracy on MNIST. What is its recall for 5, and what does that teach you about accuracy?

Its recall is 0: it finds none of the real 5s. On an unbalanced problem accuracy rewards ignoring the rare class, so you read recall and precision per class, and a confusion matrix, beside it.

Why is the test set used only once, at the end, and what do you compare models on before that?

If you chose or changed the model after reading the test score, the test set would become a second validation set and the score would stop being an honest estimate. Every comparison before then, such as the second hidden layer, is made on the fixed validation rows.
