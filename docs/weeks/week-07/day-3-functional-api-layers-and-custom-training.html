Functional composition

Functional composition: layers called like functions

Every model so far this week was a straight stack built with tf.keras.Sequential: each layer feeds the next one. The Functional API builds the same networks a second way, and it can also build shapes where the data branches and joins.

Inputs, layer calls and Model

The Functional API builds a model in three moves. You create an input with tf.keras.Input, call each layer on the result of the one before as if the layer were a function, and hand the first and last results to tf.keras.Model(inputs, outputs).1 Calling a layer on a Keras tensor returns a new Keras tensor, which is why the calls chain.1

A Keras tensor is a placeholder. It records a shape and the layers that led to it, and it holds no numbers yet. The calls draw a map of the network; real data flows along that map later.

Run in Colab

import numpy as np
import tensorflow as tf

inputs = tf.keras.Input(shape=(784,))
x = tf.keras.layers.Dense(128, activation="relu")(inputs)
outputs = tf.keras.layers.Dense(10, activation="softmax")(x)
functional_model = tf.keras.Model(inputs, outputs)

print(x.shape, outputs.shape)
print(functional_model.count_params())
print(functional_model(np.zeros((2, 784), dtype="float32")).shape)
(None, 128) (None, 10)
101770
(2, 10)

The line that does the work is the one starting x =. Dense(128, activation="relu") makes the layer, and the (inputs) straight after it calls the layer on the input. The first output line shows what each call returned: a placeholder with 128 values per row, then one with 10. None stands for the batch size, which is not known until data arrives.

The count of 101,770 is the same as Monday's Sequential digit network. A Dense layer on n inputs with u units holds n × u + u numbers.2 Here that is 784 × 128 + 128 = 100,480 for the hidden layer and 128 × 10 + 10 = 1,290 for the output layer.

The last line runs the recorded map on two rows of zeros and gets two rows of ten probabilities back, which is why the same layer calls work on real data later.

functional_model.summary() prints the same facts as a table, one row per layer with its output shape and parameter count. For this network the Functional table and the Sequential table match row for row.1

SequentialFunctional API
Shapes it buildsA plain stack with one input tensor and one output tensor3Branches, merges, several inputs or outputs1
How it is writtenA list of layersAn input, layer calls, then Model(inputs, outputs)
Spotted in code bytf.keras.Sequential([...])layer(...)(x) and tf.keras.Model(inputs, outputs)

The trade-off is length. Sequential is shorter and is enough for a straight stack, so a team reaches for the Functional API only when the model branches, merges or has several inputs or outputs.1

A skip connection: a shape Sequential cannot build

A skip connection carries a layer's input past one or more layers and joins it to a later layer's output. tf.keras.layers.Concatenate does the joining: it takes a list of tensors and lays them side by side along the last axis, the axis that holds each row's values.4 Below, the raw 784 pixels skip past the hidden layer and are joined to its 128 outputs, so the output layer reads both the image and what the hidden layer made of it.

Run in Colab

inputs = tf.keras.Input(shape=(784,))
hidden = tf.keras.layers.Dense(128, activation="relu")(inputs)
joined = tf.keras.layers.Concatenate()([inputs, hidden])
outputs = tf.keras.layers.Dense(10, activation="softmax")(joined)
skip_model = tf.keras.Model(inputs, outputs)

print(joined.shape)
print(skip_model.count_params())
(None, 912)
109610

784 + 128 = 912 values per row reach the output layer. That layer now holds 912 × 10 + 10 = 9,130 numbers, and with the hidden layer's 100,480 the model holds 109,610.4 Deleting the joined line and calling the output layer on hidden brings the count back to 101,770.

Sequential cannot express this model, because inputs is used twice: once by the hidden layer and once by the join. A Sequential model passes each layer's output only to the next layer.3 In other people's code you spot the pattern as Concatenate()([a, b]) or Add()([a, b]) inside a Functional model.

To see the branch as a picture, tf.keras.utils.plot_model(skip_model, show_shapes=True) draws the layer graph with each shape on it. It needs pydot and Graphviz, two graph-drawing tools that Colab already has installed.5

Takeaways
  • The Functional API calls layers on tensors like functions, then wraps the ends in a Model.
  • A layer call on an Input records the network; numbers flow through it later.
  • A skip connection reuses a tensor twice, so it needs the Functional API.
Say it in an interview

I use the Functional API when the model isn't a straight stack: a branch, a merge, or more than one input or output. I create an Input, call each layer on the previous result as if it were a function, and wrap the first and last tensors in a Model. For a plain stack, Sequential is shorter, so I'd use that.

A skip connection carries a layer's input past it and joins it to a later output, for example with Concatenate. It needs the Functional API because the input is used twice, and Sequential only hands each output to the next layer.

Predefined layers

Predefined layers: chosen by what they read

Keras ships ready-made layers, and a team rarely writes its own. Choosing one starts from a plain question: what shape of data does this layer read, and what shape does it hand on?

The layers a team reaches for

All seven layers in the table below live in tf.keras.layers.6 The table reads each one by its input and output for a single example; the batch axis in front is left out.

LayerReadsHands on
DenseA row of numbersA row of units numbers
FlattenSeveral axes, such as a 28 by 28 imageOne long row of 784
DropoutAny valuesThe same shape, a random share set to 0 while training
BatchNormalizationAny valuesThe same shape, rescaled per batch
Conv2DAn image with a channel axisA stack of feature maps
MaxPooling2DFeature mapsThe same maps at half the height and width
EmbeddingWhole-number token idsOne vector per id

A channel axis is the last axis of an image array, holding one number per pixel for each colour; a grey digit has one channel. A feature map is a convolution's output grid, one number per position the filter visited. A token id is one word of a text replaced by its number in a vocabulary. Steps 3 and 4 put BatchNormalization and Dropout to work.

Shapes in and out

Every layer expects a particular input shape. The quickest check that two layers fit together is to print the shape each one hands on.

Run in Colab

images = np.random.rand(32, 28, 28).astype("float32")
flat = tf.keras.layers.Flatten()(images)
dense_out = tf.keras.layers.Dense(128)(flat)
print(images.shape, flat.shape, dense_out.shape)
(32, 28, 28) (32, 784) (32, 128)

np.random.rand(32, 28, 28) makes a batch of 32 random grey images, values between 0 and 1, standing in for MNIST; astype("float32") gives the 32-bit floats a network reads. Calling a layer on a real array computes numbers at once, unlike a call on an Input.

Flatten keeps the first axis, the batch of 32, and joins the rest into one row of 28 × 28 = 784.7 Dense(128) reads that row and hands on 128 values per image. When a layer gets a shape it cannot read, Keras raises an error naming that layer and the shape it was given. Read it as "the layer before this one handed on the wrong shape", which usually means a missing reshape.

Image layers: Conv2D and MaxPooling2D

Week 6's page on kernels and pooling slid a small grid of weights, a kernel, across an image by hand. Conv2D is that operation as a layer that learns its kernels during training. One set of small kernels slides across the whole image, so the layer's parameter count does not depend on the image size.8 (Keras also calls a Dense layer's weight table its kernel; in this step the word means the sliding grid.)

Conv2D reads a batch shaped (batch, height, width, channels).8 The grey images above have no channel axis, so images[..., np.newaxis] adds one: the ... keeps every existing axis and np.newaxis puts an axis of length 1 after them.8

Run in Colab

images_4d = images[..., np.newaxis]
conv = tf.keras.layers.Conv2D(16, 3)
maps = conv(images_4d)
pooled = tf.keras.layers.MaxPooling2D()(maps)
print(images_4d.shape, maps.shape, pooled.shape)
print(conv.count_params())
(32, 28, 28, 1) (32, 26, 26, 16) (32, 13, 13, 16)
160

Conv2D(16, 3) means 16 kernels, each 3 by 3. With the default padding="valid" a kernel sits only where it fits inside the image, so it has 28 − 3 + 1 = 26 positions along each side and each kernel makes one 26 by 26 map.8 The 160 parameters are 3 × 3 × 1 × 16 = 144 weights plus one bias per kernel.

MaxPooling2D() is the layer version of that page's pooling. It uses a 2 by 2 window by default and keeps the largest value in each window, so 26 by 26 becomes 13 by 13. It has no parameters.9 Pooling shrinks the maps the next layer has to read while keeping the strongest response in each patch.

A Dense layer on a flattened image ignores which pixels are neighbours. Conv2D keeps that structure with far fewer parameters: step 4's CNN holds 12,810 against the Dense digit network's 101,770.8 In other people's code a CNN shows up as Conv2D(16, 3, activation="relu"), then MaxPooling2D(), repeated, then Flatten() before the last Dense.

The text counterpart is Embedding(input_dim, output_dim), which maps whole-number token ids to vectors: a batch shaped (batch, length) becomes (batch, length, output_dim).10 What those vectors mean is a week 8 topic.

Takeaways
  • Pick a layer by the shape it reads and the shape it hands on.
  • Flatten keeps the batch axis and turns each image into one long row.
  • Conv2D needs a channel axis; a 3 by 3 kernel shrinks 28 to 26.
  • Max pooling halves height and width and has no parameters.
Say it in an interview

Flatten turns each example's axes into one long row and keeps the batch axis, so a 28 by 28 image becomes 784 values a Dense layer can read. A Conv2D with 16 filters of 3 by 3 on a 28 by 28 by 1 image outputs 26 by 26 by 16, because with no padding the filter only fits 26 positions each way.

To check two layers fit together I print the shape each one hands on, or read model.summary. A shape error names the layer that got the wrong shape, and the fix is usually a reshape in front of it.

Batch normalization

Batch normalization, measured like any change

The idea: a scaler inside the network

Week 6 scaled input columns with StandardScaler: subtract each column's mean, divide by its standard deviation (its spread), and every column sits around 0 with a spread of 1. A BatchNormalization layer does the same rescaling inside the network, to the values a layer receives, and recomputes it on every training batch. It then multiplies by a learned scale and adds a learned offset, so training can undo the rescaling where that helps.11

The layer behaves differently in training and in prediction. While training it uses the current batch's mean and variance (the spread squared). When predicting there may be a single row, with no useful spread of its own. So the layer uses the moving averages it kept during training: running averages, nudged towards each batch's mean and variance as training goes.11 The training argument below picks the mode by hand; fit runs training mode, predict and evaluate run prediction mode.

Run in Colab

bn = tf.keras.layers.BatchNormalization()
batch = np.array([[2.0], [4.0], [6.0]], dtype="float32")
print(bn(batch, training=False).numpy().round(2).ravel())
print(bn(batch, training=True).numpy().round(2).ravel())
[2. 4. 6.]
[-1.22  0.    1.22]

The batch is one column holding 2, 4 and 6. In prediction mode this fresh layer has learned no averages from training yet, so the values pass through almost unchanged. In training mode it uses the batch's own numbers: the mean is 4, the variance is (4 + 0 + 4) / 3 ≈ 2.67, and the spread is about 1.63. So 2 becomes (2 − 4) / 1.63 ≈ −1.22, which is the first value printed.

A BatchNormalization layer after a 128-unit Dense layer holds four numbers per input, 512 in all. 256 are trainable (the scale and the offset) and 256 are not trained by the optimizer (the moving mean and moving variance); summary() shows both counts.11 In other people's code you spot it as BatchNormalization() placed between a Dense layer and the next layer.

A worked improvement attempt

Batch normalization was introduced to reduce "internal covariate shift", the drift in a layer's inputs as the layers before it change, and so to speed up training. Later work disputes that explanation.12 Treat it as a project treats any change: train with and without it on the same validation rows and compare.

Run in Colab

(x_train, y_train), (x_test, y_test) = tf.keras.datasets.mnist.load_data()
x_train = x_train.reshape(-1, 784).astype("float32") / 255.0
x_test = x_test.reshape(-1, 784).astype("float32") / 255.0
x_tr, y_tr = x_train[:54000], y_train[:54000]
x_val, y_val = x_train[54000:], y_train[54000:]
print(x_tr.shape, x_val.shape, x_test.shape)
(54000, 784) (6000, 784) (10000, 784)

This is the week's MNIST split. Each 28 by 28 image becomes a row of 784 pixels scaled to 0 to 1, the first 54,000 training images train, the last 6,000 are the validation rows, and x_test stays aside.

Run in Colab

import pandas as pd
tf.keras.utils.set_random_seed(42)

def make_digit_model(batch_norm, name):
    layers = [tf.keras.Input(shape=(784,)), tf.keras.layers.Dense(128, activation="relu")]
    if batch_norm:
        layers.append(tf.keras.layers.BatchNormalization())
    layers.append(tf.keras.layers.Dense(10, activation="softmax"))
    model = tf.keras.Sequential(layers, name=name)
    model.compile(optimizer="adam", loss="sparse_categorical_crossentropy", metrics=["accuracy"])
    return model

plain_model = make_digit_model(False, "plain_model")
bn_model = make_digit_model(True, "bn_model")
print(plain_model.count_params(), bn_model.count_params())
101770 102282

The two networks differ only by the batch-norm layer, and 101,770 + 512 = 102,282. Everything else, from the 784-128-10 shape to the loss for whole-number labels, is the digit network of earlier in the week.

Run in Colab

results = []
for model in (plain_model, bn_model):
    model.fit(x_tr, y_tr, epochs=5, batch_size=128, validation_data=(x_val, y_val), verbose=0)
    val_loss, val_acc = model.evaluate(x_val, y_val, verbose=0)
    results.append({"model": model.name, "val_loss": val_loss, "val_accuracy": val_acc})
print(pd.DataFrame(results).round(4))
         model  val_loss  val_accuracy
0  plain_model    0.0897        0.9733
1     bn_model    0.0816        0.9748

That is one run's table; your numbers will move a little. Here bn_model came out a little ahead, with validation loss about 0.082 against about 0.090. Both models saw the same validation rows, which is what makes the rows comparable.2 On a network this shallow any gain is small and not guaranteed.12

Read the gap before you call a winner. One validation image is 1 / 6,000 ≈ 0.017 percent of the accuracy, so a difference of a few hundredths of a percent is a handful of images and counts as noise. Here 0.9748 − 0.9733 = 0.0015, which is 9 images out of 6,000, so the loss gap is the clearer sign. Write one sentence: batch normalization helped if its validation loss is clearly lower, and otherwise the simpler model stays.

Takeaways
  • Batch normalization rescales a layer's inputs per batch, then applies a learned scale and offset.
  • Training uses the batch's mean and variance; prediction uses the moving averages.
  • Judge it like any change: same validation rows, and a tiny gap is noise.
Say it in an interview

A batch normalization layer rescales the values coming into it to about mean zero and spread one, using each training batch's own mean and variance, and then applies a learned scale and offset. At prediction time there may be a single row, so it uses the moving averages it kept during training instead.

To tell whether it helped, I train the same network with and without it on the same validation data and compare validation loss and accuracy. A difference of a few images is noise, so I keep the simpler model unless the gain is clear.

Build: image

Build: a CNN digit classifier, in a project's order

This step builds a CNN (a convolutional neural network, one built from Conv2D layers) end to end, in the order a project notebook follows.

Problem, data and the reshape

The problem: read a 28 by 28 grey image of a handwritten digit and say which of 0 to 9 it is, the job a form scanner or a mail sorter does. The data is MNIST, split 54,000 for training, 6,000 for validation and 10,000 for the test. The test set is held out now and used once, at the end; every choice before then is made on the validation data.

Run in Colab

x_tr_img = x_tr.reshape(-1, 28, 28, 1)
x_val_img = x_val.reshape(-1, 28, 28, 1)
x_test_img = x_test.reshape(-1, 28, 28, 1)
print(x_tr_img.shape, x_val_img.shape, x_test_img.shape)
(54000, 28, 28, 1) (6000, 28, 28, 1) (10000, 28, 28, 1)

The -1 tells numpy to work that axis out from the others, so each 784-long row folds back into a 28 by 28 image with one channel. Conv2D raises a shape error on rows without that axis.8

The model and a reason for each choice

Run in Colab

def make_cnn(dropout=0.0, name="cnn"):
    tf.keras.utils.set_random_seed(42)
    layers = [tf.keras.Input(shape=(28, 28, 1)),
              tf.keras.layers.Conv2D(16, 3, activation="relu"),
              tf.keras.layers.MaxPooling2D(),
              tf.keras.layers.Conv2D(32, 3, activation="relu"),
              tf.keras.layers.MaxPooling2D(),
              tf.keras.layers.Flatten()]
    if dropout:
        layers.append(tf.keras.layers.Dropout(dropout))
    layers.append(tf.keras.layers.Dense(10, activation="softmax"))
    model = tf.keras.Sequential(layers, name=name)
    model.compile(optimizer="adam", loss="sparse_categorical_crossentropy", metrics=["accuracy"])
    return model

cnn_base = make_cnn(name="cnn_base")
print(cnn_base.count_params())
12810

The first pair gives step 2's 13 by 13 by 16; the second gives 11 by 11 by 32, then 5 by 5 by 32 (half of 11, rounded down), and Flatten makes 800 values. The parameters are 160 + 4,640 (3 × 3 × 16 × 32 + 32) + 8,010 (800 × 10 + 10) = 12,810.8

ChoiceReason
Two Conv2D layersThey read neighbouring pixels together, so a stroke is found wherever it sits
MaxPooling2D after eachIt shrinks the maps the next layer reads
FlattenIt hands the last maps to Dense as one row
Dense(10, activation="softmax")One probability per digit, adding up to 1
sparse_categorical_crossentropy, AdamThe loss for whole-number labels; Adam is the week's default

Training with early stopping

Early stopping ends training when the monitored value, here the validation loss, has not improved for patience epochs. With restore_best_weights=True it then puts back the weights from the best epoch.13 It is passed to fit as a callback, in callbacks=[...].

Run in Colab

import matplotlib.pyplot as plt

early_stop = tf.keras.callbacks.EarlyStopping(monitor="val_loss", patience=2, restore_best_weights=True)
history_base = cnn_base.fit(x_tr_img, y_tr, epochs=20, batch_size=128,
                            validation_data=(x_val_img, y_val), callbacks=[early_stop], verbose=0)
print(len(history_base.epoch), "epochs ran")
epochs = range(1, len(history_base.epoch) + 1)
plt.plot(epochs, history_base.history["loss"], label="training loss")
plt.plot(epochs, history_base.history["val_loss"], label="validation loss")
plt.xlabel("epoch")
plt.legend()
plt.show()
14 epochs ran

history.epoch has one entry per epoch that ran,13 and range(1, ...) numbers the epochs from 1 on the chart. epochs=20 is only the ceiling, and batch_size=128 updates the weights after every 128 images.

On this run validation loss was lowest at epoch 12, about 0.041, and epochs 13 and 14 did not beat it. So patience=2 stopped training after 14 of the 20 epochs, and epoch 12's weights came back.13 Meanwhile training loss kept falling: the overfitting pattern from Monday's page, which early stopping cuts off.14

One improvement attempt: dropout

Dropout(rate) sets a random share rate of its inputs to 0 at each training step and scales the rest up to make up for them. It does nothing when predicting or evaluating.16 With 0.3 after Flatten, about 240 of the 800 values are switched off on each step, so the network cannot lean on any one of them. Dropout is a regularisation technique, a change made to reduce overfitting.14

Run in Colab

cnn_model = make_cnn(dropout=0.3, name="cnn_model")
early_stop = tf.keras.callbacks.EarlyStopping(monitor="val_loss", patience=2, restore_best_weights=True)   # a new one for this fit
history_dropout = cnn_model.fit(x_tr_img, y_tr, epochs=20, batch_size=128,
                                validation_data=(x_val_img, y_val), callbacks=[early_stop], verbose=0)
print(len(history_dropout.epoch), "epochs ran")
epochs = range(1, len(history_dropout.epoch) + 1)
plt.plot(epochs, history_dropout.history["loss"], label="training loss")
plt.plot(epochs, history_dropout.history["val_loss"], label="validation loss")
plt.xlabel("epoch")
plt.legend()
plt.show()

Here early stopping fired again: validation loss was lowest at epoch 10, and training stopped after epoch 12.

best_cnn is the model with the lower validation loss. Dropout lowers training accuracy on purpose, so judge it on validation: a lower validation loss and a narrower gap between the curves mean it helped.14 On this run it did: about 0.033 against 0.041, and 56 wrong images against 67.

At each model's best epoch, cnn_base's validation loss sat about 0.013 above its training loss and cnn_model's about 0.012 below it. The gap turns negative because dropout is on while training loss is measured and off for validation.16

The test set, once, and limitations

Run in Colab

Takeaways
  • Early stopping halts when validation loss stops improving and restores the best epoch.
  • Dropout switches off a random share of values while training and nothing when predicting.
  • Judge a change on validation loss and the gap between the curves.
Say it in an interview

I built a small CNN that classifies handwritten digits. I held the test set out first and kept 6,000 training images for validation. The model is two convolution and pooling blocks and a softmax output, trained with early stopping on validation loss.

I read the confusion matrix and the digits it got wrong, tried dropout as one change, kept the model with the lower validation loss, and scored the test set once at the end.

Saving and loading

Saving and loading a model

A trained model lives in the notebook's memory until it is written to a file. Saving it means the minutes of training never have to run again, and a project hands its model in as exactly such a file.

Save, load, same predictions

model.save("name.keras") writes one file holding the architecture, the weights and the optimizer state, and tf.keras.models.load_model rebuilds the model from it. The .keras ending is what selects the Keras 3 format.17

Run in Colab

best_cnn.save("digits_cnn.keras")
loaded = tf.keras.models.load_model("digits_cnn.keras")
before = best_cnn.predict(x_val_img[:100], verbose=0)
after = loaded.predict(x_val_img[:100], verbose=0)
print(np.allclose(before, after))
True

np.allclose compares the two arrays number by number and returns True when they all match. Here that is 100 images × 10 probabilities, 1,000 numbers, all the same: the loaded model is the trained model, and np.allclose on the same inputs is the check.17

The file also keeps the compile settings, so loaded.evaluate(x_val_img, y_val) runs without calling compile again.17 That is what makes a restart cheap. After Runtime > Restart session, which wipes every variable, rerun only the imports, the MNIST cell and the reshape, then load the file and evaluate it. No training runs.

Where the file lives in Colab

A Colab runtime is a temporary virtual machine that runs the notebook's code, and files written there live on its disk. They are deleted when the runtime is recycled, so download the file from the Files panel or copy it to Drive to keep it.18 A saved model that is missing the next morning usually went with the runtime.

The file name matters as well. A name ending .h5, or a bare folder name, selects a different format. Three related ways to write a model to disk:

  • .h5 is the legacy format, which Keras still reads and writes with a warning.17
  • model.export(path) writes a TensorFlow SavedModel for serving, which is not reloaded as a Keras model; serving models is week 11.17
  • tf.keras.callbacks.ModelCheckpoint saves the model, or only its weights, during fit, optionally only the best epoch, which protects a long fit.19

Build: classifying penguins from a table

Preprocessing from the training rows only

Fitting a scaler or a fill value on data that includes the validation or test rows is data leakage: those rows shape training, so the evaluation no longer measures unseen data.24 Three steps prepare the table, each learned from the training rows:

  • Fill the blanks: the training median for a measurement, the training rows' most common value for a category.
  • One-hot encode: pd.get_dummies turns a category column into one 0-or-1 column per category.25
  • Scale: StandardScaler.fit learns each column's mean and spread from the training rows, and transform applies them to all three tables.26

One-hot encoding has a trap. A table that lacks a category gets fewer columns, so the validation table can come out a different shape from the training table:

  • Split first, then learn every fill, encoding and scale from the training rows.

I classified three penguin species from a 344-row table. I split off a stratified test set first, then validation. I filled blanks with training medians and most common values, one-hot encoded island and sex, and scaled with a scaler fitted on the training rows.

Regression variant

Variant: predicting a number

A regression predicts a number instead of a class. The same penguin table and the same three splits can predict each bird's body mass, and only a few parts of the build change.

A regression network ends in Dense(1) with no activation, a linear output, so it can produce any number, not one squeezed between 0 and 1. It is compiled with loss="mse" and often metrics=["mae"], and its predictions are compared with the actual values.29 Both scores fit in a few lines of numpy:

Run in Colab

actual = np.array([3.5, 4.0, 5.0])
predicted = np.array([3.7, 3.9, 4.6])
errors = predicted - actual
mae = np.mean(np.abs(errors))
mse = np.mean(errors ** 2)
print(f"MAE {mae:.4f} kg ({mae * 1000:.0f} g), MSE {mse:.4f}")
MAE 0.2333 kg (233 g), MSE 0.0700

The errors are 0.2, −0.1 and −0.4 kg. MAE averages their sizes, (0.2 + 0.1 + 0.4) / 3 ≈ 0.233 kg, so the predictions are off by about 233 g on average, in the target's own unit. Monday's page computed MSE as the average squared miss; here it is 0.07, from (0.04 + 0.01 + 0.16) / 3, in kilograms squared. The one 0.4 kg miss supplies 0.16 of that 0.21 total, so MSE weighs big misses most.

Rows with no body mass are dropped. A row with no target is dropped, never filled, because a filled target would teach the model an answer someone made up. The inputs are the other three measurements plus species, island and sex, prepared as in step 6.

Check yourself

Eight questions, at least one per section. Answer each out loud before you open it.

When would you use the Functional API instead of Sequential, and what does Dense(128)(inputs) return?

When the model is not a straight stack: it branches, merges, or has several inputs or outputs. The call returns a new Keras tensor, a placeholder with a shape of (None, 128) that records the layer; no numbers are computed until real data goes through the finished Model.

The skip model has 109,610 parameters and the plain digit network 101,770. Where does the difference come from?

Concatenate hands the output layer 784 + 128 = 912 values per row instead of 128. The output layer then holds 912 × 10 + 10 = 9,130 numbers instead of 1,290, and 9,130 − 1,290 = 7,840 is the difference.

What does Conv2D(16, 3) output for a batch of 32 grey 28 by 28 images, and what must happen to the images first?

The images need a channel axis, (32, 28, 28) to (32, 28, 28, 1), with images[..., np.newaxis] or a reshape. The output is (32, 26, 26, 16): 16 maps, each 26 by 26 because a 3 by 3 kernel with no padding fits 26 positions per side.

Why does a batch normalization layer behave differently in training and in prediction, and how would you tell whether it helped?

In training it rescales with the current batch's mean and variance; in prediction there may be one row, so it uses the moving averages kept during training. Train the same network with and without it on the same validation rows and compare validation loss and accuracy; a gap of a few images is noise.

A CNN's training loss keeps falling while its validation loss rises after epoch 12. What is happening, and which two tools from the CNN build address it?

The network is overfitting: it is learning the training images rather than digits in general. Early stopping with restore_best_weights=True keeps epoch 12's weights, and dropout switches off a random share of values while training so the network cannot lean on any one of them.

What does a .keras file hold, and why might a model saved in Colab be gone the next morning?

The architecture, the weights, the optimizer state and the compile settings, so load_model gives back a model that predicts the same and can evaluate at once. Colab writes files to a temporary machine's disk that is deleted when the runtime is recycled, so download the file or copy it to Drive.

A teammate fills the penguin blanks with whole-table medians and fits StandardScaler on all 344 rows, then splits. What is wrong, and what is the fix?

That is data leakage: the validation and test birds helped set the fill values, the mean and the spread, so the validation score no longer measures unseen data. Split first, learn every fill, encoding and scale from the training rows, and reindex validation and test to the training columns.

What three things change when the penguin classifier becomes a body-mass regression, and why report MAE?

The output becomes one Dense(1) unit with no activation, the loss becomes "mse", and the reported metric becomes MAE. MAE is in the target's own unit, so 0.233 kg reads as "about 233 g off per bird", while MSE is in kilograms squared.
