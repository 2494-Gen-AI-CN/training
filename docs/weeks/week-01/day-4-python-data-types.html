Python data types: the idioms, trade-offs and pitfalls behind each built-in type

Week 1 · Day 4 Thu Oct 15, 2026 Agile for developers, Git & Python fundamentals ~40 min · reference notes @150 wpm · diagram · check Sources checked 2026-10-14 · python 3.15

This page assumes only Wednesday's lesson: Python's indented blocks, variables as names bound to objects, the operators including is, PEP 8 names, and input() and print() with f-string formats, applied to a ticket-desk script whose ticket is still a handful of flat variables. Anything it borrows from a later day gets a one-line explanation where it appears. It works through Python's built-in types in the order a ticket record needs them: strings, casting and truthiness for typed text; lists, tuples, range and sets for a queue; bytes, None and dicts for the record; then numbers, datetime and the namespaces that hold every name. Each section gives a runnable example with its output, the trade-off, how the idiom looks in someone else's code, and a spoken answer for an interview. Afterwards you can explain aliasing, why .sort() returns None, why 0.1 + 0.2 is not 0.3, and what a second import datetime does to a file.

Text

Strings: immutable text and the methods that clean it

Text typed at a prompt arrives with stray spaces and capitals in it. Before a program compares a priority or stores a title, it cleans the text, and every tool for that is a string method or a slice. In the ticket-desk code that grows through this week, the typed title and priority are normalised once, straight after they are read, so every later line sees clean text.

A method is a function that belongs to a value and is called with a dot after it: title.strip() calls the strip method of the string in title. This page uses methods on every type it covers, and Friday's page shows how to write your own.

Immutable strings and the methods that return new ones

Unicode is the standard that gives every character a number, called a code point, and a Python str is a sequence of those code points. It is also immutable: once a string exists, nothing can change its characters. Methods such as strip(), lower() and replace() build and return a new string, and the original stays exactly as it was.1 That answers the most common opening question about strings: s.upper() on a line of its own changes nothing, because it makes an upper-case copy and nobody keeps it. To keep the result you bind it to a name, often the same one, as in title = title.strip().

title = "  Login page returns 500  "
clean = title.strip()
print(len(title), len(clean))
print(clean.replace("500", "error"))
print(clean)
print(clean.startswith(("Login", "Signup")), "page" in clean)
print("a  b".split(), "a  b".split(" "))

The first line prints 26 22: strip() removed the two spaces at each end and left the spaces between words alone. The second prints Login page returns error, and the third still prints Login page returns 500, because replace() returned a copy. That is also the difference between s.strip() and s.replace(" ", ""): the first trims the ends, the second deletes every space, including the ones that separate words.2 The fourth line prints True True. startswith() accepts a tuple of prefixes and is true if any of them matches,2 and in on two strings tests for a substring.3 The last line prints ['a', 'b'] ['a', '', 'b']. With no argument, split() splits on runs of whitespace and throws away empty strings; split(" ") splits on each single space and keeps the empty string between two adjacent ones.2

You recognise this idiom in other people's code as a chain on user input, such as name.strip().lower(). Chaining works because each method returns a string the next method can be called on.

Slicing and negative indexes

Slicing is how you truncate, take the end of, or reverse a string without calling a method, and it is the question an interviewer usually asks next. A slice s[start:stop:step] includes start and excludes stop, and a negative index counts from the end, so s[-1] is the last character.3 A slice never raises IndexError: asking for more than exists returns what there is, while a single index past the end does raise.4

clean = "Login page returns 500"
print(clean[:40])
print(clean[-3:], clean[-1])
print(clean[::-1][:3])
print("abc"[:40])

This prints Login page returns 500, then 500 0, then 005, then abc. The title is shorter than 40 characters, so clean[:40] is the whole title, which is exactly why the slice is safe for display code. A step of -1 walks the string backwards, so [::-1] is the standard one-expression reversal. The pattern that turns up in real code is text[:40] + "..." to truncate a long value for a table or a log line. Its limit is that it adds the dots even when nothing was cut, so careful code checks len(text) first.

Building a long string: join and f-strings

Because strings are immutable, s += part cannot extend s in place. It creates a new string holding all the old text plus the new part, so building a large string one piece at a time can copy the text over and over. The standard way is to collect the pieces in a list and call "".join(parts) once, with whatever separator you need in the quotes.1 Reviewers flag += on a string inside a loop for exactly this reason (loops arrive on Friday).

line = " ".join(["#101", "Login page returns 500", "[high]"])
hours_open = 4.5
print(line)
print(f"{line} {hours_open:.2f}h")

The output is #101 Login page returns 500 [high], then the same line followed by 4.50h. An f-string evaluates the expressions in its braces at runtime, and the part after the colon is a format spec, so :.2f shows two decimal places.5 For a handful of values an f-string is the readable choice; for many pieces gathered over time, join is.

Say it in an interview

Python strings are immutable. A method like upper or strip gives me back a new string and leaves the original alone, so if I don't assign the result, nothing changes.

strip only trims whitespace at the two ends, while replacing every space with nothing also removes the spaces between words. For a large string I collect the parts in a list and join them once, because repeated plus-equals can copy the whole text each time.

Conversion

Casting and truthiness

Casting turns a value of one type into another, and truthiness is the cast Python performs on its own whenever a value sits in a condition. Both cause bugs that survive a quick read: the code looks right and runs without an error.

Casting with int(), float() and str()

input() always returns a str, so a number typed at the prompt is text until you cast it.6 int() given a float truncates toward zero, so int(3.9) is 3 and int(-3.9) is -3; it never rounds, and round() is the call for rounding.7 Given text, int() needs an integer literal: int("3.5") raises ValueError, while int(float("3.5")) works, and an optional second argument sets the base, so int("ff", 16) is 255.7 float() accepts strings such as "nan" and "inf", so a cast that succeeds does not promise a finite number.8

typed = " 42 "
ticket_id = int(typed)
print(ticket_id + 1)
print(int(3.9), int(-3.9), round(3.9))
print(int(float("3.5")), int("ff", 16))
print(float("inf"), float("nan"))
print(str(ticket_id) + " is open", repr("42"))
int("3.5")

The output is 43, then 3 -3 4, 3 255, inf nan and 42 is open '42', and the last line stops the script with ValueError. The first line shows that int() tolerates the spaces around a number. str() gives the readable form of an object and repr() the unambiguous one,9 which is why repr("42") keeps the quotes: in a log line that is how you tell the text '42' from the number 42. You recognise casting in real code as age = int(input("Age: ")), or float(row["price"]) applied to text read from a file. The trade-off to name is truncation: if the requirement says "round to the nearest hour", int() is quietly wrong for every value with a fraction of .5 or more.

Checking text before you cast

The follow-up question is how to convert user input safely. A common first answer is to test the text with str.isdigit(), and it is not an exact match for what int() accepts. It rejects a sign and surrounding whitespace, both of which int() accepts, and it accepts characters such as the superscript "²", which int() rejects.10 str.isdecimal() is the closer match.11

print(" 42 ".isdigit(), "-7".isdecimal(), "42".isdecimal())
print("²".isdigit())
int("²")

The first line prints False False True, even though int(" 42 ") and int("-7") both succeed. The second prints True, and the third raises ValueError. The reliable test is to attempt the cast and catch ValueError with try and except:7 try runs a block, and an except ValueError block below it runs instead of stopping the program if that error is raised. A later lesson on error handling covers both properly.

Truthiness and the bool type

Every object has a truth value. None, False, zero of any numeric type and empty sequences and collections are false; an object is also false when it defines __bool__ returning False or __len__ returning 0; everything else is true.12 (__bool__ and __len__ are special methods a class can define to answer "am I true?" and "how long am I?"; classes arrive on Friday.) So bool("False") and bool("0") are both True: they are non-empty strings, and bool() does not read the words. As Wednesday's page noted, bool is a subclass of int, a specialised kind of integer, which makes True == 1 true and sum([True, False, True]) equal to 2.13

print(bool("False"), bool(""), bool(0), bool([]), bool(None))
print(True + True, sum([True, False, True]), isinstance(True, int))
print(2 == True, bool(2))

The lines print True False False False False, then 2 2 True, then False True. The last line is why if x == True is poor style: 2 is truthy, yet it is not equal to True, because True equals 1. PEP 8 advises against comparing boolean values to True or False with ==;14 write if x:. You recognise truthiness on sight as if not queue: guarding an empty list. Its limit is that it treats 0, 0.0 and "" the same as None,12 so a legitimate zero can look like a missing value.

and and or hand back an operand

Wednesday's operators lesson introduced this rule, and truthiness is what drives it. and and or return one of their operands rather than a bool, and they stop evaluating as soon as the result is known.15 a and b returns a if it is falsy and otherwise b; a or b returns a if it is truthy and otherwise b.

is_open = True
title = "Login page returns 500"
print(is_open and title)
print("" or "anonymous")
print(0 or None)

This prints Login page returns 500, then anonymous, then None. The first result surprises people who expect True: is_open was truthy, so and returned the second operand, the title itself. The second line is the defaulting idiom you will see as value = name or "anonymous", and the spot-the-bug above is its limit.

Say it in an interview

int of 4.7 truncates toward zero and gives 4. int of the string "42" parses it and gives 42. int of the string "4.7" raises a ValueError, because that text isn't an integer literal; I'd go through float first, or round if rounding is what's wanted.

The falsy values are None, False, zero of any numeric type, and empty strings and containers. Everything else is truthy, including the string "False". bool is a subclass of int, so True plus True is 2, and that's why comparing to True with double equals is poor style: 2 is truthy but isn't equal to True.

Sequences

Lists, tuples and range

The three ordered sequence types look alike on the page and behave differently once you change, copy or sort them. In the ticket-desk code, a queue of tickets becomes a list whose items are (rank, ticket_id, title) tuples, and the examples below use that shape.

Lists: in-place methods, sorted() and aliasing

A list is a mutable sequence. append, extend, insert, remove, pop, sort and reverse change the list in place, and the ones that change its order or size return None, except pop, which returns the item it removed.16 append(x) adds one item at the end, extend(items) adds each item of another sequence, and insert(i, x) puts one item at a position. A negative index counts from the end and a slice returns a new list.3

queue = []
queue.append((2, 103, "Wi-Fi drops"))
queue.append((1, 101, "Login page returns 500"))
queue.append((2, 102, "Printer jams"))
print(queue[-1])
print(queue[1:])
print(sorted(queue))
print(queue.sort())

queue[-1] prints (2, 102, 'Printer jams') and queue[1:] prints the last two tuples in a new list. sorted(queue) returns a new list starting with the rank 1 ticket, followed by ticket 102 and then 103: tuples compare element by element, so a list of tuples sorts by rank first and by id when ranks tie.17 The last line prints None. sort() did sort queue, in place, and returned nothing, which is why queue = queue.sort() is a bug that replaces your list with None. Both sorts are stable, so items that compare equal keep their original order.17 Sorting by something other than tuple order needs a key function, a small function that tells the sort which value to compare for each item; Friday's lambda supplies one.

Assignment never copies. backup = queue binds a second name to the same list object, so a change through either name shows through both; queue.copy() makes a new list.18

backup = queue
backup.append((9, 999, "oops"))
print(len(queue), backup is queue)
safe = queue.copy()
safe.append((8, 888, "late"))
print(len(queue), len(safe))

This prints 4 True, then 4 5. The trade-off of a list is at its front. pop(0) and insert(0, x) shift every other element, so they cost O(n), which makes a list a poor queue for large data. O(n), read "order n", is shorthand for work that grows in step with the number of items n: twice the list, roughly twice the time. O(1) means a fixed cost whatever the size, and collections.deque adds and removes at both ends in O(1).1920

Shallow and deep copies

The next question after aliasing is what copy() actually copies. It copies the outer list only, so any lists inside it are still shared. copy.deepcopy copies nested objects at every level, the lists inside the lists included.21 A related trap is [x] * n, which repeats references to the same object, so mutable elements end up shared.3

rows = [[0] * 3] * 3
rows[0][0] = 1
print(rows)
import copy
nested = [[1, 2], [3]]
shallow = nested.copy()
deep = copy.deepcopy(nested)
nested[0].append(99)
print(shallow[0], deep[0])

The first print shows [[1, 0, 0], [1, 0, 0], [1, 0, 0]]: one assignment changed all three rows, because they are one list. The second prints [1, 2, 99] [1, 2]. When you see rows = [[0] * 3] * 3 in a review, it is almost always three aliases of one row by accident.

Tuples: fixed records that sort and hash

A tuple is an immutable sequence, used for a fixed record whose positions mean something, where a list holds a varying number of similar things. The comma makes the tuple, not the parentheses: (1) is the integer 1, (1,) is a one-element tuple, and () is the empty tuple.22 Tuples compare lexicographically, the way a dictionary orders words: the first elements decide, and only a tie moves on to the second, so (1, 9) < (2, 0).17 They support count() and index() and have no method that changes them.23

print(type((1)), type((1,)))
print((1, 9) < (2, 0))
rank, tid, text = (1, 101, "Login page returns 500")
first, *rest = (1, 101, "Login page returns 500")
print(tid, first, rest)
pair = (1, [2])
pair[1].append(3)
print(pair)
hash(pair)

This prints <class 'int'> <class 'tuple'>, then True, then 101 1 [101, 'Login page returns 500']. Unpacking needs as many targets as items unless a starred target absorbs the rest.22 The tuple pair prints as (1, [2, 3]): a tuple is immutable only at its own level, so a list inside it can still change. That is also why the last line raises TypeError. hash() computes a hash, a number derived from the value, and an object is hashable when that number stays fixed for the object's whole life; sets and dicts use it to find things fast, as the next two sections show.24 A tuple is hashable, and so usable as a dict key, only if every element is hashable.24 In real code you recognise tuples by unpacking such as rank, tid, text = row, or a trailing comma such as SIZE = (640,).

range: integers computed on demand

range(start, stop, step) excludes stop, and a negative step counts down.25 A range is not a list. It is an immutable sequence that stores only start, stop and step and computes items on demand, so len(), indexing and in work without building the values, and a range of a billion numbers takes the same small memory as a range of three.26

r = range(1, 4)
print(r, list(r), len(r), r[-1], 3 in r)
print(list(range(10, 0, -1)))
print(list(range(0, 10, 3)))
range(0.5, 3)

The first line prints range(1, 4) [1, 2, 3] 3 3 True; list() is how you materialise the values. The next two print ten down to one, then [0, 3, 6, 9]. The limit is that a range holds integers only, so range(0.5, 3) raises TypeError,25 and a step of 0 raises ValueError.26 You will see it as list(range(1, 4)), or as range(len(items)) to get positions.

Say it in an interview

b equals a doesn't copy a list; it gives the same list a second name, so appending through b shows up in a. For an independent copy I call copy, and if the list holds other lists I use deepcopy, because copy is shallow.

a dot sort sorts the list in place and returns None. sorted of a returns a new sorted list and leaves a alone. Writing a equals a dot sort is a classic bug, because it throws the list away.

A list is mutable and holds a varying number of similar things. A tuple is immutable, is a fixed record, and can be a dict key as long as everything inside it is hashable.

Sets & bytes

Sets and binary types

Sets and bytes have little in common, except that people reach for a list or a string when a set or bytes fits better. A set answers "have I seen this before?" quickly, and bytes is the form text takes the moment it leaves your program for a file, a network connection or a web server's reply.

Sets: distinct, hashable, fast to search

A set is an unordered collection of distinct hashable objects, built for fast membership testing. It locates an element by its hash value, while x in some_list compares x against the items one by one.27 That is why in on a set is faster than on a list. add ignores an element that is already present; remove raises KeyError for a missing element and discard does not. Values that compare equal, such as 1 and 1.0, count as one element, and because {} already means an empty dict, an empty set is written set().28

reporters = {"dana", "lee", "dana"}
reporters.add("lee")
print(len(reporters), "dana" in reporters)
print(type({}), type(set()), {1, 1.0})
reporters.discard("zed")
reporters.remove("zed")

The first print shows 2 True: the literal listed "dana" twice and the set kept one, and adding "lee" again changed nothing. The second shows <class 'dict'> <class 'set'> {1}. discard on a missing name passes quietly, and the last line raises KeyError: 'zed'.

The trade-off: a set has no order and no indexing, and its elements must be hashable, so a list cannot be a member. list(set(items)) is the quick way to remove duplicates from a list, and it does not keep the original order.28 When you need a set inside a set or as a dict key, frozenset is the immutable, hashable variant.28 In other people's code, sets show up as seen = set() before a scan, or unique = set(names).

Set algebra in one expression

The follow-up is usually "which reporters are also watchers?", and sets answer it with an operator. a & b, a | b, a - b and a ^ b give the intersection, union, difference and symmetric difference, and each has a method with the same name spelled out.28

watchers = {"lee", "sam"}
print(sorted(reporters & watchers), sorted(reporters | watchers))
print(sorted(reporters - watchers), sorted(reporters ^ watchers))

This prints ['lee'] ['dana', 'lee', 'sam'], then ['dana'] ['dana', 'sam']. The sorted() calls are there because a set has no order of its own: sorted returns a list, so the output reads the same on every run.

bytes: what text becomes after encoding

A str holds Unicode code points; a bytes object holds raw bytes, each a number from 0 to 255. An encoding, also called a codec, is the rule that turns code points into bytes and back, and UTF-8 is the common one. str.encode() returns bytes, using UTF-8 unless you name another codec, and bytes.decode() reverses it.29 len counts code points for a str and bytes for a bytes, and indexing a bytes object returns an int from 0 to 255.30 UTF-8 uses one to four bytes per character, so "café" has 4 characters and 5 bytes, because é takes two. Python never mixes the two types implicitly, so b"a" + "b" raises TypeError.31

title = "Café menu crashes"
raw = title.encode("utf-8")
print(raw)
print(len("café"), len("café".encode()))
print(raw[0], raw.decode() == title)
print(b"caf\xc3\xa9".decode("latin-1"))
print(b"\xff".decode("utf-8", errors="replace"))
b"a" + "b"

The first print shows b'Caf\xc3\xa9 menu crashes', with the two bytes of é written as hex escapes: \xc3 is one byte written as a two-digit hexadecimal (base 16) number. Then come 4 5 and 67 True: the first byte is the integer code for C, and the round trip gives back the same string. The next line decodes UTF-8 bytes as latin-1 and prints cafÃ©. Decoding with the wrong codec either raises UnicodeDecodeError or, as here, silently produces the wrong characters, because latin-1 accepts every byte. errors="replace" puts the replacement character U+FFFD in place of a bad byte instead of raising,31 so the sixth line prints �. The last line raises TypeError.

The limit to keep in mind is that byte length is not character count. Code that cuts a byte string at a fixed position, say to fit a 255-byte field, can split a character in half, and decoding the result fails.31 You recognise bytes on sight as a b"..." literal, or as payload.decode("utf-8") on data that came from a file, a network connection or a web server's reply.

bytearray, the mutable variant

A bytes object is immutable, so the next question is what to use when the bytes must change. bytearray is the mutable counterpart, so its items can be reassigned in place.29

buf = bytearray(b"abc")
buf[0] = 65
print(buf)

This prints bytearray(b'Abc'). Assigning the integer 65 replaced the first byte with the code for A; the same assignment on a bytes object would raise TypeError.

Say it in an interview

To remove duplicates I turn the list into a set, which keeps one of each. I lose the original order, and every item has to be hashable. Membership on a set is fast because it finds the item by its hash instead of comparing against every element the way a list does.

A str is text, a sequence of code points; bytes is the encoded form, raw values from 0 to 255. len can differ because UTF-8 uses more than one byte for characters like é, so café is four characters but five bytes.

Mappings

None and dictionaries

A ticket has an assignee before anyone is assigned, and a record has fields that may or may not be there. None is how Python spells "no value yet", and a dict is how it spells a record with named fields. In the ticket-desk code the ticket becomes a dict, and three separate SLA constants become one lookup table.

None, the single missing value

None is the only value of the type NoneType, and it is a singleton: there is exactly one None object in a running program, so an identity test with is is reliable.32 PEP 8 says comparisons to singletons such as None should use is or is not, never the equality operators.14 Many calls hand back None because they do their work as a side effect, something they change or show, such as text on the screen or a reordered list, rather than a value they hand back: print() returns None,33 and so do the in-place list methods such as sort().16

assignee = None
print(assignee is None, type(assignee))
print(print("x"))
print({}.get("owner"))
None < 1

The first line prints True <class 'NoneType'>. The second prints x and then None: the inner print runs first and shows x, and the outer one prints what the inner one returned. The third prints None, because dict.get(key) returns None when the key is missing and no default is given.34 The last line raises TypeError, since None cannot be ordered against numbers.35

The trade-off is the one from truthiness. None is falsy, so if not value: cannot tell None from 0 or "";12 when "missing" must stay distinct from "empty", write if value is None. You recognise the idiom as a placeholder such as assignee = None at the top of a record, filled in later.

Dictionaries: keys, lookups and safe reads

A dict maps keys to values. d[key] raises KeyError when the key is missing; d.get(key, default) returns the default instead, without raising and without inserting the key. d.setdefault(key, default) is the variant that does insert the default when the key is absent, then returns the value. key in d tests keys, not values, and keys must be hashable, so a list cannot be one.36

SLA_HOURS = {"high": 4, "normal": 24, "low": 72}
priority = "high"
ticket = {"id": 101, "title": "Login page returns 500",
          "priority": priority, "assignee": None, "history": []}
print(SLA_HOURS[priority])
print(ticket.get("owner", "unassigned"), "owner" in ticket)
ticket["assignee"] = "lee"
ticket["history"].append("assigned to lee")
print("id" in ticket, "lee" in ticket)
print(ticket.setdefault("tags", []), "tags" in ticket)
tickets_by_id = {ticket["id"]: ticket}
print(tickets_by_id[101]["assignee"])
ticket["owner"]

The prints show 4, then unassigned False (the default came back and no owner key was added), then True False, because "lee" is a value and in only looks at keys. setdefault prints [] True: this time the key was added. tickets_by_id is a registry that finds a ticket from its id, and it prints lee. The last line raises KeyError: 'owner'. One subtlety follows from the None section: ticket.get("assignee") is None would also have been True before assignment, when the key existed with the value None, so a get that returns None does not prove the key is missing. in does.

Replacing three constants with SLA_HOURS turns a choice between names into a lookup, so a fourth priority is one more entry in the table. The trade-off is that a dict gives fast lookup by key at the cost of memory, and offers no lookup by value at all.36 In other people's code you will find config.get("timeout", 30), and registries written as by_id = {t["id"]: t for t in tickets}. That second form is a dict comprehension, a loop written inside the braces that builds one entry per ticket; you only need to recognise it for now, and Friday's loops make it readable.

Views, order and the hash table underneath

.keys(), .values() and .items() return views, live windows that reflect later changes to the dict, so list(d.items()) is how you take a snapshot that stays still.37 Dicts preserve insertion order, and that has been a guarantee of the language since Python 3.7.3638

items = ticket.items()
print(len(items))
ticket["status"] = "open"
print(len(items))
snapshot = list(ticket.items())
print(list(ticket))

Continuing with the same ticket, this prints 6, then 7: the view saw the new key without being asked again. The last line lists the keys in the order they were added, from 'id' to 'status'.

Underneath, a dict is a hash table: a block of numbered slots, where Python computes the key's hash and turns it into the slot to look in, so it never has to scan the other keys. That gives average constant-time lookup, insertion and deletion, meaning a lookup in a dict of ten million keys takes about as long as in a dict of ten.20 The same mechanism powers sets, which is why both need hashable members: if a key's hash could change after insertion, the table would look in the wrong slot.24

Say it in an interview

None is the single value of NoneType. I compare with is None because there's only one None object, so an identity check is exact, and PEP 8 asks for it.

Square brackets raise a KeyError when the key is missing. get returns None, or the default I pass, and doesn't add the key. Keys have to be hashable, so strings, numbers and tuples of those work and lists don't. And yes, dicts keep insertion order; it's been part of the language since 3.7.

Numbers & time

Numbers and datetime

Numbers and dates share a section because they meet in the same calculation: how long has a ticket been open, and is it past its deadline? The ticket-desk code replaces a hard-coded hours figure with one computed from two datetimes, and the float pitfalls show up in that same computation.

int, float and the two divisions

Wednesday's page showed the symptom; this section gives the cause and the fixes. A float is a binary floating-point number: it stores a value as a fraction in base 2, and just as 1/3 has no exact decimal form, 0.1 has no exact binary one. The tiny error in 0.1 and in 0.2 does not cancel out when they are added, so 0.1 + 0.2 == 0.3 is False.39 An int, by contrast, has arbitrary precision, so integer overflow does not happen in Python; an int grows as large as memory allows.40 / is true division and always returns a float, while // is floor division and rounds down, so -7 // 2 is -4 rather than -3.41 divmod(a, b) returns the quotient and the remainder as a tuple.42

print(0.1 + 0.2 == 0.3, 0.1 + 0.2)
print(round(0.1 + 0.2, 2) == 0.3, abs((0.1 + 0.2) - 0.3) < 1e-9)
print(10 / 4, 10 // 4, 10 / 5, -7 // 2)
print(divmod(28, 24), round(2.5), round(3.5))
print(2 ** 100, 1_000_000)

The first line prints False 0.30000000000000004, which shows the error directly. The second prints True True: the two safe comparisons are rounding both sides to the precision you care about, or checking that the difference is smaller than a tolerance. The third prints 2.5 2 2.0 -4; note that 10 / 5 is the float 2.0 even though the division is exact. The fourth prints (1, 4) 2 4: 28 hours is one day and four hours, and round() rounds half to even, so 2.5 goes down to 2 and 3.5 up to 4.43 The last line prints a 31-digit integer and 1000000; Python ignores the underscores in a numeric literal, and they exist only for the reader.44

You recognise careful float code on sight by abs(a - b) < 1e-9 where a naive version would have ==. Week 2's math module adds a named helper for the same comparison.

Exact decimal arithmetic with decimal

When an interviewer asks how you would handle money, the expected answer is the decimal module. Decimal works in base ten, so the sum that failed above succeeds.45 The import line uses the from form: from decimal import Decimal loads the decimal module and binds just the name Decimal, so the code can write Decimal(...) without the module name in front.50 The last section of this page returns to what that binding means.

from decimal import Decimal
print(Decimal("0.1") + Decimal("0.2") == Decimal("0.3"))

This prints True. Each value is built from a string, so it holds exactly the digits written. The trade-off: floats are fast and compact but approximate, and Decimal is exact for decimal fractions but slower.39 Hours on a support ticket can live with a float compared through a tolerance. A bank balance cannot.

datetime and timedelta arithmetic

Subtracting one datetime from another gives a timedelta, a duration, and adding a timedelta to a datetime gives a new datetime.46 total_seconds() converts a duration to a float. The similar-looking .seconds attribute is only the seconds part left over after whole days, so it is wrong for anything a day or longer.47

from datetime import datetime, timedelta
opened_at = datetime(2026, 10, 15, 9, 30)
NOW = datetime(2026, 10, 15, 14, 0)
age = NOW - opened_at
hours_open = age.total_seconds() / 3600
deadline = opened_at + timedelta(hours=4)
print(age, hours_open)
print(NOW > deadline)
long = timedelta(days=1, hours=2)
print(long.seconds, long.total_seconds())

This prints 4:30:00 4.5, then True, because a four-hour deadline from 9:30 passed at 13:30. The last line prints 7200 93600.0: .seconds reports only the two hours and drops the whole day, while total_seconds() counts all 26 hours.

NOW is a fixed value on purpose. datetime.now() reads the system clock on every call, so code that calls it directly gives a different answer on every run,48 and a test that checks "is this ticket breached?" would pass in the morning and fail in the evening. Pinning the current time in one name keeps the output repeatable. The bigger limit is time zones. These values are naive: they carry no time zone, so subtracting values recorded in different zones silently gives a wrong answer, and comparing a naive datetime with an aware one using < raises TypeError.46 Zones arrive in week 2. In real code you recognise the idiom as datetime.now() - created_at, or deadline = start + timedelta(hours=24).

Formatting and parsing: isoformat, strftime and strptime

Once the arithmetic works, the next question is how to turn a datetime into text and back. isoformat() returns an ISO 8601 string such as 2026-10-15T09:30:00,48 the form to use in logs, files and APIs. strftime formats with codes such as %a for the abbreviated weekday and %H:%M for 24-hour time, and strptime parses text using the same codes.49

print(deadline.isoformat())
print(deadline.strftime("%a %H:%M"))
parsed = datetime.strptime("2026-10-15 09:30", "%Y-%m-%d %H:%M")
print(parsed == opened_at)

This prints 2026-10-15T13:30:00, then Thu 13:30, then True: the parsed text names the same moment as opened_at.

Say it in an interview

Binary floating point can't store 0.1 or 0.2 exactly, so their sum comes out a tiny bit off and the equality fails. I compare floats with a tolerance, or round both sides, and for money I use Decimal.

Single slash is true division and always gives a float; double slash is floor division and rounds down, so minus seven floor two is minus four.

Subtracting two datetimes gives a timedelta. I use total_seconds for the full duration, because the seconds attribute drops the whole days.

Names

Namespaces: which object a name means

Every section so far has bound values to names: title, queue, ticket, NOW. This last one is about the names themselves: where they live, how to list them, how to remove one, and how one ordinary line can make a name point at something else.

Namespaces, dir() and del

A module is one Python file loaded as a unit, either the file you run or one brought in with import. A namespace is a mapping from names to objects. Python keeps several: the built-in names such as len and list, the global names of each module, and the local names of each function call.50 When a line uses a name, Python looks it up in these namespaces to find the object. dir() with no arguments lists the names in the current scope,51 which at the top level of a file means the module's global names (Friday's page looks at scope inside functions). del name removes a binding. It does not necessarily destroy the object, which is freed only when no names refer to it any more.52

queue = [(1, 101, "Login page returns 500")]
backup = queue
print("backup" in dir())
del backup
print("backup" in dir(), len(queue))

This prints True, then False 1. The name backup is gone from the module's namespace, and the list it pointed at is untouched, because queue still refers to it. This links back to aliasing: a name is a label on an object, and del peels off one label. You recognise del in real code as tidying a name that should not be used again, such as del backup after the copy it held has served its purpose.

__name__ and the main guard

Every module has a global name __name__, read aloud as "dunder name" for its double underscores. It is "__main__" when the file is run directly, and the module's own name when the file is imported.53 That difference is what the line at the bottom of so many scripts tests.

print(__name__)
if __name__ == "__main__":
    print("running as a script")

Saved as ticket_desk.py and run with python ticket_desk.py, this prints __main__ and then running as a script. If another file runs import ticket_desk instead, the first line prints ticket_desk and the guarded line is skipped.53 That is the point of the guard: code beneath it runs when the file is the program and stays quiet when the file is used as a library. The trade-off is that anything a script does outside the guard also happens on import, so a module that prints or prompts at top level does so for every file that imports it.

Shadowing: the later binding wins

A later binding replaces an earlier one with no warning, so a name can shadow a built-in such as list or id and break code further down.50 The import statements are bindings too. from datetime import datetime binds the name datetime to the class; a later import datetime binds the same name to the module, so the class is no longer reachable by that name.50

from datetime import datetime
print(datetime(2026, 10, 15))
import datetime
datetime(2026, 10, 15)

The first print shows 2026-10-15 00:00:00. The last line fails with TypeError: 'module' object is not callable, because datetime now names the module, and a module cannot be called. The usual way in is a file that grows over time: someone adds import datetime near the top for an unrelated reason, and code twenty lines down that worked yesterday breaks. The fix is one import style per module.

The interviewer's next question is often how to get a built-in back. Assigning list = [1] at module level hides the built-in list until the module-level name is deleted,50 and the builtins module still reaches the original in the meantime.54

list = [1]
import builtins
print(builtins.list("ab"))
del list
print(list("ab"))

Both prints show ['a', 'b']. Between the first two lines, calling list("ab") would have raised TypeError, because list named a list object. After del list, the lookup falls through to the built-in namespace again.

Say it in an interview

A namespace is a mapping from names to objects. There's one for the built-ins, one per module for its globals, and one per function call for its locals, and Python looks a name up in them to find the object.

If a file does from datetime import datetime and later import datetime, the second import rebinds the name to the module, so calling datetime fails with "module object is not callable".

The main guard checks dunder name. It's set to main, with the double underscores, when I run the file directly, and to the module's name when it's imported, so the code under the guard only runs when the file is the program.

Check yourself

Nine retrieval questions, at least one per section. Answer each out loud before you open it.

A line reads title.upper() on its own and the title is still lower-case afterwards. Why, and how do you cut a title to 40 characters for display without risking an error?

Strings are immutable, so upper() returned a new string that nobody kept; write title = title.upper(). title[:40] is safe because a slice never raises IndexError; a shorter title comes back whole.

What do int(4.7), int(" 42 ") and int("4.7") give?

4, because int() truncates toward zero; 42, because surrounding whitespace is accepted; and a ValueError, because "4.7" is not an integer literal. int(float("4.7")) or round() handle the third case.

Why is bool("False") true, and why is if x == True: poor style?

Any non-empty string is truthy; bool() does not read the words. True equals 1, so a truthy value such as 2 fails == True; PEP 8 says to test the value directly with if x:.

After queue = queue.sort(), what is in queue? And after backup = queue and backup.append(t), how long is queue?

None, because sort() sorts in place and returns None; use sorted(queue) for a new list. queue is one item longer, because both names refer to the same list; queue.copy() makes a separate (shallow) one.

What is the type of (1), and what values does range(1, 4) contain?

(1) is just the integer 1, because the comma makes a tuple: (1,). range(1, 4) contains 1, 2 and 3, since the stop value is excluded, and it computes them on demand rather than storing a list.

How do you write an empty set, and why is len("café") different from len("café".encode())?

set(), because {} is an empty dict. The string has 4 code points; UTF-8 needs two bytes for é, so the bytes object has 5.

What is the difference between ticket["owner"] and ticket.get("owner", "unassigned"), and how do you test whether assignee has been set?

The first raises KeyError when the key is missing; the second returns the default without raising or adding the key. Test with assignee is None, since None is a singleton and if not assignee would also treat an empty string as unset.

Why is 0.1 + 0.2 == 0.3 false, and why is timedelta(days=1, hours=2).seconds 7200?

Binary floating point cannot represent 0.1 exactly, so compare with abs(a - b) < 1e-9 or round both sides. .seconds is only the part after whole days; total_seconds() gives the full 93600.0.

A file has from datetime import datetime at the top and someone adds import datetime below it. What breaks, and how can you see the names a module currently has?

The second import rebinds datetime to the module, so datetime(2026, 10, 15) raises TypeError: 'module' object is not callable. dir() with no arguments lists the names in the current scope.
