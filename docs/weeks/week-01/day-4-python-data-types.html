Python data types: the idioms a team expects and the pitfalls a review catches

Week 1 · Day 4 Thu Oct 15, 2026 Agile for developers, Git & Python fundamentals ~11 min · notes @150 wpm + diagram + check

This page assumes Wednesday's work: the PEP 8 conventions, the ticket desk file with its flat variables and three SLA constants, and the intake lines that read a title and a priority at the prompt. You know every type on today's list from coursework, so the page covers the idioms a reviewer expects and the mistakes that get past a first read. The four demos grow the same file, the trainer types each one live, and this page is the reference for what you watched.

Text

Strings: every method hands back a new string

Strings are immutable. .strip(), .lower() and .replace() each return a new string and leave the original alone, so a line that calls title.upper() and does nothing with the result changes nothing. Assign the result back to the name when you want to keep it.

Typed text arrives with stray spaces and capitals, and Wednesday's intake used it as typed. The ticket-text demo normalises both fields once, directly after the input guard, so every later line sees clean text:

title = title.strip()
priority = priority.strip().lower()

The chain reads left to right, so a priority typed with capitals and spaces around it becomes "high".

title[:40] runs from the start up to index 40 without including it, and a stop past the end is fine, so a short title comes back whole. Negative indexes count from the end, which makes title[-3:] the last three characters. len counts the characters, .startswith() answers with a bool, and in tests for a substring anywhere in the text.

Pitfall

Casting typed text, and what bool really tests

input() always returns text. The ticket-text demo keeps the typed text in one variable and casts it on the next line, inside the same guard Wednesday wrote:

ticket_id_text = input("Ticket id: ")
ticket_id = int(ticket_id_text)

With the cast on its own line, a typed abc gives a traceback that points straight at it, and the program stops with a ValueError.

On text, int accepts only whole-number text, so int("3.5") raises that same error even though float("3.5") works. On a float it truncates toward zero, so int(3.9) is 3. Use round when you mean rounding. str(ticket_id) goes the other way, which you need before joining a number to a string with +.

bool(x) follows truthiness. Empty sequences, zero, None and False are false, and nearly everything else is true. That includes every non-empty string, whatever it says.

A related mistake is comparing with == True. A non-empty title is truthy, yet that comparison gives False for it, because == compares values and a string never equals True. Test the value itself. The demo keeps one truthiness line, is_open and title, which prints the title because and returns one of its operands.

Collections

A queue of tuples that sorts itself

A tuple is immutable, which suits a record nobody should edit by accident. The ticket-queue demo holds three tickets as a list of tuples, each one a rank, a ticket id and a title. They are appended out of order and each is printed by its own line, which Friday's loop replaces.

Tuples compare element by element, left to right. Rank comes first, so sorted(queue) puts rank 1 at the front, and when two ranks tie the ticket id decides. Lay a tuple out so its natural order is the order you want and no sort key is needed.

sorted() returns a new list and leaves the original alone. queue.sort() sorts in place and returns None.

Assigning a list to a second name binds the same object. After backup = queue, appending through either name changes both, and the demo prints both lengths as 4. queue.copy() makes a new list, and they print as 3 and 4. The copy is shallow, meaning the items inside are shared, so a copied list of lists still shares its inner lists.

The comma is what makes a tuple. (1) is the number 1 in parentheses and (1,) is a one-element tuple. range(1, 4) gives 1, 2 and 3, because the stop value is excluded as it is in a slice. A range is an immutable sequence that computes its items on demand, so wrap it in list() to see the numbers.

Collections

Sets for membership, bytes for files and APIs

A set holds each value once and has no order. The literal in the ticket-queue demo names dana twice and the set keeps one, and .add() with a name already there changes nothing. Print sorted(reporters) when you want the same output on every run.

in asks whether a value is a member. & gives the intersection, the names in both sets, and - gives the difference, the names only in the left one.

Set elements must be hashable, which means the object has a fixed hash for its lifetime. Strings, numbers and tuples qualify and a list does not. Dictionary keys follow the same rule. {} is an empty dict, so an empty set is written set().

Text is str. Files and APIs carry bytes, an immutable sequence of integers from 0 to 255. .encode() turns a string into bytes, UTF-8 by default, and .decode() reverses it. The ticket-dict demo opens with that round trip on the ticket title.

len counts code points for a string and bytes for a bytes object, so the two can disagree.

Modelling

None for "not yet", and the ticket as a dict

None is the only value of NoneType, and it means no value: the ticket exists and nobody has been assigned. An empty string or a zero would say something different. Test for it with is None, which asks whether this is the one such object. Other types can override ==, and reviewers flag that form.

A dict maps keys to values. The ticket-dict demo replaces Wednesday's three SLA constants with one table and rewrites the line that used them:

SLA_HOURS = {"high": 4, "normal": 24, "low": 72}
hours_left = SLA_HOURS[priority] - hours_open

Adding a priority is now one entry in the table. The change also fixes a bug. Wednesday's line always subtracted from the high-priority constant, so a ticket typed as low was measured against 4 hours, and with the lookup it gets 72. The lookup works because the priority was stripped and lower-cased first.

The ticket itself becomes a dict of five fields. Its assignee starts as None and its history as an empty list. ticket["owner"] raises KeyError because the key is absent, and ticket.get("owner", "unassigned") returns the default instead. Use square brackets for keys that must exist and .get for optional ones.

in on a dict tests keys. Dicts keep insertion order, so list(ticket.items()) gives the key and value pairs as tuples in the order the fields were written. The demo's last line builds tickets_by_id, a dict from each id to its ticket, so a ticket is found by id without scanning a list.

Numbers & time

Floats that almost match, and hours that come from a clock

Binary floating point cannot represent 0.1 exactly, so adding 0.1 and 0.2 gives 0.30000000000000004, and comparing that to 0.3 with == gives False. Compare floats by rounding to the precision you care about, or by checking that the difference is tiny:

round(0.1 + 0.2, 2) == 0.3
abs((0.1 + 0.2) - 0.3) < 1e-9

/ is true division and // is floor division, so 10 divided by 4 is 2.5 with the first and 2 with the second. divmod returns the quotient and the remainder together as a tuple. A long literal can use _ as a separator, as in 1_000_000.

Until this point hours_open was a float someone typed. The ticket-clock demo computes it from two datetimes:

opened_at = datetime(2026, 10, 15, 9, 30)
NOW = datetime(2026, 10, 15, 14, 0)
age = NOW - opened_at
hours_open = age.total_seconds() / 3600

Subtracting two datetimes gives a timedelta. total_seconds() converts it to a float, and dividing by 3600 gives 4.5 hours. NOW is pinned because datetime.now() returns a different value on every run, and a rule built on it cannot be checked. These are naive datetimes, meaning they carry no time zone. Zones arrive in week 2.

Adding a timedelta to a datetime gives another datetime, which is how the deadline is built from the SLA table. The sample ticket opened at 09:30 with a 4-hour SLA, so its deadline is 13:30, and the pinned clock is already past it. .isoformat() writes the deadline as 2026-10-15T13:30:00, and .strftime() formats it by a pattern you supply.

Practice

Namespaces, the merge, and what to carry forward

A namespace is a mapping from names to objects. The top level of a file is one, and dir() lists the names in it: your variables, the names you imported, and a few that Python adds itself. Every assignment and every import binds a name, and a later binding replaces an earlier one.

The ticket-clock demo types a common import mistake and then deletes it:

from datetime import datetime
import datetime
print(datetime(2026, 10, 15))

The first line binds the name datetime to the class. The second rebinds the same name to the module, so the third fails with a TypeError saying that a module object is not callable. Keep one import style per module, and do not reuse a standard-library name for a variable.

del removes a name from the namespace, and the demo checks for backup in dir() before and after. __name__ is one of the names Python adds. It is "__main__" when the file runs as a script.

The demo ends by merging the day's branch:

git switch main
git merge feature/data-types

main has not moved since the branch started, so the merge is a fast-forward, and the log shows the day's four commits, one per demo.

Today's exercise is a pytest-checked module with four jobs: normalise a ticket title, build the queue as tuples, look up SLA hours from a dict, and compute a deadline with timedelta.

To remember from today: string methods return new strings; any non-empty string is truthy; .sort() returns None; a second name for a list is the same list; .get for optional keys and is None for missing values; no == on floats. Excerpt: the queue of tuples and its copy

Steps 1 and 2 of the ticket-queue demo. Three tuples are appended out of order, printed one by one, sorted by tuple order, and then copied.

queue = []
queue.append((2, 103, "Wi-Fi drops"))
queue.append((1, 101, "Login page returns 500"))
queue.append((2, 102, "Printer jams"))
print(queue[0])
print(queue[1])
print(queue[2])
print(queue[-1])
print(queue[1:])
print(len(queue))
print(sorted(queue))

backup = queue.copy()
backup.append((9, 999, "oops"))
print(len(queue), len(backup))

sorted(queue) prints ticket 101 first, then 102, then 103: rank decides and the id breaks the tie. The last line prints 3 4 because backup is a copy.

Excerpt: the deadline from a timedelta

Step 2 of the ticket-clock demo. The age prints as a timedelta, and the deadline is the opening time plus the SLA hours from the table.

print(age)
deadline = opened_at + timedelta(hours=SLA_HOURS[priority])
print(f"opened {opened_at.isoformat()}, deadline {deadline.isoformat()}")
print(f"past deadline: {NOW > deadline}")
print(deadline.strftime("%a %H:%M"))

For the sample ticket this prints 4:30:00, then the opening time and the 13:30 deadline in ISO form, then past deadline: True, then Thu 13:30.
