Control flow, functions & classes: deciding where a rule lives

Week 1 · Day 5 Fri Oct 16, 2026 Agile for developers, Git & Python fundamentals ~11 min · notes @150 wpm + diagram + check

This page assumes Thursday's work: the ticket is a dict, the queue is a list of tuples sorted by tuple order, and the clock gives the ticket a deadline. You wrote if statements, loops, functions and classes in coursework, so today treats them as design choices and asks one question of the ticket desk script: where should this rule live? The trainer types four demos on one branch, feature/design-choices.

Branching

A three-word status replaces a boolean

Thursday's breach flag was a boolean, which can only say yes or no. The board needs a third state, "at risk", so the control-flow demo replaces the flag with a string named status. if, elif and else pick exactly one branch: Python runs the first one whose test is true and skips the rest, so the strictest test goes first.

if NOW > deadline:
    status = "breached"
    print(f"warning: ticket {ticket_id} is past its deadline", file=sys.stderr)
elif deadline - NOW < timedelta(hours=2):
    status = "at risk"
else:
    status = "on time"

The warning to sys.stderr sits inside the breached branch, so it prints only for a breached ticket. The sample ticket's deadline is 13:30 and NOW is 14:00, so the run prints status: breached. The demo then pins NOW to 12:00 and to 09:00 so that the other two branches run at least once.

A guard clause is an early if that handles a bad or special case and returns or continues at once, so the main logic stays unnested below it. The demo first nests the checks in the queue loop, which puts the print two levels deep, then flattens them. The flat version, shown in the next section, skips an empty title and a rank above 2 first and leaves the print at the loop's own indentation. The output is the same, and a reviewer who reaches the last line of the flat version knows every earlier condition has passed.

Loops

for walks a collection, while waits for a condition

for iterates over any iterable, one item per pass. Thursday printed the queue with one print per tuple. One loop replaces those three lines, and a fourth ticket would need no new line. The header unpacks each tuple into three names:

for rank, tid, text in sorted(queue):
    if not text:
        continue
    if rank > 2:
        continue
    print(f"#{tid} [{rank}] {text}")

continue ends the current pass and starts the next one. The same loop shape reads the ticket dict: for key, value in ticket.items() prints one field per line.

while re-tests its condition before each pass and stops once the condition is false, which suits a prompt that may get any number of wrong answers. At intake the loop keeps asking until the cleaned priority is a key of SLA_HOURS. break leaves the nearest enclosing loop at once. Here it is the exit for an empty title, where the priority falls back to normal.

while priority.strip().lower() not in SLA_HOURS:
    if not title.strip():
        priority = "normal"
        break
    priority = input("Priority must be high, normal or low: ")

The whole loop sits inside Wednesday's if sys.stdin.isatty(): guard. A loop that waits for a keyboard would hang a scheduled job, so when input is piped in, the guard is false, the loop is never reached and the sample board prints.

Functions

A function gives a rule one name

Write a function when the same shape or rule would otherwise appear twice. The functions demo extracts three: make_ticket builds every ticket dict, deadline_for holds the SLA arithmetic, and is_overdue answers whether a ticket is late. Once a call has more than two arguments of similar type, teams pass them by keyword, as in priority="low", so the call documents itself.

A function with no return statement returns None. Nothing fails at the call; the None fails later, in a comparison or a sort. Defaults hold a second trap: default argument values are evaluated once, when def runs. A fixed constant such as now=NOW is safe. A mutable default is one object shared by every call that omits the argument.

A lambda is a single-expression anonymous function, most often passed as key= to sorted() or list.sort(). Once the queue holds dicts, tuple order is gone and the sort needs a function that maps each ticket to the value to sort by. A key of t["priority"] sorts the text alphabetically, which puts "low" ahead of "normal". The demo maps the text through PRIORITY_RANK and returns a tuple, so equal ranks fall through to the older ticket:

queue.sort(key=lambda t: (PRIORITY_RANK[t["priority"]], t["opened_at"]))

Pass the function itself, as in key=f. Writing key=f() calls it before the sort starts.

The demo ends on the standard library's array module. array("d", [...]) stores values of one numeric type code compactly, where a list holds any objects. Most team code uses a list and reaches for an array when the numbers are many and uniform.

Design choice

When data and its rules belong in a class

After the functions demo the ticket's data sits in a dict and its rules sit in loose functions, and every caller has to know both. A class keeps them together. You know the vocabulary: the class is the blueprint, an object is one ticket built from it, attributes hold the data and methods are the rules that act on it. __init__ runs when you write Ticket(...), and self, the first parameter of every method, is the object being worked on.

Ticket takes the four arguments make_ticket took, so each call changes its name and nothing else. deadline() is the old deadline_for and needs no argument. assign(agent) sets the assignee and appends to the history in one call, so nobody can update one and forget the other. A dict suits data you pass through, and a class suits data that carries its own rules.

Every line that treated the ticket as a dict gets an attribute-style rewrite. vars(ticket) returns the instance's __dict__, hasattr(ticket, "ticket_id") tests for an attribute, and ticket.assignee or "unassigned" replaces the .get fallback.

Without __repr__, print(ticket) shows <__main__.Ticket object at 0x...>. __repr__ supplies the string that print() and the REPL show when no __str__ exists, so one method makes every print and list display read #101 Login page returns 500 [high]. Watch for ticket.deadline without parentheses: that is the bound method, and comparing it with a datetime fails.

The Desk demo applies the same idea to the collection. Desk owns a list in self._tickets, where the leading _ is a convention for "internal, use the methods" that Python does not enforce. add is the only way in, so a later rule about rejecting a ticket changes one method. __len__ is what len(desk) calls.

Inheritance

A subclass overrides one rule and keeps the rest

class UrgentTicket(Ticket) says that an urgent ticket is a ticket. It inherits __init__, assign, close and __repr__. Defining deadline again in the subclass overrides it, so calls on an UrgentTicket run the new version. super().deadline() reaches the parent's version, and the override halves the window between opened_at and that deadline. Redefining the method without super() would copy the SLA rule into a second place, and the next contract change would miss one of them.

isinstance(t, Ticket) is true for an UrgentTicket, so every function that takes a Ticket takes an urgent one. is_overdue calls ticket.deadline() and gets the right rule for each kind with no if on the type. In the demo the Printer ticket has a 24-hour SLA and, as an urgent ticket, is due twelve hours after it was opened.

A real desk would more likely keep urgency as data on the record, the way priority already is, and save a subclass for a kind of ticket that needs behaviour of its own.

Iteration

What a for loop does underneath

A for loop asks its object for an iterator and pulls items from it until none are left. iter(obj) calls obj.__iter__(), next(it) advances the iterator, and StopIteration signals that it is exhausted. The Desk demo steps the queue by hand before removing it:

it = iter(queue)
print(next(it))
print(next(it))
print(list(it))
print(next(it))

The first two calls print the first two tickets and list(it) drains the third. The last next(it) has nothing to return, so the run ends in a StopIteration traceback.

An iterator is single use: after one pass, a second pass yields nothing. A class that defines __iter__ works in a for loop, and Desk.__iter__ returns a fresh iter(self._tickets) each time it is asked, so every loop over the desk starts from the first ticket. sorted() accepts any iterable, which lets the sort move into the loop header:

for t in sorted(desk, key=lambda x: (PRIORITY_RANK[x.priority], x.opened_at)):

sorted returns a new list and leaves the desk's own order alone.

Scope

Scope: where a name is found, and where state should sit

Python searches for a name in four places, in order: local, enclosing, global, built-in (LEGB). Assigning to a name inside a function makes it local unless it is declared global or nonlocal. The Desk demo keeps a small function, label(), that assigns title = "shadowed". The local name hides the module's title inside the function and leaves it unchanged, so the run prints shadowed | Login page returns 500. Enclosing is the scope of an outer function around an inner one, and nonlocal does for it what global does for the module.

Inside a function, next_id += 1 raises UnboundLocalError: the assignment makes the name local, and it is read before it has a value. A plain next_id = 1 raises nothing and silently creates a local, leaving the module-level counter unchanged. global next_id makes the counter work and leaves you with state that any line in the file can change, so the demo deletes it and puts the counter on the class. A class attribute is shared by all instances and is read as Desk.next_id, while self._tickets, set in __init__, belongs to one desk. After tickets 1, 2 and 3 are added the run prints next id: 4.

Excerpt: the subclass and the rule function

From the Ticket class demo. UrgentTicket writes one method; is_overdue never asks which kind of ticket it was given.

class UrgentTicket(Ticket):
    """A ticket that gets half the usual time."""

    def deadline(self):
        return self.opened_at + (super().deadline() - self.opened_at) / 2


def is_overdue(ticket, now=NOW):
    """Return True when the ticket is past its deadline."""
    return now > ticket.deadline()

super().deadline() is the SLA deadline from Ticket. Subtracting opened_at gives the window as a timedelta, and a timedelta can be divided by a number.

Excerpt: the Desk class

From the Desk demo. One class attribute, one instance attribute, and the two special methods that make len() and for work.

class Desk:
    """A desk owns its tickets and hands them out one at a time."""

    next_id = 1

    def __init__(self):
        self._tickets = []

    def add(self, ticket):
        self._tickets.append(ticket)
        Desk.next_id = max(Desk.next_id, ticket.ticket_id + 1)

    def __len__(self):
        return len(self._tickets)

    def __iter__(self):
        return iter(self._tickets)

    def overdue(self, now):
        late = []
        for t in self._tickets:
            if is_overdue(t, now):
                late.append(t)
        return late

next_id sits in the class body, so every Desk shares it. _tickets is created in __init__, so each Desk has its own list.
