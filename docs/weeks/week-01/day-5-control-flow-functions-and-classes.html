Control flow, functions & classes: design choices in plain Python

Week 1 · Day 5 Fri Oct 16, 2026 Agile for developers, Git & Python fundamentals ~39 min · reference notes @150 wpm · diagram · check Sources checked 2026-10-12 · python 3.15

This page assumes Thursday's data types: a ticket stored as a dict, a queue of tuples sorted by tuple order, and deadlines worked out with datetime and timedelta. It treats control flow, functions and classes as design choices, covering if/elif/else and guard clauses, while and for loops, functions and their two classic traps, lambda sort keys, arrays and lists, OOP concepts, classes and objects, inheritance, iterators and scope. Each section shows a runnable example, names the trade-off and ends with the words to say when an interviewer asks. Afterwards you can explain why a mutable default is a bug, what a for loop does underneath, how super() and isinstance behave, and why next_id += 1 inside a function raises UnboundLocalError.

Control flow

Branching with if, elif and else

You have written if statements since your first programming course. On a team the question is which shape of branch makes the rule easiest to read and hardest to break when the next person edits it.

One branch runs: the first whose test is true

An if statement with elif and else parts runs at most one block. Python tests the conditions from the top, runs the block of the first one that is true and skips the rest; the else block runs only when none of them was true.1 Blocks are marked by indentation alone, and PEP 8 sets four spaces per level.2 A ticket's status is a good example, because it has three answers and exactly one of them applies.

from datetime import datetime, timedelta

NOW = datetime(2026, 10, 16, 12, 0)
deadline = datetime(2026, 10, 16, 13, 30)

if NOW > deadline:
    status = "breached"
elif deadline - NOW < timedelta(hours=2):
    status = "at risk"
else:
    status = "on time"
print(status)

This prints at risk. The deadline has not passed, so the first test is false, and ninety minutes is under two hours, so the elif block runs and the else is skipped. The order of the tests carries meaning. A breached ticket also has less than two hours left (a negative amount), so if the "at risk" test came first, a breached ticket would be reported as at risk and the breach branch would never run. Put the strictest test first.

That is also the difference between elif and a second if. Two separate if statements are tested independently, so both can run and the second can overwrite what the first set. An elif is tested only when everything above it was false. The trade-off of a long chain is that it grows one branch per case and has to be edited for each new value.1 When every branch only compares the same variable to a constant, a dict such as SLA_HOURS = {"high": 4, "normal": 24, "low": 72} keeps the table as data and one lookup replaces the chain. The chain keeps one ability the dict lacks: each branch can test a different, arbitrary condition, as the status example does.

What counts as false

A condition does not have to be a bool. Empty containers, 0, 0.0, "" and None are false in a test, and most other objects are true.3

for value in [0, 0.0, "", None, [], {}, "0", [0]]:
    print(repr(value), bool(value))

The first six lines end in False. The last two end in True: "0" is a non-empty string and [0] is a list with one item in it. So if queue: reads as "if the queue has anything in it", which is the idiomatic test. The operators and and or short-circuit and return one of their operands, which is not necessarily a bool.4 That is why assignee or "unassigned" evaluates to "unassigned" when assignee is None. The limit of truthiness is that it lumps values together: if 0 is a valid ticket count, if count: treats it the same as a missing count. When you mean "is missing", say so. PEP 8 asks for comparisons to None to use is or is not, never ==.2

Guard clauses instead of nesting

A guard clause is an early if that handles a bad or special case and returns at once, so the main logic sits unnested below it. Compare a nested version with a guarded one:

def describe_nested(ticket):
    if ticket is not None:
        if ticket["title"]:
            return f"#{ticket['id']} {ticket['title']}"
        else:
            return "untitled"
    else:
        return "no ticket"


def describe(ticket):
    if ticket is None:
        return "no ticket"
    if not ticket["title"]:
        return "untitled"
    return f"#{ticket['id']} {ticket['title']}"


print(describe(None))
print(describe({"id": 7, "title": ""}))
print(describe({"id": 7, "title": "Printer jams"}))

Both functions behave the same, and the three calls print no ticket, untitled and #7 Printer jams. The guarded version reads top to bottom as a list of exclusions followed by the normal case, and adding a fourth special case means adding two lines at the top instead of another level of indentation. Nesting still has a place when both branches do real work of similar weight; a guard clause suits the case where one branch is an exit. You recognise the pattern in other people's code as if x is None: return, or a continue inside a loop, at the very top of a block.

The conditional expression

The usual follow-up question is the expression form of the same branch: label = "late" if NOW > deadline else "ok". It produces a value, so it fits inside an assignment, an f-string or a function argument, and it always needs both halves. It reads well for a choice between two short values. Once either half needs its own logic, or a third case appears, the statement form is clearer.

Say it in an interview

An elif is only tested when every condition above it was false, so a chain runs exactly one branch, the first true one. Two separate ifs are tested independently, so both can run. That's why I put the strictest test first.

Zero, empty strings, empty containers and None are false in a condition, and almost everything else is true. For None specifically I write "is None" rather than relying on truthiness or using double equals.

A guard clause handles the special case at the top and returns early, so the main logic isn't nested. I use it when one branch is really an exit, and keep nesting for two branches that both do real work.

Control flow

Loops: while for a condition, for over a collection

While loops: repeat until the condition fails

A while statement tests its condition before every pass and stops as soon as it is false.5 Use it when you cannot say in advance how many passes there will be, only what has to become true to stop. The natural example is input validation: keep asking until the answer is acceptable.

SLA_HOURS = {"high": 4, "normal": 24, "low": 72}

priority = input("Priority (high, normal, low): ")
while priority not in SLA_HOURS:
    priority = input("Priority must be high, normal or low: ")
print(f"priority set to {priority}")

Type urgent at the first prompt and the second prompt appears; type high there and the script prints priority set to high. The limit is the one every reviewer checks: the body must change something the condition reads. If the body forgot to reassign priority, the loop would run forever. A for loop over a finite collection cannot have that bug.1 You recognise the shape on sight as while value not in allowed: value = input(...).

The re-ask loop, break, continue and the loop else

break leaves the nearest enclosing loop and continue jumps to its next pass.1 while True: never fails its own test, so it runs until a break inside the body ends it, which lets the exit test sit in the middle of the body instead of at the top.5 A loop can also carry an else block, which runs when the loop ends without a break.1 It reads as "no break happened", which makes it a search's not-found branch:

queue = [(2, 102, "Printer jams"), (1, 101, "Login page returns 500")]
for rank, tid, text in queue:
    if tid == 105:
        print("found", text)
        break
else:
    print("no ticket 105")

No item matches, the loop runs to the end, and the else prints no ticket 105. Change 105 to 101 and the loop prints found Login page returns 500, breaks, and the else is skipped.

For loops: walk any iterable

for takes items from any iterable in order and binds the loop variable on each pass.5 A list, a tuple, a string, a dict, a file and a range all qualify. range(n) yields 0 to n-1 and does not build a list of the numbers up front.1 When each item is a tuple, the loop header can unpack it:

queue = [(2, 102, "Printer jams"), (1, 101, "Login page returns 500"), (3, 103, "Update footer year")]
for rank, tid, text in sorted(queue):
    print(rank, tid, text)

This prints 1 101 Login page returns 500, then 2 102 Printer jams, then 3 103 Update footer year. One loop replaces one print per item, and it keeps working when the queue grows to a hundred tickets.

enumerate, zip and dict.items()

A Python for keeps no counter of its own. When you need a position, enumerate(iterable, start=0) yields (index, item) pairs.6 zip walks several iterables side by side and stops at the shortest one unless strict=True is passed.6 dict.items() yields key and value pairs that unpack in the header.7

titles = ["Login page returns 500", "Printer jams"]
owners = ["lee", "dana", "sam"]
for n, title in enumerate(titles, start=1):
    print(n, title)
for title, owner in zip(titles, owners):
    print(title, "->", owner)

The first loop prints the two titles numbered 1 and 2. The second prints two pairs and silently drops sam, because titles ran out first. for i in range(len(items)): followed by items[i] is the habit reviewers flag; for item in items or enumerate says the same thing directly.

Changing a list while you loop over it

Adding or removing items from a list while a for loop walks it can skip elements or repeat them.1

ids = [101, 102, 102, 103]
for i in ids:
    if i == 102:
        ids.remove(i)
print(ids)

This prints [101, 102, 103]. Removing the first 102 shifts everything left, the loop moves on to the next position, and the second 102 is never looked at. Loop over a copy, for i in ids.copy():, and the result is [101, 103]; or build a new list of the items you want to keep.

Say it in an interview

I use while when I know the stopping condition but not the number of passes, like re-asking for input until it's valid. I use for when I'm walking a collection, because it can't loop forever and it reads more directly.

Break leaves the nearest loop, continue skips to the next pass, and the else on a loop runs only if the loop finished without a break. It's handy for a search's not-found case.

Removing items from a list while looping over it shifts the remaining items, so the loop skips some. I loop over a copy or build a new list instead.

Functions

Functions: naming a rule once

When the same rule appears in three places in a script, a change to it has to be made three times, and one of them will be missed. A function gives the rule one name and one home.

def, parameters and arguments

def is a statement: when it runs, it creates a function object and binds it to the name.1 The names in the def line are parameters; the values a caller passes are arguments. If the first statement of the body is a string literal, it becomes the function's docstring, readable as __doc__,1 and PEP 257 asks for a one-line docstring that ends with a period and states the effect as a command ("Return ...", not "Returns ...").8

from datetime import datetime, timedelta

SLA_HOURS = {"high": 4, "normal": 24, "low": 72}


def deadline_for(priority, opened_at):
    """Return when a ticket with this priority breaches its SLA."""
    return opened_at + timedelta(hours=SLA_HOURS[priority])


print(deadline_for("high", datetime(2026, 10, 16, 9, 30)))
print(deadline_for.__doc__)

The first line prints 2026-10-16 13:30:00, four hours after the ticket opened, and the second prints the docstring. Functions are objects like any other value, so they can be passed as arguments and returned,9 which is what makes the sort keys in the next section possible.

No return means None

A function with no return statement, or with a bare return, gives back None.1

def log_ticket(title):
    print(f"logged: {title}")


result = log_ticket("Printer jams")
print(result)

This prints logged: Printer jams and then None. The bug it causes is quiet: a function that prints its answer instead of returning it looks right when you run it by hand, and the caller that compares or sorts on the result receives None. If a caller needs the value, return it and let the caller decide whether to print.

The mutable default argument

Default values are evaluated once, when the def statement runs, and not on each call.1 For an immutable default such as 0 or "normal" that makes no difference. For a list it does:

def add_note(text, history=[]):
    history.append(text)
    return history


print(add_note("opened"))
print(add_note("assigned"))

The first call prints ['opened'] and the second prints ['opened', 'assigned']. Both calls appended to the one list created when def ran, so notes leak from one ticket into the next. The fix is to default to None and build the list inside the body:

def add_note(text, history=None):
    if history is None:
        history = []
    history.append(text)
    return history


print(add_note("opened"))
print(add_note("assigned"))

Now the calls print ['opened'] and ['assigned']. The cost of the idiom is one extra check in the body, which is cheap next to a shared-state bug.1 Recognise it as def f(items=None): followed by if items is None: items = []; a reviewer who sees =[] or ={} in a signature will ask you to change it.

Positional and keyword arguments

The follow-up question is how callers may pass values. Arguments can be passed by position or by keyword, as in deadline_for(priority="low", opened_at=start), and in a call a keyword argument may not come before a positional one.1 Keywords cost a few characters and buy a call that reads without the signature open beside it, which matters most when several parameters share a type and could be swapped by mistake. The same tutorial section goes on to *args and **kwargs, which let a function accept extra positional and keyword arguments.1

Say it in an interview

A parameter is the name in the function definition; an argument is the value the caller passes in. Callers can pass arguments by position or by keyword, and keywords make a call readable without the signature.

A function with no return statement returns None. The classic bug is printing the result instead of returning it, so the caller ends up comparing None.

Default values are evaluated once, when def runs, so a list default is shared by every call that doesn't pass one. I default to None and create the list inside the function.

Functions

Lambda and sort keys

A list of tuples sorts by tuple order, first element first, which works only while the first element happens to be the thing you want to sort by. Records stored as dicts have no natural order, so the sort has to be told what to compare.

Lambda: a function in one expression

lambda args: expr builds an anonymous function whose body is a single expression.4 lambda t: t["priority"] is the same function as a two-line def that returns t["priority"], written where it is used. Its limits come from the same definition: one expression, no statements, no docstring, and no name to show in a traceback.1 Anything longer, reused in two places or worth documenting belongs in a def. PEP 8 also says to write def f(x): ... rather than assign a lambda to a name, because a def gives the function a real name.2 In practice lambdas appear in one place more than any other: the key= argument of a sort.

Sorting records by a key

sorted() and list.sort() call the key function once per item and compare the results instead of the items.10 A tuple key sorts by its first element and uses the second only to break ties.10

from datetime import datetime

PRIORITY_RANK = {"high": 1, "normal": 2, "low": 3}
queue = [
    {"id": 1, "priority": "normal", "opened_at": datetime(2026, 10, 15, 11, 0)},
    {"id": 2, "priority": "low", "opened_at": datetime(2026, 10, 15, 8, 0)},
    {"id": 3, "priority": "normal", "opened_at": datetime(2026, 10, 14, 9, 0)},
    {"id": 4, "priority": "high", "opened_at": datetime(2026, 10, 15, 13, 0)},
]

by_text = sorted(queue, key=lambda t: t["priority"])
print([t["id"] for t in by_text])

queue.sort(key=lambda t: (PRIORITY_RANK[t["priority"]], t["opened_at"]))
print([t["id"] for t in queue])

The first print shows [4, 2, 1, 3], and it is wrong. Sorting on the priority text compares strings alphabetically, and "high" < "low" < "normal", so the low ticket jumps ahead of both normal ones. The second key maps the text to a rank first and breaks ties on the opening time, and it prints [4, 3, 1, 2]: the high ticket, the older normal ticket, the newer normal ticket, then the low one. In a code review you will see this shape as sorted(rows, key=lambda r: (r.rank, r.opened_at)).

The other common slip is calling the function instead of passing it. With a helper such as rank_of, key=rank_of passes the function so the sort can call it per item; key=rank_of() calls it once and hands the sort its result instead.

sorted() versus list.sort(), and stable sorting

sorted() takes any iterable and returns a new list, leaving the original alone; list.sort() sorts the list in place.10 Use sorted() when the original order still matters to someone else, or when the input is not a list at all. Use .sort() when you own the list and want it reordered.

Python's sort is stable, so items with equal keys keep their original order.10 You can see it in the first print above: tickets 1 and 3 have the same key, "normal", and come out in the order they went in.

Say it in an interview

A lambda is an anonymous function limited to one expression. I use it inline for short things like a sort key; anything longer, reused or worth a docstring gets a def with a proper name.

To sort records by a field I pass a key function, usually a lambda, that returns a tuple: the main field first, then the tie-breaker. If the field is text like a priority, I map it to a rank first so it doesn't sort alphabetically.

Key equals f passes the function so the sort can call it per item. Key equals f with parentheses calls it once, immediately, and hands the sort the result instead.

Data

Arrays and lists

Is a Python list an array?

Interviewers coming from Java or C ask this to see whether you know what a list is underneath. A Python list is a mutable sequence of references, and the items it refers to may be of mixed types.7 [101, "Printer jams", 4.0, None] is a perfectly good list. In CPython it is implemented as a dynamic array of references to objects, so it is an array in the data structures sense: indexing by position is fast, and it grows as you append.11 What it does not store is the values themselves side by side. Each slot holds a reference to a separate Python object, which is flexible and costs memory.

Arrays: array.array for one numeric type

The standard library's array module stores values of one fixed numeric type compactly. You choose the type with a type code, and "d" is a C double.12 An array supports indexing, slicing, append and len() like a list, and rejects a value of the wrong type.12

from array import array

ages = array("d", [3.0, 29.0, 6.0])
ages.append(12.5)
print(ages[0], len(ages), ages[1:3])
print(ages)
ages.append("late")

The first print shows 3.0 4 array('d', [29.0, 6.0]) and the second array('d', [3.0, 29.0, 6.0, 12.5]). The last line stops the script with an error, because a string is not a double. That rejection is the trade-off. Packing values into a compact C buffer saves memory, which matters for a few million readings and not for a queue of tickets, and the price is that the array accepts only its type code and lacks list-only methods such as sort().12 You recognise one on sight by the type-code string as its first argument, array("d", [1.5, 2.0]). For ordinary application data, a list is the default.

Copies are shallow

Slicing a list returns a new list,13 and list.copy() does the same, but both are shallow copies: the new list holds references to the same objects, so nested objects are shared between the copies.7

tickets = [{"id": 1, "tags": ["printer"]}]
backup = tickets.copy()
backup[0]["tags"].append("hardware")
print(tickets[0]["tags"])
print(backup is tickets, backup[0] is tickets[0])

This prints ['printer', 'hardware'] and then False True. The two lists are different objects, but they point at the same ticket dict, so a change made through the backup shows up in the original. Adding or removing items affects only one list; changing an item that both lists share shows up in both.

List performance: the cheap end and the expensive end

Because a list is a dynamic array of references, append is amortised O(1): the array keeps spare room and only occasionally has to grow.11 Inserting or removing at the front is different. insert(0, x) and pop(0) are O(n), because every other element has to shift one place.7 A list makes a good stack, adding and removing at the end, and a slow queue once it is long. In code review the warning sign is pop(0) inside a loop over a large list.

Say it in an interview

A Python list is a dynamic array of references, so it can hold mixed types, indexing is fast and appending is amortised constant time. Inserting or popping at the front is linear, because everything after it shifts.

I'd use array dot array when I have a lot of numbers of one type and memory matters. It packs the raw values into a compact buffer instead of storing a reference to a separate object for each one, but it only accepts its one type.

Classes

OOP concepts, classes and objects

OOP concepts in Python terms

You met the vocabulary at university; here is how it maps onto Python. Encapsulation means keeping data together with the rules that use it, behind methods. Python classes support it, along with inheritance, overriding and multiple base classes, but all members are public by default.14 A leading underscore, as in self._tickets, marks a name as internal by convention only, and the language does not block access to it.14 Inheritance, a class built on another class, has its own section next. Polymorphism in Python works by behaviour: any object that has the method a piece of code calls will work there, whatever its class. The glossary calls this duck typing.15 A function that calls ticket.deadline() works for every kind of ticket that has a deadline method.

Classes and objects: self, __init__ and __repr__

A class is the definition; an object, or instance, is one value built from it. Calling the class creates an instance and passes it as self to __init__,14 which sets it up and must return None.9 In every method, self is the instance the method was called on, passed automatically when you write obj.method().14

from datetime import datetime, timedelta

SLA_HOURS = {"high": 4, "normal": 24, "low": 72}


class Ticket:
    """One support ticket and the rules that belong to it."""

    def __init__(self, ticket_id, title, priority, opened_at):
        self.ticket_id = ticket_id
        self.title = title
        self.priority = priority
        self.opened_at = opened_at
        self.assignee = None

    def deadline(self):
        """Return when this ticket breaches its SLA."""
        return self.opened_at + timedelta(hours=SLA_HOURS[self.priority])

    def assign(self, agent):
        self.assignee = agent

    def __repr__(self):
        return f"Ticket({self.ticket_id!r}, {self.title!r})"


t = Ticket(101, "Login page returns 500", "high", datetime(2026, 10, 16, 9, 30))
t.assign("lee")
print(t)
print(t.deadline())
print(t.deadline)
print(hasattr(t, "assignee"), vars(t)["assignee"])

The prints show Ticket(101, 'Login page returns 500'), then 2026-10-16 13:30:00, then <bound method Ticket.deadline of Ticket(101, 'Login page returns 500')>, then True lee. The first line comes from __repr__, which supplies the string print() shows when the class has no __str__. Delete it and the same line reads <__main__.Ticket object at 0x...>.9 The third line is the trap reviewers spot: t.deadline without parentheses is the bound method object, and only t.deadline() calls it.14 vars(t) returns the instance's __dict__ of attributes, and hasattr(t, "assignee") is true when the attribute exists,6 which is how you inspect an object you did not write.

The follow-up after any class is __str__ versus __repr__. __repr__ is the developer-facing text, the one the REPL and debugging output use, and print() falls back to it.9 Write __repr__ first; add __str__ only when end users need a different, friendlier string.

When a class beats a dict

A dict ticket and a set of loose functions that take it work until the rules multiply. A class bundles the data with those rules, so a reader looking for how a ticket's deadline works finds it on the ticket, and a caller writes ticket.deadline() without knowing which helper function to import. The cost is ceremony: an __init__, a self on every method, more lines. For a record with no behaviour, a dict or a tuple is lighter, and since Python enforces privacy only by naming convention, hiding data is not a reason on its own to write a class.14 The working rule: once two or more functions take the same dict and reach into the same keys, the dict wants to be a class.

Composition versus inheritance

The question after the OOP principles is "has-a or is-a". An instance can store other objects in its data attributes, which the tutorial calls instance variables,14 so a desk that holds a list of tickets has tickets: that is composition. An urgent ticket is a ticket: that is inheritance. If you cannot say "is a" truthfully, hold the object in an attribute instead of subclassing it.

Say it in an interview

Encapsulation keeps data and the rules that use it together behind methods. Inheritance builds a class on an existing one. Polymorphism means code can call the same method on different kinds of objects; in Python that's duck typing, so the object only needs the method, not a particular class.

A class is the definition and an object is one instance of it. Self is that instance, passed automatically when I call a method on it.

I switch from a dict to a class when several functions keep reaching into the same keys. The class puts those rules next to the data. For a plain record with no behaviour, a dict is fine.

Classes

Inheritance: one rule overridden

Overriding a method and calling super()

A derived class is written class Derived(Base):. When an attribute or method is missing on the derived class, lookup falls through to the base.14 A subclass overrides a method by defining one with the same name, and super() returns a proxy that delegates method calls to the parent class, so the override can build on the parent's version instead of copying it.6 Urgent tickets get half the usual time. Add this below the Ticket class from the previous section:

class UrgentTicket(Ticket):
    """A ticket that gets half the usual time."""

    def deadline(self):
        return self.opened_at + (super().deadline() - self.opened_at) / 2


u = UrgentTicket(102, "Printer jams", "normal", datetime(2026, 10, 16, 9, 0))
print(u.deadline())
print(u)
print(isinstance(u, Ticket), type(u) == Ticket, issubclass(UrgentTicket, Ticket))

A normal ticket gets 24 hours, so the parent's deadline is 09:00 the next day; halving the window prints 2026-10-16 21:00:00. The second line prints Ticket(102, 'Printer jams'), because UrgentTicket did not define __repr__ and lookup fell through to the parent. The last line prints True False True.

The override reuses the SLA table through super().deadline(), so a contract change to SLA_HOURS reaches urgent tickets too. Copying the parent's formula into the subclass would work today and silently drift the first time someone edits only one of them. You recognise the pattern in other people's code as class UrgentTicket(Ticket): with a method whose body calls super().method().

isinstance, issubclass and type

isinstance(obj, Cls) is true for instances of Cls and of its subclasses;6 issubclass(Sub, Base) asks the same question about two classes rather than an instance.6 That is the whole difference from type(x) == Ticket, which is false for an UrgentTicket. A check written with type() rejects every subclass, which is almost never what the author meant. Better still, a function such as is_overdue(ticket) that only calls ticket.deadline() needs no type check at all: both kinds of ticket have the method, and each runs its own version.

A subclass with its own __init__

If a subclass defines __init__, it must call the parent's __init__ itself, or the parent's setup does not run.9

class EscalatedTicket(Ticket):
    def __init__(self, ticket_id, title, priority, opened_at, manager):
        super().__init__(ticket_id, title, priority, opened_at)
        self.manager = manager


e = EscalatedTicket(103, "VPN down", "high", datetime(2026, 10, 16, 8, 0), "dana")
print(e.manager, e.deadline())

This prints dana 2026-10-16 12:00:00. Leave out the super().__init__ line and e.manager still works, but e.deadline() fails, because opened_at and priority were never set. Forgetting super() in an override is the general form of this bug: the parent's rule is silently lost.

The trade-off is coupling. A subclass depends on the attributes and methods it inherits, and a base-class method that calls another method on self may end up running the subclass's override.14 A change in the parent changes the child. Keep inheritance for a true is-a relation and prefer holding an object otherwise.

Multiple bases and the method resolution order

Python classes may list more than one base class.14 Python then needs a fixed order in which to search the bases for a method, called the method resolution order, and it is the question that follows once super() is explained. The single-base case is the starting point: when a name is missing on the subclass, attribute lookup falls through to the base class.14

Say it in an interview

A subclass overrides a method by defining one with the same name. Inside it I call super() to reach the parent's version, so I build on the parent's rule instead of copying it.

Isinstance is true for the class and any of its subclasses, while comparing type with double equals only matches the exact class. So isinstance is usually what I want, and often I don't need a type check at all if the object has the method.

Mechanics

Iterators: what a for loop does underneath

iter(), next() and StopIteration

A for loop calls iter() on its target once, then calls next() on the result until StopIteration is raised, which ends the loop.14 You can do the same steps by hand:

queue = ["Login page returns 500", "Printer jams"]
it = iter(queue)
print(next(it))
print(next(it))
print(next(it))

The first two calls print the two titles. The third finds nothing left and raises StopIteration, so the script ends with a traceback.16 Inside a for loop the same exception is the normal, silent signal that the items have run out. The formal name for this arrangement is the iterator protocol: an iterable's __iter__ returns an iterator, and the iterator provides __next__.3 In application code you seldom step an iterator by hand; when you do meet it = iter(items) followed by next(it), someone wanted the first item, or wanted to consume a header row before looping over the rest. Writing your own __next__, or a generator with yield, is week 2 material.

Iterables versus one-shot iterators

An iterable is something you can ask for an iterator; an iterator is the object that keeps a position and hands out the next item. A list is an iterable, and each iter(list) call returns a new, independent iterator.3 An iterator itself keeps one position and gives each item once. That saves memory, since nothing is copied, but it cannot be rewound or indexed.14

queue = ["Login page returns 500", "Printer jams"]
it = iter(queue)
print(list(it))
print(list(it))
print(list(queue), list(queue))

The first line prints both titles and the second prints []: the iterator was used up. The third prints both titles twice, because each pass over the list asked for a fresh iterator. Code that stores an iterator in a variable and loops over it twice gets nothing the second time, so ask the iterable for a new iterator for each pass.

A class that works with for and len()

A class that defines __iter__ works in a for loop,14 and len() on an object works only if its class defines __len__.9 A desk that owns a list of tickets can delegate both to the list:

class Desk:
    def __init__(self):
        self._tickets = []

    def add(self, ticket):
        self._tickets.append(ticket)

    def __len__(self):
        return len(self._tickets)

    def __iter__(self):
        return iter(self._tickets)


desk = Desk()
desk.add("Login page returns 500")
desk.add("Printer jams")
print(len(desk))
for t in desk:
    print(t)
print(sorted(desk))

This prints 2, the two titles, and then the sorted list of both. Because __iter__ returns a fresh iter(self._tickets) every time it is called, the desk can be looped over as often as you like, and sorted() accepts it like any other iterable. Picture the other design, where __init__ builds one iterator up front and __iter__ hands back that same object every time: the first loop would print both titles and every later loop would print nothing, the one-shot problem from the previous subsection built into the class. Without __len__, len(desk) fails. The underscore on _tickets tells callers to go through the desk's methods. You recognise the pattern on sight as def __iter__(self): return iter(self._items).

Say it in an interview

An iterable is anything I can ask for an iterator, like a list. The iterator keeps a position and hands out one item at a time, and once it's exhausted it stays empty.

Under the hood a for loop calls iter on the object once, then next on the iterator again and again until it raises StopIteration, which the loop treats as the end.

An iterator can only be consumed once because it only moves forward. If I need two passes, I ask the original collection for a new iterator.

Mechanics

Scope: where a name is looked up

The LEGB rule

When Python meets a name, it looks in four scopes in order: local (the current function), enclosing (any function wrapped around it), global (the module) and built-in.14 The first scope that has the name wins.

title = "Login page returns 500"


def label():
    title = "shadowed"
    return title


print(label(), "|", title)
print(len(title))

This prints shadowed | Login page returns 500 and then 22. Inside label(), the local title shadows the module's, and the module's value is untouched. len is found in none of the first three scopes, so it comes from the built-ins. Only modules, functions (lambdas included), classes and comprehensions create scopes; if, for and while blocks do not.17 A loop variable is still defined after the loop ends, holding the last value it took, and a name first assigned inside an if belongs to the surrounding function.

global, nonlocal and UnboundLocalError

An assignment anywhere in a function makes that name local for the whole function, from its first line.17 Reading a module-level name inside a function needs no declaration; rebinding it needs global.18 Put those two rules together and you get the classic interview puzzle:

next_id = 1


def take_id():
    next_id += 1
    return next_id


take_id()

This ends in UnboundLocalError. The += assigns to next_id, so the name is local throughout take_id, and the read half of += finds a local with no value yet. A plain next_id = 1 in the body would raise nothing and silently create a local, leaving the module's counter unchanged, which is worse because nothing reports the mistake. Adding global next_id as the first line makes it work. The trade-off is that the counter is now state any function in the file can change, in a place callers cannot see.14 You recognise it on sight as global counter at the top of a function body, and reviewers usually ask where the state should live instead. nonlocal is the same idea one level in: it rebinds a name in the nearest enclosing function scope.18

Class attributes in place of a global

The usual answer is to put the state on an object or class, where the dependency is explicit. A class attribute is shared by all instances, while self.x set in __init__ belongs to one instance.14

class Desk:
    next_id = 1

    def __init__(self):
        self._tickets = []

    def add(self, title):
        self._tickets.append((Desk.next_id, title))
        Desk.next_id += 1


a = Desk()
b = Desk()
a.add("Login page returns 500")
b.add("Printer jams")
print(Desk.next_id)
b.next_id += 1
print(Desk.next_id, b.next_id, a.next_id)

The first print shows 3: two desks, one shared counter. The last line answers a favourite follow-up question. b.next_id += 1 reads 3 through the instance, then assigns 4 as a new instance attribute on b that hides the class attribute, so the line prints 3 4 3.14 This is why the method writes Desk.next_id explicitly. The same sharing makes a mutable class attribute, such as a list in the class body, a shared-state bug unless sharing is the point.

Closures

The enclosing level of LEGB leads to the next question. A nested function can read a variable of the function around it, because the enclosing function's scope sits between local and global in the lookup order.14 A nested function that reads an enclosing variable is a closure, and nonlocal rebinds a name in the nearest enclosing function scope, which lets the inner function change the variable:18

def make_counter():
    count = 0

    def take():
        nonlocal count
        count += 1
        return count

    return take


take = make_counter()
print(take(), take(), take())

This prints 1 2 3. Without the nonlocal line, count += 1 would make count local to take and fail with the same UnboundLocalError as before.

Say it in an interview

LEGB is the order Python looks up a name: local, then any enclosing function, then the module's globals, then the built-ins. The first scope that has the name wins.

Count plus-equals one inside a function raises UnboundLocalError because any assignment makes the name local for the whole function, so the read happens before the local has a value. Global or nonlocal fixes it, but I'd usually move the state onto a class instead.

Check yourself

Ten retrieval questions, at least one per section. Answer each out loud before you open it.

A status chain tests "less than two hours left" before "past the deadline". What goes wrong for a breached ticket?

A breached ticket has a negative time left, which is also less than two hours, so the first branch runs and reports it as at risk. Only the first true branch of an if/elif/else chain runs, so the breach branch is never reached. The strictest test goes first.

Which values are false in an if test, and what does assignee or "unassigned" give when assignee is None?

0, 0.0, "", None and empty containers are false; most other objects are true. or returns one of its operands, so the expression gives "unassigned".

When do you reach for while instead of for, and when does a loop's else block run?

Use while when you know the stopping condition but not the number of passes, such as re-asking until the input is valid; use for to walk a collection. A loop's else runs when the loop finishes without a break.

Why does def add_note(text, history=[]) leak notes between calls, and what is the fix?

Default values are evaluated once, when def runs, so every call that omits history appends to the same list. Default to None and create a new list in the body when the argument is None.

A teammate sorts tickets with key=lambda t: t["priority"]. What is wrong, and how do you fix it?

The key is the priority text, which sorts alphabetically, so "low" lands before "normal". Map the text to a rank first, and add the opening time as a tie-breaker: key=lambda t: (PRIORITY_RANK[t["priority"]], t["opened_at"]).

Is a Python list an array, and when would you use array.array?

In CPython a list is a dynamic array of references to objects, so it can mix types and appends are amortised O(1). array.array stores raw values of one numeric type code compactly, which saves memory for large amounts of numeric data, but it accepts only that type.

What does self refer to, and what is the difference between t.deadline and t.deadline()?

self is the instance the method was called on, passed automatically. t.deadline is the bound method object; only t.deadline() calls it and returns the datetime.

How does UrgentTicket reuse the parent's deadline rule, and why is isinstance(u, Ticket) true when type(u) == Ticket is false?

Its deadline override calls super().deadline() and halves the window, so the SLA table stays in one place. isinstance is true for instances of subclasses, while comparing type() matches only the exact class.

What does a for loop do underneath, and why does a second pass over the same iterator print nothing?

It calls iter() on the target once, then next() until StopIteration is raised. An iterator keeps one position and only moves forward, so once exhausted it stays empty; a class whose __iter__ returns a fresh iterator can be looped over again.

Why does next_id += 1 inside a function raise UnboundLocalError, and what happens if you write desk.next_id += 1 on an instance?

Any assignment makes the name local for the whole function, so the read half of += finds a local with no value. On an instance, the line reads the class attribute and then creates a separate instance attribute that hides it, leaving Desk.next_id unchanged.

Answer key excerpt: 03_ticket_class.py

From the ticket-desk code once the dict became a class. UrgentTicket writes one method; is_overdue never asks which kind of ticket it was given.

class UrgentTicket(Ticket):
    """A ticket that gets half the usual time."""

    def deadline(self):
        return self.opened_at + (super().deadline() - self.opened_at) / 2


def is_overdue(ticket, now=NOW):
    """Return True when the ticket is past its deadline."""
    return now > ticket.deadline()

super().deadline() is the SLA deadline from Ticket. Subtracting opened_at gives the window as a timedelta, and a timedelta can be divided by a number.

Answer key excerpt: 04_desk_object.py

From the ticket-desk code's final state. One class attribute, one instance attribute, and the two special methods that make len() and for work.

class Desk:
    """A desk owns its tickets and hands them out one at a time."""

    next_id = 1

    def __init__(self):
        self._tickets = []

    def add(self, ticket):
        self._tickets.append(ticket)
        Desk.next_id = max(Desk.next_id, ticket.ticket_id + 1)

    def __len__(self):
        return len(self._tickets)

    def __iter__(self):
        return iter(self._tickets)

    def overdue(self, now):
        late = []
        for t in self._tickets:
            if is_overdue(t, now):
                late.append(t)
        return late

next_id sits in the class body, so every Desk shares it. _tickets is created in __init__, so each Desk has its own list.
