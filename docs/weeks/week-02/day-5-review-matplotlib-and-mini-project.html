Data visualisation

Choosing a chart from the question

Thursday's page ended with the desk's tickets in a pandas DataFrame and a count of tickets per status printed as a small table. A table answers a question if the reader is willing to read every row. A chart answers it at a glance, which is why teams draw them, and the first decision is what to draw.

What a chart is for

Data visualisation means turning numbers into marks (bars, lines, dots) so that one comparison or one trend can be seen at once. The Matplotlib quick start guide builds its examples from the same few parts every time: the marks themselves, a title, and two labelled axes.1

In practice a chart carries one message, its title states that message, and each axis names what it measures and in what unit.1 "Tickets per status" with an x-axis called Status and a y-axis called Tickets passes. A chart titled "Figure 1" with bare axes makes the reader guess which number is which.

Which chart answers which question

A bar chart compares one value across discrete categories, and a histogram shows how a single numeric variable is distributed.2 A scatter plot shows the relationship between two numeric variables, and each point on it is one observation.3 A line chart joins its points in order, which tells the reader that something continuous happens between them, so it suits ordered data such as time and misleads when the points are unrelated categories.1

The data usually tells you which row you are in. Here is the status column of the desk's six tickets, counted the way Thursday's code counts it:

import pandas as pd

df = pd.DataFrame({"status": ["closed", "closed", "closed",
                              "assigned", "assigned", "open"]})
counts = df["status"].value_counts()
print(counts)

It prints four lines of table: closed 3, assigned 2, open 1, then Name: count, dtype: int64. value_counts() counts how often each distinct value occurs and returns a Series indexed by those values.4

The index holds the categories and the values hold the counts, which is exactly what a bar chart needs: one bar per label, each bar as long as its count. The three statuses have no order or distance between them, so this is a comparison across categories, and a line joining "closed" to "assigned" would claim a continuity that does not exist.

Axes that start at zero, and other ways a chart misleads

Bars encode their value by length, so a value axis that does not start at zero exaggerates every difference between them.1

Suppose two teams close 96 and 98 percent of their tickets inside the SLA. On an axis from 0 to 100 the two bars are nearly the same height, which is the truth. On an axis that starts at 95, the first bar is 1 unit tall and the second is 3, so the chart shows one team doing three times better when the real gap is two points.

The other faults to look for are:

  • a line drawn across unrelated categories,
  • an axis with no name or unit,
  • a chart with two kinds of mark and no legend to say which is which, and
  • two messages squeezed into one figure so that neither lands.

Reviewing a colleague's chart works much like reviewing their code. Read the title and ask whether the chart actually shows that. Check that a bar chart's value axis starts at zero. Check both axes have names and units. Check there is a legend whenever more than one kind of mark is drawn.

Charts in code that runs unattended

A chart made by a program has a second audience besides people: the program's next run. A chart that has to be reproduced by a scheduled job, a pipeline or a test is saved to a file rather than shown on screen, because showing it needs someone to look at a window and close it.5 The next two steps build the desk's charts that way.

You will also meet a shortcut in other people's notebooks. pandas offers plotting straight from a Series or a DataFrame through a .plot method, built on top of Matplotlib,6 so a line such as df.plot(kind="bar") is the same library reached in one call. It is quick for exploring, but the desk's code calls Matplotlib directly instead, because a chart function that makes its own figure, labels it and saves it is easier to read in review and easier to test.

Takeaways
  • A chart carries one message, and its axes name what they measure.
  • Bars compare categories, lines show order, histograms show spread, scatter plots show relationships.
  • A bar chart's value axis starts at zero.
Say it in an interview

I start from the question. Comparing categories is a bar chart, because lengths are easy to compare; change over time is a line, because a line implies order; the spread of one number is a histogram; and two numbers against each other is a scatter plot.

A bar's length is its value, so if the axis starts at ninety-five a two-point gap looks enormous. When I review a chart I check that the title states one message, both axes are labelled with units, bars start at zero, and there's a legend if there's more than one kind of mark.

Matplotlib

Matplotlib: a figure, an axes and a bar chart

Matplotlib is the plotting library that pandas' .plot is built on, and it joins the desk the same way pandas did: on a branch of its own, installed with pip, and pinned.

Installing Matplotlib and pinning it

Matplotlib is a third-party package, so it goes into the project's virtual environment with pip and gets a line in requirements.txt. Pinning means writing the exact version, matplotlib==3.11.2, so every machine that installs from the file gets the same release.7

git switch -c feature/desk-charts
python -m pip install matplotlib==3.11.2

The install collects a handful of packages Matplotlib depends on, such as fonttools and pillow, reports NumPy as already satisfied because the desk has had it since Wednesday, and ends with a "Successfully installed" line that names matplotlib-3.11.2. Then matplotlib==3.11.2 goes on a new line of requirements.txt under the pandas pin. Without the pin, a teammate installing next month could get a different release from the one the code was written and tested against.7

Figure and Axes

Two objects do nearly all the work. plt.subplots() returns a pair: a Figure and an Axes. The Figure is the whole canvas, the thing that ends up in an image file. The Axes is one plot area drawn on that canvas, with its own x-axis, y-axis, title and marks.1 The name trips people up: an Axes, singular despite the final s, is a whole plot, not one axis line. The figsize argument sets the figure's size in inches, width first.8

import matplotlib.pyplot as plt

fig, ax = plt.subplots(figsize=(6, 4))
print(type(fig).__name__, type(ax).__name__)
plt.close(fig)

This prints Figure Axes. import matplotlib.pyplot as plt is the alias every codebase uses, so plt. in a file is the first sign of Matplotlib. The split of jobs is worth memorising: methods on the Axes draw and label (ax.bar, ax.set_title), and methods on the Figure deal with the canvas as a whole (fig.tight_layout, fig.savefig).

Tickets per status, drawn from the DataFrame

The desk's chart code lives in a new module, chart.py, next to Thursday's frame.py. It imports status_table from frame, so the chart is drawn from exactly the numbers the status table prints.

"""Draw charts of the desk's tickets with Matplotlib."""
import matplotlib.pyplot as plt

from frame import status_table


def status_chart(df, path):
    """Save a bar chart of tickets per status to path."""
    counts = status_table(df)
    fig, ax = plt.subplots(figsize=(6, 4))
    ax.bar(counts.index, counts.values)
    ax.set_title("Tickets per status")
    ax.set_xlabel("Status")
    ax.set_ylabel("Tickets")
    fig.tight_layout()
    fig.savefig(path)
    plt.close(fig)

Read it from the top. counts is the value_counts() Series from the first section. ax.bar(x, height) draws one bar per category, and passing counts.index as the x values and counts.values as the heights puts each status under a bar as tall as its count.9 set_title, set_xlabel and set_ylabel label the chart.9 fig.tight_layout() adjusts the padding so the title and labels are not clipped at the edges.10 fig.savefig(path) writes the figure to a file and picks the format from the extension, so status.png gives a PNG.11 plt.close(fig) releases the figure.12

main() in ticket_desk.py gains one line, status_chart(df, "status.png").

Running python ticket_desk.py prints the same log lines and tables as Thursday and leaves status.png in the folder:

  • a 600 by 400 pixel bar chart titled "Tickets per status",
  • with bars of 3, 2 and 1 for closed, assigned and open, and
  • the value axis starting at 0.

savefig also takes a dpi argument when a sharper PNG is wanted.11 The check that matters is to open the image next to the printed status table and confirm the bars show the same three numbers.

Two interfaces: explicit and pyplot

Matplotlib documents two ways to write the same chart. The explicit, object-oriented interface creates the figure and axes and calls methods on them, as status_chart does. The implicit pyplot interface calls functions such as plt.bar, which act on whichever axes pyplot currently treats as "current". The quick start guide recommends the explicit form for anything beyond a quick sketch.1

import matplotlib.pyplot as plt

plt.figure()
plt.bar(["closed", "assigned", "open"], [3, 2, 1])
plt.title("Tickets per status")
plt.show()

This is the older style you find in tutorials and notebooks, and it draws the same three bars in a window. It reads well for one chart. In a program that draws two, every plt. call lands on the current axes, so a function that forgets to start its own figure draws on top of the previous chart. With fig and ax in hand, each line names the plot it changes, which a reviewer can check without running the code.

plt.show() and the window that waits

plt.show() opens a window and blocks until that window is closed.5 While exploring at your own machine, that is how you look at a chart. In a script, the line after it does not run until someone closes the window, and in a test, a scheduled job or a remote shell nobody will, so the run hangs. savefig works anywhere, with or without a display.5 That is why status_chart saves and closes, and has no show at all.

Takeaways
  • A Figure is the whole canvas and an Axes is one plot area on it.
  • The explicit interface names the figure and axes that each line changes.
  • Unattended code saves and closes the figure, because plt.show() blocks.
Say it in an interview

A Figure is the whole canvas, the thing that gets saved to a file. An Axes is one plot area on it, with its own axes, title and marks. plt.subplots gives me both; I draw and label with methods on the axes and save with savefig on the figure.

The pyplot style calls plt functions that act on whatever axes is current. The object-oriented style names the figure and axes. I use the explicit one in real code, because when a program draws two charts I always know which plot each line changes.

Matplotlib

A second chart, saving it and testing it

One chart answers one question. The desk's second question is about time: did each closed ticket finish inside the SLA for its own priority? That needs a second chart, and a second chart needs a figure of its own.

Each chart gets its own figure

Every call to plt.subplots() creates a new, separate figure, so two chart functions should each create their own.8 hours_chart starts with its own fig, ax = plt.subplots(figsize=(6, 4)) and never borrows status_chart's. Skip that call and draw with plt.bar on the "current" axes instead, and the second chart's marks can land on the first chart's figure, leaving one image with both charts piled on top of each other.

Ending each function with plt.close(fig) matters for the same reason. pyplot keeps every open figure in memory, and opening many without closing them raises a warning.12 A desk that redrew its charts every hour for a month would otherwise hold hundreds of figures it no longer needs.

Marking each ticket's own SLA

chart.py gains one import at the top, next to the pyplot import, and this function below status_chart:

from desk import SLA_HOURS


def hours_chart(df, path):
    """Save each closed ticket's hours against its own SLA to path."""
    closed = df[df["hours"].notna()]
    labels = "TD-" + closed["ticket_id"].astype(str)
    fig, ax = plt.subplots(figsize=(6, 4))
    ax.bar(labels, closed["hours"], label="hours to resolve")
    ax.scatter(labels, closed["priority"].map(SLA_HOURS), marker="_", s=600,
               color="black", label="SLA for its priority")
    ax.set_title("Resolution hours against each ticket's SLA")
    ax.set_xlabel("Ticket")
    ax.set_ylabel("Hours")
    ax.legend()
    fig.tight_layout()
    fig.savefig(path)
    plt.close(fig)

df["hours"].notna() gives a boolean mask that is True wherever hours has a value, and indexing the DataFrame with it keeps only those rows.13 Open and assigned tickets have no closing time, so their hours are missing and they drop out, leaving the three closed tickets. The next line turns ids 1, 2 and 3 into the labels TD-1, TD-2 and TD-3, and the prefix is needed.

When every x label is a string that parses as a number, such as "1", Matplotlib still draws them as categories but logs an INFO message suggesting you convert them to numbers.1415 The desk configures logging at INFO, so that message would print on every run; a label such as "TD-1" does not trigger it.15

The comparison itself is one call. Series.map(dict) replaces each value with the dict's entry for it, and gives NaN for a value that is not a key.16

import pandas as pd

SLA_HOURS = {"high": 4, "normal": 24, "low": 72}
priority = pd.Series(["high", "normal", "normal", "urgent"])
print(priority.map(SLA_HOURS))

This prints 4.0, 24.0, 24.0 and NaN, with dtype: float64: "urgent" is not a key, so it maps to a missing value, and the column becomes floats to hold it. In hours_chart every closed ticket's priority is a key, so each bar gets its own ticket's limit, the same comparison Wednesday's breached() makes with an array.

ax.scatter draws a marker at each point, and a "_" marker with a large s renders as a short horizontal mark across the column, a reference line per bar.3 Both drawing calls pass label=, and ax.legend() builds the legend from those labels.17

The saved hours.png shows TD-1 at 1.5 hours under a mark at 4, TD-2 at 54.75 against 24, and TD-3 at 23 against 24. Only TD-2 rises past its mark, and summary() reports 'breached': 1 for the same tickets. When a chart and a number computed by separate code agree, both are probably right.

Saving, closing and ignoring the image

Save last. savefig writes the figure as it stands at that line, so a call placed above set_title produces an image with no title.11 Then close. Then decide what Git should do with the file. status.png and hours.png are rebuilt on every run, which makes them build outputs, and generated files belong in .gitignore rather than in version control.18 A committed image shows as modified after every run and fills reviews with binary diffs nobody can read.

git status
git add chart.py requirements.txt ticket_desk.py .gitignore
git commit -m "Chart tickets per status with Matplotlib"

Before the pattern *.png goes into .gitignore, git status lists both chart.py and status.png as untracked. After it, only chart.py is left, and the commit stages exactly the four files that changed.

Testing code that writes a file

Checking a chart's pixels with an assert is fragile, but a chart function has a contract that can be tested: given a path, it writes a file there, and the file is not empty. pytest's built-in tmp_path fixture gives each test a fresh temporary directory as a pathlib.Path, so the test never writes into the project.19 A fixture is requested by naming it as a test parameter, which is also how Wednesday's sample_desk arrives.20

def test_charts_write_png(tmp_path, sample_desk):
    """Both charts write a PNG file that is not empty."""
    save_desk(sample_desk, tmp_path / "tickets.json")
    df = load_frame(tmp_path / "tickets.json")
    status_chart(df, tmp_path / "status.png")
    hours_chart(df, tmp_path / "hours.png")
    for name in ["status.png", "hours.png"]:
        assert (tmp_path / name).exists()
        assert (tmp_path / name).stat().st_size > 0

Path.stat().st_size is the file's size in bytes, so > 0 proves the file is not empty.21 With this test added, pytest collects 19 items and all 19 pass. The test has a limit: it proves both functions run from a saved JSON file all the way to an image, and says nothing about whether the bars are the right height. The comparison with the printed numbers stays a job for a person, done once when the chart is written.

The branch then ends like every branch this week: committed, merged into main and pushed. git log --oneline -- . lists only the commits that touched files under the current directory.22 So run inside ticket-desk/ it shows the desk's nineteen commits for the week, from "Restart the ticket desk with the math module" at the bottom to the two chart commits on top.

Takeaways
  • Each chart function makes its own figure and closes it after saving.
  • Series.map(dict) gives NaN for a value that is not a key.
  • Generated images belong in .gitignore, and a test can check that the file exists and is not empty.
Say it in an interview

I call plt.close on the figure after saving because pyplot keeps every open figure in memory. In a long-running program that redraws charts on a schedule, unclosed figures pile up, Matplotlib starts warning, and memory keeps growing.

I test a chart function by handing it pytest's tmp_path, calling it, and asserting the file exists and its size is above zero. That doesn't prove the bars are right, so I compare the image with the numbers once by eye, but it catches a function that crashes or writes nothing.

Modules and the __main__ guard

A module is a .py file. import loads a module the first time it is imported and binds its name in the importing file, and a later import of the same module reuses the one already loaded.23 from desk import SLA_HOURS binds a single name from it instead. A file that only defines functions can be imported by another without running its if __name__ == "__main__": block, because that block runs only when the file is the program being run.23

"""board.py: format one ticket as a line of the board."""


def board_line(ticket_id, title, status):
    """Return one tab-separated line for the board."""
    return f"{ticket_id}\t{title}\t{status}"


if __name__ == "__main__":
    print(board_line(1, "Login page returns 500", "closed"))

python board.py prints 1, Login page returns 500 and closed separated by tabs. Another file that runs import board prints nothing and can call board.board_line(...). That is why a test file can import every module of the desk without starting the desk.

The desk splits by reason to change.

  • desk.py holds the model and its rules,
  • storage.py saving and loading,
  • stats.py the numbers,
  • report.py the text output,
  • frame.py the DataFrame and
  • chart.py the images.

ticket_desk.py is a thin script that wires them together, and test_desk.py holds the tests. The split has a cost: more files, more imports to keep straight, and a direction to respect, since chart.py imports from frame.py and never the other way round.

You recognise a well-split Python project by short imports at the top of each file and a guard at the foot of the one file meant to be run.

Exceptions: catching the one you expect

A function that cannot do its job raises an exception with a message, and the caller decides what to do. try/except catches a named exception class, and catching a specific class is preferred over a bare except, which would also swallow mistakes nobody expected.24

def sla_for(priority):
    hours = {"high": 4, "normal": 24, "low": 72}
    if priority not in hours:
        raise ValueError(f"unknown priority: {priority!r}")
    return hours[priority]


try:
    sla_for("urgent")
except ValueError as err:
    print("rejected ticket:", err)

This prints rejected ticket: unknown priority: 'urgent'. The desk does the same at intake: an unknown priority raises ValueError, the script catches it, logs the rejection and carries on with the next ticket.24 Had the except been bare, a typo such as a misspelled variable name inside sla_for would have been caught too and reported as a rejected ticket, hiding the real bug.

Files that may not be there

Tuesday's storage code reads the tickets file, and that file does not exist the first time the desk runs. The with block from Tuesday opens the file, and json.load parses it into dicts and lists.25

import json


def load_tickets(path):
    try:
        with open(path, encoding="utf-8") as f:
            return json.load(f)
    except FileNotFoundError:
        return []


print(load_tickets("missing.json"))

With no missing.json in the folder this prints []. Returning an empty list is a decision, and it has a limit: it is right on a first run and wrong when a typo in the path quietly gives an empty desk.

A malformed file is a different error, json.JSONDecodeError, and the desk deliberately does not hide that one.25 It raises a clear error instead, because starting empty would throw a day's tickets away at the next save. In other people's code, try: around a json.load with an except FileNotFoundError: under it is this pattern.

Abstract classes: a base that only its subclasses can build

The desk will one day tell people about their tickets, by email or by chat. Both channels keep the same state, a name and a count of messages sent, and both must offer a send method; only the delivery differs. Python writes that contract with abc.ABC and @abstractmethod: a class that derives from ABC is an abstract base class, and a method marked abstract has to be implemented by a subclass before any object can be built.31

from abc import ABC, abstractmethod


class Channel(ABC):
    """A way of telling someone about a ticket."""

    def __init__(self, name):
        self.name = name
        self.sent = 0

    @abstractmethod
    def send(self, ticket_id, text):
        """Deliver one message about a ticket."""

    def notify(self, ticket_id, text):
        self.send(ticket_id, text)
        self.sent += 1


class EmailChannel(Channel):
    def send(self, ticket_id, text):
        print(f"[email via {self.name}] TD-{ticket_id}: {text}")


class ChatChannel(Channel):
    def send(self, ticket_id, text):
        print(f"[chat #{self.name}] TD-{ticket_id}: {text}")


for channel in (EmailChannel("support@desk"), ChatChannel("tickets")):
    channel.notify(7, "status is now closed")
    print(channel.name, "sent", channel.sent)

try:
    Channel("base")
except TypeError as err:
    print("TypeError:", err)
[email via support@desk] TD-7: status is now closed
support@desk sent 1
[chat #tickets] TD-7: status is now closed
tickets sent 1
TypeError: Can't instantiate abstract class Channel without an implementation for abstract method 'send'

The shared __init__ and notify live once, in the base, and each subclass writes only its own send. Channel("base") raises TypeError because the class still has an abstract method, and the message names the method that is missing.31 A subclass that forgets send fails the same way, at construction, long before the first ticket is notified.

Without the base class Python would still accept any object that happens to have a send method. That is duck typing, and it works until someone passes a channel without the method and the failure turns up mid-run. A team reaches for the abstract class when several classes share state and a required method, so the expectation is written in code and checked early. An abstract method may carry a body, which a subclass can call through super().31

map, filter and reduce beside the comprehension

Thursday's page built new lists with a loop and with a comprehension. Three built-in functions do the same jobs in a functional style. map(function, items) applies a function to every item and filter(function, items) keeps the items the function is true for; both return an iterator, so nothing is computed until something consumes it, and printing one shows only an object.3233 functools.reduce(function, items, initial) folds the items into one value, calling the function with the running total and the next item, left to right.34

from functools import reduce

hours = [1.5, 54.75, 23.0, 30.25]

over_24 = filter(lambda h: h > 24, hours)
print(over_24)
print(list(map(lambda h: h - 24, hours)))
print(list(over_24))
print(reduce(lambda total, h: total + h, hours, 0))

print([h - 24 for h in hours])
print([h for h in hours if h > 24])
print(sum(hours))

The last three lines are the same transformations as comprehensions, plus sum, which already folds a list of numbers. The comprehension carries its condition and its expression in one readable line, and the filter call is documented as equivalent to the generator form of it.33 Which is faster is a question to measure, and timeit is the standard library's tool for that: it runs a statement a given number of times and returns the total seconds.35

import timeit

setup = "hours = list(range(10_000))"
runs = 1000
for label, stmt in [
    ("map + lambda", "list(map(lambda h: h - 24, hours))"),
    ("comprehension", "[h - 24 for h in hours]"),
    ("map + str", "list(map(str, hours))"),
    ("comprehension", "[str(h) for h in hours]"),
]:
    seconds = timeit.timeit(stmt, setup=setup, number=runs)
    print(f"{label:<14}{seconds:.2f} s")
map + lambda  0.91 s
comprehension 0.30 s
map + str     0.76 s
comprehension 0.80 s

Those numbers come from one machine and one run; yours will differ. With a lambda, map is about three times slower, because every item costs a Python function call that the comprehension does inline. With a builtin such as str the two are level. So a team writes the comprehension by default, keeps map for a builtin applied to a stream, and uses reduce when the answer is one value that no builtin such as sum or max already gives.34

Recursion: a function that calls itself

A recursive function solves a problem by calling itself on a smaller piece of it. It needs a base case, an input small enough to answer without another call, and a recursive case that shrinks the input towards the base. The desk's hours sometimes arrive as a list holding lists of sub-task hours, and nested data like that is where recursion fits.

import sys


def total_hours(items):
    """Sum hours from a list that may hold lists of sub-task hours."""
    if not items:
        return 0
    first, rest = items[0], items[1:]
    if isinstance(first, list):
        return total_hours(first) + total_hours(rest)
    return first + total_hours(rest)


print(total_hours([1.5, [2.0, 0.5], 23.0]))


def count_down(n):
    if n == 0:
        return 0
    return 1 + count_down(n - 1)


print(sys.getrecursionlimit())
print(count_down(500))
try:
    count_down(5000)
except RecursionError as err:
    print("RecursionError:", err)
27.0
1000
500
RecursionError: maximum recursion depth exceeded

Each call waits for the next one to return, so every unfinished call keeps a frame on the call stack, and the stack is deepest just before the base case answers. Python caps that depth: sys.getrecursionlimit() returns the cap, 1000 under the course Python, and going past it raises RecursionError.3637 count_down(500) fits under it; count_down(5000) does not, and the error carries the message shown.

The limit decides between a loop and recursion. Anything you can walk from start to end, counting down or summing a flat list, is a loop's job, with no stack to run out. Recursion fits data that nests to a modest depth, such as a nested list or a folder tree. In an interview, name the base case first, then the smaller call, then the limit.

Takeaways
  • The desk is split into modules by reason to change.
  • Catch the specific exception you expect, never a bare except.
  • A missing file can mean an empty desk, but a malformed file should raise.
Say it in an interview

I split a program by reason to change: the model and its rules in one module, storage in another, reporting in another, and a thin script on top with an if-name-equals-main guard, so every module can be imported and tested without running the program.

For a missing file I catch FileNotFoundError specifically and decide whether starting empty is right. A malformed file raises a JSON decode error, and I surface that with a clear message rather than hide it. Each case gets its own test with a temporary folder.

When several classes share state and must each offer the same method, I write an abstract base class with the shared init and the abstract method, and each subclass fills in its own version. Building the base, or a subclass that forgot the method, raises a TypeError at construction, so a missing method shows up before the first call.

Review, part 2: JSON, tests and arrays

Tuesday made the desk's data outlive the program. Wednesday made its rules provable and its resolution hours a single array. These three are where an interviewer's follow-up questions about "your project" tend to land.

JSON as the desk's file format

json.dump writes Python dicts and lists to a file as JSON, and json.load parses a file object back into dicts and lists.25

import json

tickets = [{"ticket_id": 1, "priority": "high", "status": "closed"}]
with open("tickets.json", "w", encoding="utf-8") as f:
    json.dump(tickets, f)
with open("tickets.json", encoding="utf-8") as f:
    loaded = json.load(f)
print(loaded == tickets, type(loaded[0]).__name__)

This prints True dict, and tickets.json holds one line that any text editor, and any other language, can read. That readability is why the desk saves to JSON. The limit is that the whole file is read and rewritten on every save, and a damaged file fails to parse at all, raising json.JSONDecodeError.25 Week 3 moves the tickets into a database. In other code, a with open(...) followed by json.load(f) is this format being read, and a "w" mode with json.dump is it being written.

pytest: discovery, assert and fixtures

pytest discovers files named test_*.py and functions named test_* inside them, and a bare assert is enough, because when one fails pytest reports the values that made it fail.26 A fixture is a function that prepares something a test needs, such as sample tickets, and a test asks for it by naming it as a parameter.20 tmp_path is the built-in fixture behind every file test this week.19

def over_sla(hours, limit):
    return hours >= limit


def test_over_sla_is_strict():
    assert over_sla(24.5, 24)
    assert not over_sla(24, 24)

Saved as test_rules.py and run with pytest, this fails on purpose. pytest marks the second assert with > and explains it as assert not True, where True = over_sla(24, 24), then ends with 1 failed. The rule says a ticket is over its SLA only when it took longer than the limit, so >= is the bug, and changing it to > turns the run green. That is the habit the desk's tests follow: one rule, a case on each side of the line, and an assert that reads like the rule.

The desk's nineteen tests cover the deadline rules, unknown priorities, saving and loading with tmp_path, corrupt JSON, the hours array and its breach mask, the per-status counts and both image files. In a test file you recognise the style by def test_x(tmp_path, sample_desk): signatures and a fixture function marked @pytest.fixture near the top.20

A loop, a comprehension and an array

Every list this week was built the long way: an empty list, a for loop and append. A list comprehension is the shorter form of exactly that loop, written inside square brackets.27 Teams write the comprehension for a simple transformation and keep the loop when the body needs more than one expression. A NumPy array goes a step further: it holds items of one dtype and supports whole-array arithmetic with no Python loop at all.28

import numpy as np

hours = [1.5, 54.75, 23.0]
over = []
for h in hours:
    over.append(h - 24)
print(over)
print([h - 24 for h in hours])
arr = np.array(hours)
print(arr - 24)
print(arr.dtype)

The first two lines both print [-22.5, 30.75, -1.0]: the loop and the comprehension build the same list. The third prints [-22.5 30.75 -1. ], NumPy's own layout with no commas, and the last prints float64.28 The trade-off is what each container may hold. A list holds anything, mixed types and None included. An array holds one dtype, which is what lets arr - 24 work on every element at once, and it cannot carry a ticket's title next to its hours.

Takeaways
  • json.dump writes dicts and lists to a file, and json.load reads them back.
  • A bare assert is enough in pytest, and a fixture is requested by naming it as a parameter.
  • A list holds anything, while a NumPy array holds one dtype and supports whole-array arithmetic.
Say it in an interview

pytest finds files and functions whose names start with test, and a plain assert is enough because pytest shows me the values when it fails. Anything a test needs, like sample tickets or a temporary folder, comes in as a fixture that I name as a parameter.

A list holds references to anything, and I build it with a loop and append or with a comprehension. A NumPy array holds one numeric type, so I can subtract twenty-four from every element in one expression, without a loop.

Review, part 3: DataFrames, and how a team reviews a codebase

Thursday's DataFrame is the last data structure of the fortnight. After it comes the question every team asks of a finished branch, and the mini-project is marked the same way.

The DataFrame as the week's last data structure

A pandas DataFrame is a two-dimensional labelled table: named columns, each holding values of one type, and a labelled index down the side. groupby followed by an aggregation such as mean summarises the table by the values of one column.29

import pandas as pd

df = pd.DataFrame({
    "priority": ["high", "normal", "normal", "normal", "high", "low"],
    "hours": [1.5, 54.75, 23.0, None, None, None],
})
print(df.groupby("priority")["hours"].mean())

It prints high 1.500, low NaN and normal 38.875, then Name: hours, dtype: float64. The 38.875 is the average of the two closed normal tickets, 54.75 and 23.0. The one low ticket is still open, so there is no number to average and its row shows NaN. A Counter could already count statuses, and Thursday's test proved value_counts() gives the same numbers. The DataFrame earns its dependency when a question involves several columns at once: hours, grouped by priority, closed tickets only.29

List, array or DataFrame column

The three containers answer one interview question between them.

  • A list suits items that are mixed or that arrive one at a time, such as the desk's queue of Ticket objects.
  • A NumPy array suits one column of numbers that you do arithmetic over as a whole, such as Wednesday's resolution hours and its breach mask.28
  • A DataFrame column suits numbers that belong to rows with other columns you want to group or filter by, such as hours next to priority and status.

Like an array, a column holds values of one type, and it carries a label and the table's index with it.29 Each step up gives more operations and costs another package and a conversion, which is why the desk still keeps its tickets in a list and builds the array and the frame only where a question needs them.

Reading a codebase the way a reviewer does

Before reading any line closely, a reviewer looking at a finished branch asks four things. Are the tests green? Is the linter clean, or does every remaining message have a reason? Are the commits small, with summaries that say what changed? Is the branch merged, with main pushed? The desk's last commands answer each one:

pytest
pylint desk.py storage.py stats.py report.py frame.py chart.py ticket_desk.py test_desk.py
git log --oneline -- .

A linter reads source code without running it and reports style problems and likely mistakes. Its messages are advice, and the team decides what to do with each.

Two messages from the desk show both outcomes. R1705, no-else-return, fires on an else that follows a block ending in return; the fix is to delete the else: and de-indent its body, which leaves behaviour unchanged.30 In a try/except/else whose except returns. Pylint raises it on the try's else:, which is where it found storage.py's delete_file.30

W0621, redefined-outer-name, fires nine times in test_desk.py, once for every test whose parameter shares the name of the sample_desk fixture. pytest requests fixtures by exactly that pattern, so the desk names the message and leaves it.20 Fixing every message blindly would break the tests, and ignoring every message would leave real problems in.

The history is the last check. git log --oneline -- . lists the commits that touched the current directory,22 and nineteen imperative summaries such as "Split the desk model into its own module" and "Raise a clear error for corrupt JSON" read as the fortnight's changelog.

The mini-project and its rubric

The mini-project is a small ticket-report codebase in your own learner repo, marked against a rubric instead of a set of starter tests. The rubric asks for the same things a reviewer asked of the desk:

  • code split into modules,
  • a JSON file loaded with its errors handled,
  • pytest tests that pass,
  • a NumPy array,
  • a pandas DataFrame,
  • a chart saved to a file, and
  • a pylint run that is clean or whose remaining messages are named.

Order matters more than polish, so start with the spine: a module that loads the JSON file, and one test that proves it loads and one that proves a missing file is handled. Add the array, then the frame, then the picture. A project that starts with the picture often ends with no tests, a failing pylint run or an unmerged branch, and the rubric marks all three.

Takeaways
  • Choose a list, an array or a DataFrame column by what the data is for.

Say it in an interview

A list holds anything and grows an item at a time. A NumPy array is one numeric type, with arithmetic over the whole thing at once. A DataFrame column is like an array with a label and an index, and it sits in a table, so I can group and filter it by the other columns.

When I review a branch I check the tests are green, the linter is clean or each remaining message has a reason, the commits are small with clear summaries, and it's merged and pushed. Check yourself

Check yourself

Nine retrieval questions, at least one per section. Answer each out loud before you open it.

A manager wants to see how many tickets were opened each day this month. Which chart do you draw, and why not join the status bars with a line?

A line chart, because the days are ordered and a line implies something continuous between points. Statuses have no order, so a line joining "closed" to "assigned" would claim a continuity that does not exist; they get bars.

A colleague's bar chart compares 96 and 98 percent on an axis that starts at 95. What is wrong with it?

Bars encode value by length, so the truncated axis makes the second bar three times as tall as the first for a two-point gap. A bar chart's value axis starts at zero.

What is the difference between a Figure and an Axes, and which one do you call savefig on?

The Figure is the whole canvas that ends up in the image file; an Axes is one plot area on it, with its own axes, title and marks. You draw and label on the Axes and call savefig on the Figure.

A chart script works when you run it by hand but hangs under pytest. What is the likely cause?

A plt.show() call. It opens a window and blocks until the window is closed, and an unattended run has nobody to close it. Save with fig.savefig and close the figure instead.

Why does hours_chart call plt.subplots() itself and end with plt.close(fig)?

Each call to plt.subplots() makes a separate figure, so the second chart cannot land on the first chart's image. Closing releases the figure, because pyplot keeps every open figure in memory and warns when too many pile up.

What does test_charts_write_png prove, and what does it not prove?

It proves both chart functions run from a saved JSON file through the DataFrame and write a non-empty PNG into tmp_path. It does not prove the bars have the right heights; that is checked once by eye against the printed numbers.

Why does a module that only defines functions put its demo code under if __name__ == "__main__":, and why catch FileNotFoundError instead of using a bare except?

The guarded block runs only when the file is the program, so other modules and tests can import it without side effects. A specific exception class catches only the case you planned for; a bare except would also hide real bugs.

hours = [1.5, 54.75, 23.0]. Give two ways to subtract 24 from every value without NumPy, and say what np.array(hours) - 24 adds.

A for loop that appends to a new list, or the comprehension [h - 24 for h in hours]. The array holds one dtype, float64 here, and does the subtraction on every element in one expression with no Python loop.

pylint reports R1705 in storage.py and W0621 nine times in test_desk.py. Which do you fix, which do you leave, and why?

Fix R1705 by deleting the unnecessary else: after a return and de-indenting its body, which leaves behaviour unchanged. Leave W0621 and name it, because pytest passes fixtures by giving a test parameter the fixture's name, which is exactly what the message complains about.

A colleague rewrites [h - 24 for h in hours] as list(map(lambda h: h - 24, hours)) for speed. What do you say?

Measure it with timeit first. With a lambda, map pays a Python function call per item and ran about three times slower than the comprehension on one machine; with a builtin such as str the two are level. Both map and filter return lazy iterators, which is why the list() is there. The comprehension reads better, so it stays, and reduce is kept for folding items to one value.
