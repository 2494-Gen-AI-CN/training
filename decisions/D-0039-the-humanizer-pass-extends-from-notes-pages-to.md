- Date: 2026-10-12
- Status: accepted
- Decision: The humanizer pass extends from notes pages to the trainer's delivery wording (amends D-0029, which stands): in day-fanout.js one humanize agent rewords the day's demo scripts after the demo author and one rewords the runbook after the runbook author, both before their critics and on the existing humanize tier; they change prose only (talking points, instruction sentences, questions and answers, logistics sentences) and harness/prose_guard.py proves it by comparing each file with a snapshot taken before the pass (fenced blocks, inline code, headings, script header bullets, cwd lines, table shape, bold labels, URLs and bullet counts must be identical); no critic item is added, so the bar does not move; the What we did NOT cover bullets of a demo script take one format, topic then a colon then where it goes then the reason as its own sentence, set in the demo-script template and checked by demo_check.py
- Why: The trainer reads these files aloud while typing in front of the room; machine-sounding wording has to be reworded live, which is clunky. The first hand-run pass (2026-10-12, 18 files) showed the authors already write plainly, that the useful edits are split run-ons and semicolon chains, and that a humanizer applied by rule flattens good spoken contrasts, so the baked-in prompt keeps real contrasts and the guard keeps the demos' end state fixed. Three agents had left the not-covered bullets in three different shapes, hence one format.
