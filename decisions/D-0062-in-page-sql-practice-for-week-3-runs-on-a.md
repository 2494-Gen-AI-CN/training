- Decision: In-page SQL practice for week 3 runs on a vendored sql.js 1.15.0 (SQLite 3.54.0, first-party under docs/assets/vendor/sqljs/) behind a MySQL-shaped terminal widget (ix-sql: mysql> prompt, MySQL result boxes and error codes, SHOW/DESCRIBE, dialect rewrites, IN-parameter procedures) with declarative JSON checks that the same wasm runs under node for the contract tests; Pyodide ix-task stays for the Python-desk tasks; staged plan in docs/process/sql-in-page-plan.md
- Why: Learners need no MySQL server to practise SQL in the page. Verified 2026-10-17 under node: Pyodide 314.0.7 core does ship sqlite3 (SQLite 3.39.0; the practice critic's runtime line saying otherwise is stale), but a SQL-only Monday page would boot ~10 MB of Pyodide for it, CPython 3.15 here bundles SQLite 3.53.4 so contract tests pass CONCAT and similar that fail in the browser, and SQL wrapped in Python strings hides the client the week teaches. sql.js 1.15.0 is 685 KB of wasm, vendored so the site keeps its two pinned external origins, runs the identical engine under node for tests (no skew), has CONCAT and RIGHT JOIN natively, and lets JS dress the output as the mysql client the room uses (D-0059). What SQLite cannot fake (isolation levels, concurrency, EXPLAIN format, procedures with control flow) stays with predict and spot widgets and an honest partial verdict.
