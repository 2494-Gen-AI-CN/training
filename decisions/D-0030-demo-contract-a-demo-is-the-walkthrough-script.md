## Notes

The demo contract, in full (catalog rows in parentheses; `docs/process/mined-rules-catalog.md`).

**What a demo is (A1, A3).** A demo is a walkthrough script the trainer performs in front of the room; the committed code is the end-state answer key and never a substitute for performing it. Per subtopic the CONSULT-vs-WRITE test decides: if the objective is fluency (code, commands, git, SDK calls) the typing is the lesson and the subtopic gets a script with Delivery mode `typed`; material learners will look up later may be `lecture-over-file` (rare); a concept subtopic (SDLC, Scrum, story points, professionalism, MLOps concepts) gets no script and is facilitated from the runbook.

**Script format (A28 header, A2 body).** `trainer/<rel>/demos/NN_<slug>.md`, template `harness/templates/demo-script.md`. Header bullets: Objective, Time, Before the room arrives, Delivery mode, Audience, Prerequisite reading, Answer key, Hand-typed files, Tool-generated files. Body: `## Step n — title (M min)` headings (≥2, minutes summing to Time, Time within `metrics.demos.minutesPerScriptMin..Max`), a `cwd:` line in every step that has a code or command block, the exact code/commands in fenced blocks (```python typed into a file, ```bash one command per line without prompts, ```text expected output), "Talking points while typing", then Common pitfalls (symptom + fix), What we did NOT cover (intentional), Wrap-up questions, Sequence pointer. The old `# --- STEP n ---` markers survive as the step headings (A30).

**Answer key (A5, A29, A30).** One per script, same NN and slug, under `trainer/<rel>/demos/key/`: `NN_<slug>.py` (runnable from `key/`, ≤ `metrics.demos.maxLinesPerFile` lines) or `NN_<slug>.md` for a terminal demo (a transcript: ```console blocks whose `$ ` lines are the commands and the other lines the real output), or `.ipynb` on `demoFormat: nb` days. Both-ways check: for a `.py` key every non-blank line of the script's ```python blocks is in the key and every key line is in some ```python block (a typed line later replaced goes in ```python transient); for a transcript the ```bash command sequence equals the transcript's `$ ` sequence in order. `harness/demo_check.py` runs the check; the demos critic and `tests/test_demos.py` call it. The critic still runs every key (A29) and the size caps stay (A30). `key/README.md` is the run-order table (template `demo-README.md`, reduced to that).

**Pre-flight (A17) as critic items.** Every token introduced before first use (walk as a learner); the first script of the day that uses a tool carries install + version + config commands proven by running; every step with a block states its cwd; every tool-generated claim proven by running the tool at the stamped version.

**Visibility (A21): trainer-only until taught.** Authors write only to `trainer/<rel>/demos/`. The public `demos/<rel>/` is written only by `harness/publish_demos.py <week> <day>`, which copies `key/` there and flips the notes page demo card from `data-demo="pending"` ("Published after class", no links) to `data-demo="published"` (links) only when the day carries `taught: "YYYY-MM-DD"` in `curriculum.json`. `taught` is set by the delivery-day close (codify plan Stage 4), never by an author or the Wire step. The Wire step runs the publish script (a no-op on authoring runs). `build_index.py` emits the index Demo chip only for taught days. Tests: a live untaught day must have no `demos/<rel>/`; a taught day's `demos/<rel>/` must mirror `key/`.

**Concept days (A22).** `demoFormat: none` marks a day with no code demo: `day-fanout.js` skips the Demos stage, the runbook carries one `## Facilitation N: <subtopic> (M min)` block per subtopic (Goal, numbered timed beats, ≥2 "Ask the room" questions with the steering answer, ≥1 misconception from the brief, what the room writes down), the notes page has no demo card, no "Demos today" list and no code popups. On ordinary days the same Facilitation blocks cover the concept subtopics that the CONSULT-vs-WRITE test left without a script; `## Demo N: NN_<slug>.md` sections point at the script (path, key, Time, room state, stop point, checkpoint questions, one pitfall) and carry no talk track of their own.

**Metrics.** `demos: scriptsMin 2, scriptsMax 5, minutesPerScriptMin 15, minutesPerScriptMax 45, maxLinesPerFile 90` (replaces `filesMin/filesMax`).

**Transition.** W1D2's existing demos (five print-style/subprocess `.py` files in the public `demos/`) do not satisfy the new tests; the day is `status: planned` until Stage 3 re-authors them under this contract, and its public demo folder is removed there.
