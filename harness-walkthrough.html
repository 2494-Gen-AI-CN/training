0Goal & context

Build a repeatable, agent-driven pipeline that turns each curriculum day into a complete, reviewed set of training materials. The harness is the deliverable right now. Content for the 55 training days comes out of running it.

Delivery context (ours)

  • In person or Zoom, live code-along demos are the core.
  • Site supports the demos: notes, examples, short quizzes, exercises.
  • No AI grading of trainee answers. No login, no progress sync, no backend.
  • Trainer keeps a private runbook and solutions per day.

Reference (2463-FDE site)

  • Fully remote, part-time, self-paced readings.
  • Cloudflare Worker backend: LLM proxy, AI-graded spoken summaries, interview question bank, progress sync, trainer dashboard.
  • Research-first authoring pipeline with critics and repass loops. This part we keep.
  • Static HTML + JS front end, zero build step. This part we fork.

4Per-day artifacts

Every curriculum day produces the same five things. Metrics are sized for an in-person day where demos carry the explanation and notes are a reference, not a self-paced reading.

a. Research brief harness/research/week-WW/day-N-slug.md

  • Header: title, gate level, verified date, version stamps per library.
  • Claims: full gate = every claim carries a fetched URL; light gate = 3–8 claims, sources optional.
  • Sources: at least 3 official-doc URLs either way.
  • Glossary terms (3–8), common pitfalls (3–6), demo plan hints (2–4). These feed the runbook, quiz distractors and the demo author.

b. Demo code demos/week-WW/day-N-slug/

  • 2–5 files, numbered in teaching order, each under roughly 90 lines. Top docstring states purpose and expected output.
  • # --- STEP n: what to type next --- comment checkpoints so the trainer can type along.
  • README with a run-order table: file, what it shows, run command, needs key?
  • Anything needing a key guards with an env check and exits cleanly. LLM provider from config.json: Anthropic SDK in week 5, Bedrock Converse in week 9 per curriculum.
  • Notebooks: nbformat v4, one markdown cell per STEP, outputs cleared.

c. Notes page + quiz docs/weeks/week-WW/day-N-slug.html

d. Exercise exercises/week-WW/day-N-slug/

  • README: task, acceptance criteria, how to run python -m pytest.
  • starter/module.py: signatures, docstrings, raise NotImplementedError.
  • tests/: 4–10 tests, no network. conftest.py puts starter/ on the path unless EXERCISE_SRC points elsewhere.
  • Contract enforced by critic and test suite: starter fails, trainer solution passes.

e. Trainer runbook trainer/week-WW/day-N-slug/runbook.md + solutions

  • Day at a glance: timing table summing to a 6-hour day (330–390 min).
  • Objectives, setup check, one section per demo file (talk track, type-live vs paste, checkpoint questions, expected output, pitfalls).
  • Notes page handoff, exercise briefing with where trainees get stuck, common questions, if-running-long / short.
  • Review days add a review agenda; the last teaching day of each week adds the feedback form slot. The header line carries the derived calendar date.

5Workflow pipeline

One script, harness/workflows/day-fanout.js, run through the Workflow tool. Adapted from the reference week-fanout.js, keeping its gated() repass helper, verdict schema and salvage pattern. Invocation:

Workflow({ scriptPath: "harness/workflows/day-fanout.js",
           args: { week: 1, days: [1], today: "2026-10-11", wordMin: 1200, wordMax: 1800 } })
1 · ResearchPer day. Prompt branches on gate: full = WebSearch + WebFetch every URL; light = version stamps + 3 official URLs, no fetch.
critic: research.md
2 · DemosAuthor writes demo dir from the brief. Critic compiles every file, runs the ones that need no key, checks README order and STEP markers.
critic: demos.md
3 · MaterialsThree authors in parallel, each handed the demo file list: notes page, runbook + solutions, exercise.
critics: notes.md, runbook.md, exercise.md
4 · WireSerial, one agent. Append glossary terms, flip day status to live, regenerate index WEEKS block, fix NEXT links.
shared files, no parallel edits
5 · VerifyOne agent runs python -m unittest. If a failure names a day artifact, one targeted fix agent, then re-run (max 2).
report + flagged count

Demos before pages. Notes, runbook and exercise all cite demo filenames, so demos must exist first. The notes critic rejects links to files that do not exist.

Repass loop (every gated artifact): generate, critic judges, if fail regenerate with the critiques, up to 3 passes. On the third fail the item is flagged for human review and the run continues. Critic is never the same agent as the author.

Dropped from reference: concept reconciliation (fed a backend taxonomy we do not have), interview question authoring, STT day-summary, client packets. Replaced by a cheap glossary-term append in the Wire step.

Multi-day runs: days are pipelined (day 2 can be in Materials while day 1 is in Research), then a serial Wire barrier, then Verify.

7Agent budget

What it means. A Workflow run spawns sub-agents. Every gated artifact costs one author agent plus one critic agent per pass. The Workflow tool in this session carries a guideline of fewer than 10 agents per run. It is a guideline, not a hard cap. The hard limit is 16 agents running concurrently.

ScopePass-1 agentsWorst case (3 passes everywhere)
One day5 artifacts × 2 = 10, + wire + verify = 125 × 5 + 2 = 27
One week (5 days)56130

Three ways to run it:

  1. Per-day runs, accept 12–27. One invocation per training day. Fits the concurrency cap. Simplest, and the natural unit for the pilot. recommended
  2. Split into two scripts per day. day-research-demos.js (~6 agents) then day-materials.js (~8). Stays near the guideline, doubles the invocations and needs the demo result handed between runs.
  3. Per-week runs. Raise the limit via /config (Dynamic workflow size). 5 days pipelined in one run, 56–130 agents. Fewest invocations, biggest single bill.

Decision: per-day runs. python harness/args_for.py <week> <day> prints the args; one Workflow call per training day.

10Pilot sequence

  1. Scaffold. Directories, gitignore, copy and modify assets, transcribe curriculum.json from the PNGs, write metrics / config / build_index / templates / critic specs / tests. git init at root and inside trainer/. Test suite passes with zero live days.
  2. Hand-build the exemplar page from the reference w02d1 with placeholder content, so authors copy structure rather than RAG content.
  3. Dry run W1D1. Single-day run. Review all five artifacts by hand, rehearse the runbook against the demo files, fix prompts and critic specs, re-run using resumeFromRunId so unchanged steps are cached.
  4. Promote W1D1 to the template. Run W1 d2–d5. Full test suite, local http.server walk-through, bump-css.sh.
  5. W1 retrospective. Update AGENTS.md, metrics, critic specs. Then scale week by week. Before week 5 (first full gate, first LLM demos) run W5D1 alone as a second pilot.

11Remaining decisions & risks

Status: this page is a design snapshot. Live status, milestones and open items are in STATUS.md; decisions are in decisions/README.md. Both are read at session start (AGENTS.md).
Review days. Proposed artifact set: recap notes page, cumulative quiz, week mini-exercise, runbook with review agenda and feedback form slot. A prompt variant keyed on kind: review.
W1D1 exercise. Orientation and git day; a pytest exercise is awkward. Proposal: small script exercise (parse a git log --oneline fixture) so the contract holds every day.
Known risks
  • Key-gated demos (Anthropic wk 5, Bedrock wk 9, Pinecone wk 8, SageMaker wk 11): critics can compile and shape-check but not execute. Rehearse manually.
  • Heavy dependencies (TensorFlow wk 6–7, SageMaker SDK wk 11): critic execution impractical here; structure validation only. Document a venv per week.
  • Dating: Workflow scripts cannot call Date; args.today is mandatory and stamped into briefs.
  • Nested git clones under Reference-Example/: never git add; gitignored.
  • Node in this shell: the nvm hook is broken in the Bash tool here. Node 22 exists on the machine; tests that need it must locate it or skip.
