# Exercise — A library schema with keys and constraints, then two functions through the connector

Week 3 · Day 3 · `w03d3` · Wed 2026-10-28 · ~60–90 min
Notes: [weeks/week-03/day-3-keys-constraints-and-normalization.html](https://2494-gen-ai-cn.github.io/training/weeks/week-03/day-3-keys-constraints-and-normalization.html) · Demos: [2494-Gen-AI-CN/demos](https://github.com/2494-Gen-AI-CN/demos)

## Task

Design a small `library` schema the way the ticket desk's schema is rebuilt in this day's notes: write `starter/schema.sql` with three tables, `members`, `books` and `loans`, using a primary key, a composite key on `loans`, foreign keys with `ON DELETE CASCADE`, `UNIQUE`, `NOT NULL`, `CHECK`, `DEFAULT` and `AUTO_INCREMENT`. Then write `add_member(conn, ...)` and `return_book(conn, ...)` in `starter/library_db.py` with mysql-connector-python, passing values as `%s` placeholders.

The tests build a scratch database called `library_test` inside your `desk-mysql` container, run your `schema.sql` in it, check every rule by trying to break it, and drop the database at the end. Each test rolls back what it wrote, so your functions must not call `commit()`. Your `ticket_desk` database is never touched.

The tables:

- `members`: `member_id` (generated by the server, primary key), `name` (required), `email` (required, no two members share one), `joined` (a date that defaults to today).
- `books`: `book_id` (primary key you supply), `title` (required), `copies` (required, defaults to 1, never negative).
- `loans`: `member_id` and `book_id` (together the primary key; each is a foreign key to its parent and deletes cascade), `loaned_on` (required date), `returned_on` (a date that may be empty), `status` (`'out'` or `'returned'`, defaults to `'out'`). Because the pair `(member_id, book_id)` is the key, a member can never borrow the same book a second time, even after returning it: that is a deliberate simplification for this exercise, so an error 1062 on a re-borrow means your key works, not that your schema is wrong.

## Acceptance criteria

- [ ] `test_add_member_returns_increasing_generated_ids`: `add_member` returns the id the server generated, and a second member gets a larger one
- [ ] `test_duplicate_email_is_refused`: a second member with the same email raises `IntegrityError` (error 1062)
- [ ] `test_member_name_is_required`: a NULL name is refused (error 1048)
- [ ] `test_negative_copies_fail_the_check`: a book with negative `copies` fails the CHECK (error 3819)
- [ ] `test_loan_status_defaults_to_out`: a loan inserted without `status` reads back as `'out'` with no `returned_on`
- [ ] `test_loan_pair_is_the_composite_key`: the same member and book twice in `loans` is refused (error 1062)
- [ ] `test_loan_needs_existing_member_and_book`: a loan for a member that does not exist, and a loan for a book that does not exist, are both refused (error 1452)
- [ ] `test_deleting_a_member_or_book_deletes_its_loans`: deleting a member removes only that member's loans and keeps the books; deleting a book removes its loans and keeps the members
- [ ] `test_return_book_closes_the_loan_and_restocks`: `return_book` sets `status` to `'returned'`, fills `returned_on` and adds one to `copies`
- [ ] `test_return_book_without_an_open_loan_raises`: with no outstanding loan `return_book` raises `ValueError` and changes nothing
- [ ] All tests pass: `python -m pytest -q` ends with `10 passed`; a line that says `skipped` means the tests did not reach your container and nothing was checked

## Hints

- A column constraint sits on the column line (`email VARCHAR(120) NOT NULL UNIQUE`); a constraint over two columns, such as `PRIMARY KEY (member_id, book_id)`, is a separate line at the end of the table.
- Create parents before children: `loans` points at `members` and `books`, so it comes last.
- `DEFAULT (CURRENT_DATE)` with the brackets gives a date column today's date; `CHECK (status IN ('out', 'returned'))` lists the allowed values.
- After an `INSERT` the cursor's `lastrowid` holds the id the server generated.
- `cursor.rowcount` after an `UPDATE` is the number of rows changed; `0` means the `WHERE` matched no outstanding loan, so raise `ValueError` before touching `books`.
- Never build SQL with an f-string; pass the values as a tuple: `cursor.execute("... WHERE member_id = %s", (member_id,))`.
