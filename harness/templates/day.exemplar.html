Topic Title: One-Line Hook

Week 0 · Day 0 Mon Jan 1, 2026 Phase label (week theme) ~35 min · reference notes @150 wpm · diagram · check Sources checked 2026-01-01 · python 3.15

Three to five sentences. The first names, in one sentence, what this page assumes from the previous day. The next say what the page teaches and what the reader can answer afterwards. No sentence points back at a classroom moment: the page stands on its own as documentation.

Framing

Section heading that states the idea

Each teaching step is 450–900 prose words and teaches one or two subtopics to junior-interview depth. Each one gets a plain explanation, a runnable example with its output shown, a trade-off or limit, how to recognise the thing in someone else's code, and the words to say when asked. Facts come only from the brief; a sentence that states a version, an API name's behaviour, a default or a limit cites its source like this.1

First subtopic as an h3

Explain the mechanism in plain words a graduate can follow. Single tokens go inline as python -m pytest -q; anything the reader would type goes in a fenced block, one command per line, no prompt characters, and the prose says what the output is.2

python --version
python -c "import sys; print(sys.version_info[:2])"
Python 3.12.1
(3, 12)

The second command prints (3, 12). Say what to notice and why it matters when the version differs.

The adjacent concept

The follow-up an interviewer asks next, from the brief's Notes depth. One level beyond the subtopic, never a later day's topic as a section. A later day's topic may be named in one sentence that says where it lands.

Three or more parallel things are a list, not a sentence:

  • the first thing, with the one fact that matters about it;
  • the second thing, stated the same way;
  • the third thing, and where it comes up.
Takeaways
  • One line the reader can check themselves against, drawn from this step's prose.
  • A second line: the trade-off or limit this step named.
  • A third line, optional: how to recognise the thing in someone else's code.
Say it in an interview

One to three spoken-form answers, first person, no code, each sayable in ten to twenty seconds, each answering one of this step's interview questions from the brief.
