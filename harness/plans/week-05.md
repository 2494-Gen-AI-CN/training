## Weekly Epic

By Friday afternoon a learner can take a developer task on the ticket desk (a triage rule for the desk's tickets, a band function of the kind P0's engineered features ask for (a bucket), the tests for `ticket_age_band`, a docstring for `extract.read_events`) and write a prompt for it that gives a model the code, the error, the constraint and the expected output, then improve that prompt over rounds instead of zero-shotting it. The learner reads a model's reply (printed, labelled as illustrative or quoted from an official doc) and judges it for correctness, maintainability and security: finds the boundary bug in generated code, the test that asserts the bug, the library function that does not exist, the SQL built by string formatting and the hard-coded password, says how to fix each, and checks a claim about a library against its documentation. The learner sorts what may be pasted into a public chat interface (never PII, credentials, keys or client data), explains how a large language model produces text and why it hallucinates, names the model families and the four ways a developer reaches a model (chat assistant, editor assistant, agentic coding tool, API access), and states the licence and copyright questions generated code raises. On Friday each pair presents Project 0 (`projects/P0/` in one partner's learner repo) to an audience playing technical and non-technical managers, with the deck's queries run live in BigQuery and both partners speaking, and can tell the same project in an interview as situation, task, action and result. The artifacts are the room's written AI-use rules from Monday, kept on the wall and in each learner's notes, and each pair's Project 0 hand-in and deck.

## Real-world framing and deliberate deviations

On a software team an assistant is one more tool in the review loop: a developer on the desk's team asks an editor assistant for a band function of the kind P0's engineered features ask for (a bucket), reads the suggestion, runs the tests, and opens a pull request that a teammate reviews like any other change; the company's AI policy, written with security and legal, says which assistant is approved, what may be sent to it and how its use is disclosed to the client. This week the room practises that loop on the desk's real code with replies printed on paper, because it has no approved assistant, and writes its own version of the policy as Monday's poster. A professional team would run the assistant live inside the editor, get a different reply each time, and find bugs nobody planted.

| Deviation | Workplace reality | Pedagogical reason |
|---|---|---|
| the room reads printed or on-screen replies and never runs a prompt itself | each developer uses an assistant the employer provisions, inside the editor and the chat tool | learners have no provisioned account and the substitute may have none; judging the reply is the skill, and paper works the same for every pair |
| model replies are written for the page and labelled illustrative, or quoted from an official doc | a live model answers each prompt fresh, differently by version and by run | a fixed reply lets every pair review the same lines and keeps a planted bug where the answer box says it is |
| generated code carries planted bugs listed in the runbook | real generated code has unplanted defects in unknown places | a known issue makes each review checkable by a substitute with no tool |
| the desk's code is quoted at 55f65d7 and nothing is committed | assistant output becomes a branch, a pull request and a review | concept week (D-0082): the desk's history ends at `06-etl-job` and this week teaches judging code the room did not write |
| the room writes its own AI-use rules on a poster | the employer's AI usage policy is written by security and legal and is binding | writing the rules makes the room own them; the notes point to the employer's or client's policy as the one that binds at work |
| the showcase audience is classmates playing technical and non-technical managers | a data team presents to the client's stakeholders and answers to them | the room has no client; playing the managers trains the audience's questions too |
