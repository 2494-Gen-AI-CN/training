## Weekly Epic

## Real-world framing and deliberate deviations

A support desk at a small software company runs on a codebase several people change every day. A customer files a ticket, an agent triages and assigns it, the SLA says how many hours each priority may stay open, and the team lead reads a weekly report: tickets per status, how long they took to resolve, which ones breached. The code behind that is a repository of modules with one job each, a virtual environment pinned by a lock file, a database for the tickets, logs shipped to a log service, a test suite that CI runs on every pull request, and a reporting job that draws the charts. This week builds a small version of each layer on purpose, in one folder on one laptop, and ledgers every shortcut below so the trainer can name it in one sentence when the room asks.

| Deviation | Workplace reality | Pedagogical reason |
|---|---|---|
| the thread restarts cold on Monday: 01-desk-modules retypes a compact `Ticket` and then `Desk` | work continues in the codebase that already exists | week 1 ran as loose days (D-0050), so the room's week-1 code is not the week-1 key; the plan args carry coldRestart |
| flat modules (`desk.py`, `storage.py`, `stats.py`, `report.py`, `frame.py`, `chart.py`) beside `ticket_desk.py` | a package folder with `__init__.py`, a `src/` layout, `pyproject.toml` and `pip install -e .` | flat modules import with no packaging configuration and pytest finds them from the folder; packaging for distribution is beyond the curriculum |
| the `.venv` runs Python 3.14 (applies only if the W2D1 brief finds no pylint and astroid release that declares Python 3.15 support) | the team's Python version is the newest one every tool in the stack supports, written down in the project's config | pylint is Monday's headline tool and support for a new Python release often lags; the transcript says why in one line and the rest of the week runs unchanged |
