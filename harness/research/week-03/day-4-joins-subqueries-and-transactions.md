## Claims (≥ metrics.research.claimsMin; each MUST carry a source on a full gate; light gate: source optional but recommended)

- WHERE filters rows before grouping; HAVING filters groups after aggregation, so an aggregate such as COUNT(*) is legal in HAVING and illegal in WHERE — [MySQL 8.4 Reference Manual: SELECT Statement](https://dev.mysql.com/doc/refman/8.4/en/select.html)
- A SELECT is written in the order SELECT, FROM, JOIN, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT, but the server logically evaluates FROM and WHERE first and SELECT near the end — [MySQL 8.4 Reference Manual: SELECT Statement](https://dev.mysql.com/doc/refman/8.4/en/select.html)
- Aggregate functions (COUNT, SUM, AVG, MIN, MAX) collapse many rows into one value per group, while scalar functions (CONCAT, DATE_ADD, UPPER) return one value per input row — [MySQL 8.4 Reference Manual: Aggregate Functions](https://dev.mysql.com/doc/refman/8.4/en/aggregate-functions.html)
- COUNT(*) counts rows; COUNT(column) skips rows where the column is NULL — [MySQL 8.4 Reference Manual: Aggregate Functions](https://dev.mysql.com/doc/refman/8.4/en/aggregate-functions.html)
- With the default ONLY_FULL_GROUP_BY SQL mode, a selected column that is neither grouped nor aggregated is rejected with an error — [MySQL 8.4 Reference Manual: MySQL Handling of GROUP BY](https://dev.mysql.com/doc/refman/8.4/en/group-by-handling.html)
- A column alias can be used in ORDER BY, GROUP BY and HAVING but not in WHERE, because WHERE is evaluated before SELECT assigns the alias — [MySQL 8.4 Reference Manual: Problems with Column Aliases](https://dev.mysql.com/doc/refman/8.4/en/problems-with-alias.html)
- A subquery is a SELECT nested inside another statement; a scalar subquery returns one value, a derived table sits in FROM, and IN / EXISTS take a subquery in WHERE — [MySQL 8.4 Reference Manual: Subqueries](https://dev.mysql.com/doc/refman/8.4/en/subqueries.html)
- MySQL's JOIN, INNER JOIN and CROSS JOIN are syntactic equivalents; an inner join without a match condition behaves as a cross join — [MySQL 8.4 Reference Manual: JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
- LEFT JOIN keeps every row of the left table and fills the right table's columns with NULL when nothing matches; RIGHT JOIN is the mirror image — [MySQL 8.4 Reference Manual: JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
- MySQL has no FULL OUTER JOIN keyword; the standard emulation is a LEFT JOIN combined by UNION with a RIGHT JOIN — [MySQL 8.4 Reference Manual: UNION Clause](https://dev.mysql.com/doc/refman/8.4/en/union.html)
- UNION removes duplicate rows and UNION ALL keeps them; each SELECT needs the same number of columns — [MySQL 8.4 Reference Manual: UNION Clause](https://dev.mysql.com/doc/refman/8.4/en/union.html)
- InnoDB is the MySQL storage engine that supports transactions with the ACID properties: atomicity, consistency, isolation, durability — [MySQL 8.4 Reference Manual: InnoDB and the ACID Model](https://dev.mysql.com/doc/refman/8.4/en/mysql-acid.html)
- InnoDB's default isolation level is REPEATABLE READ; the other three are READ UNCOMMITTED, READ COMMITTED and SERIALIZABLE — [MySQL 8.4 Reference Manual: Transaction Isolation Levels](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)
- Autocommit is on by default in the mysql client, so each statement is its own transaction until START TRANSACTION begins a multi-statement one — [MySQL 8.4 Reference Manual: autocommit, Commit, and Rollback](https://dev.mysql.com/doc/refman/8.4/en/innodb-autocommit-commit-rollback.html)
- DDL statements such as CREATE TABLE and DROP TABLE cause an implicit commit and cannot be rolled back — [MySQL 8.4 Reference Manual: Statements That Cause an Implicit Commit](https://dev.mysql.com/doc/refman/8.4/en/implicit-commit.html)
- LAST_INSERT_ID() returns the first AUTO_INCREMENT value generated by the current connection's most recent INSERT, unaffected by other connections — [MySQL 8.4 Reference Manual: Information Functions](https://dev.mysql.com/doc/refman/8.4/en/information-functions.html)
- Connector/Python's start_transaction() accepts an isolation_level argument and raises ProgrammingError when a transaction is already in progress — [MySQL Connector/Python: MySQLConnection.start_transaction()](https://dev.mysql.com/doc/connector-python/en/connector-python-api-mysqlconnection-start-transaction.html)

### Scalar functions
- Interview questions: What is a scalar function and how does it differ from an aggregate one? (qc2.sql.R18); Name three string, date or numeric functions; Can a scalar function appear in WHERE?
- Adjacent concept: Implicit type conversion — CONCAT turns a number such as ticket_id into a string, and comparing a string column with a number converts silently.
- Trade-off or limit: CONCAT and most scalar functions return NULL when any argument is NULL, so one missing value blanks the whole result; IFNULL or COALESCE supplies a fallback — [String Functions](https://dev.mysql.com/doc/refman/8.4/en/string-functions.html)
- Recognise on sight: `SELECT CONCAT('TD-', ticket_id), DATE_ADD(opened_at, INTERVAL 4 HOUR) FROM tickets;`
- Claims:
  - CONCAT returns NULL if any argument is NULL — [String Functions](https://dev.mysql.com/doc/refman/8.4/en/string-functions.html)
  - DATE_ADD(date, INTERVAL n unit) adds a time interval — [Date and Time Functions](https://dev.mysql.com/doc/refman/8.4/en/date-and-time-functions.html)
  - NOW() returns the current date and time — [Date and Time Functions](https://dev.mysql.com/doc/refman/8.4/en/date-and-time-functions.html)
  - COALESCE returns the first non-NULL argument — [Comparison Functions and Operators](https://dev.mysql.com/doc/refman/8.4/en/comparison-operators.html)
  - ROUND and other numeric functions work one row at a time — [Numeric Functions](https://dev.mysql.com/doc/refman/8.4/en/numeric-functions.html)

### Aggregate functions
- Interview questions: What is the difference between COUNT(*) and COUNT(column)? (qc2.sql.P15); Which aggregates ignore NULL?; What does an aggregate return over an empty table?; How does a window function such as ROW_NUMBER() OVER (PARTITION BY agent_id ORDER BY opened_at) differ from GROUP BY? (qc2.sql.S05)
- Adjacent concept: Window functions keep every row while computing over a partition (stretch, qc2.sql.S05), where GROUP BY collapses rows.
- Trade-off or limit: mixing an aggregate with a plain column without GROUP BY is an error under ONLY_FULL_GROUP_BY — [MySQL Handling of GROUP BY](https://dev.mysql.com/doc/refman/8.4/en/group-by-handling.html)
- Recognise on sight: `SELECT agent_id, COUNT(*) AS open_tickets FROM tickets WHERE status <> 'closed' GROUP BY agent_id;`
- Claims:
  - SUM, AVG, MIN and MAX ignore NULL values — [Aggregate Functions](https://dev.mysql.com/doc/refman/8.4/en/aggregate-functions.html)
  - COUNT over zero rows returns 0, while SUM, AVG, MIN and MAX return NULL — [Aggregate Functions](https://dev.mysql.com/doc/refman/8.4/en/aggregate-functions.html)
  - COUNT(DISTINCT col) counts unique non-NULL values — [Aggregate Functions](https://dev.mysql.com/doc/refman/8.4/en/aggregate-functions.html)
  - MySQL 8.0 and later support window functions with OVER (...) — [Window Functions](https://dev.mysql.com/doc/refman/8.4/en/window-functions.html)

### What is a subquery
- Interview questions: What is a subquery and where can one appear?; When would you use a subquery rather than a join? (qc2.sql.P14); What is the difference between IN and EXISTS, and what is a correlated subquery? (qc2.sql.S07); How would you rewrite a derived-table subquery as a WITH common table expression, and why is it easier to read? (qc2.sql.S06)
- Adjacent concept: Common table expressions name a subquery so the main query reads top to bottom (stretch, qc2.sql.S06).
- Trade-off or limit: a scalar subquery that returns more than one row raises ERROR 1242 — [Subqueries as Scalar Operands](https://dev.mysql.com/doc/refman/8.4/en/scalar-subqueries.html)
- Recognise on sight: `SELECT name FROM customers WHERE customer_id NOT IN (SELECT customer_id FROM tickets);`
- Claims:
  - A correlated subquery refers to a column of the outer query and is logically re-evaluated per outer row — [Correlated Subqueries](https://dev.mysql.com/doc/refman/8.4/en/correlated-subqueries.html)
  - NOT IN returns no rows when the subquery list contains a NULL; NOT EXISTS does not have that trap — [Subqueries with EXISTS or NOT EXISTS](https://dev.mysql.com/doc/refman/8.4/en/exists-and-not-exists-subqueries.html)
  - A subquery in FROM is a derived table and must have an alias — [Derived Tables](https://dev.mysql.com/doc/refman/8.4/en/derived-tables.html)
  - A WITH clause defines a common table expression, supported from MySQL 8.0 — [WITH (Common Table Expressions)](https://dev.mysql.com/doc/refman/8.4/en/with.html)

### What is a join
- Interview questions: What is a join and why do relational schemas need them? (qc2.sql.R21); What condition connects two tables in a join?; What happens to rows with no match?
- Adjacent concept: Foreign keys (Wednesday) are what a join's ON condition usually follows.
- Trade-off or limit: a missing or wrong ON condition multiplies rows (rows in A times rows in B) — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
- Recognise on sight: `FROM tickets AS t JOIN customers AS c ON c.customer_id = t.customer_id`
- Claims:
  - ON holds the join condition; USING(col) is shorthand when both tables share the column name — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
  - Several joins chain one after another in FROM — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
  - Selecting a column name present in both tables without a prefix gives ERROR 1052 (ambiguous) — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)

### Aliases
- Interview questions: What is the difference between a table alias and a column alias? (qc2.sql.P16); Why must a self-join use aliases?; Can you use a column alias in WHERE?
- Adjacent concept: A SQL alias is only a second name that lasts for one statement; it is unrelated to Python name aliasing.
- Trade-off or limit: an alias with spaces needs backticks or quotes, so snake_case aliases avoid the issue — [Schema Object Names](https://dev.mysql.com/doc/refman/8.4/en/identifiers.html)
- Recognise on sight: `SELECT COUNT(*) AS open_tickets FROM tickets AS t;`
- Claims:
  - AS is optional for both table and column aliases, but writing it makes intent clear — [SELECT Statement](https://dev.mysql.com/doc/refman/8.4/en/select.html)
  - Once a table is aliased in FROM, the alias must be used for its columns in that statement — [SELECT Statement](https://dev.mysql.com/doc/refman/8.4/en/select.html)
  - A column alias becomes the column name of the result, so it is the header in client output — [SELECT Statement](https://dev.mysql.com/doc/refman/8.4/en/select.html)
  - A dictionary cursor returns each row as a dict keyed by the result's column names, so `row["open_tickets"]` reads an aliased column — [MySQL Connector/Python: cursor.MySQLCursorDict Class](https://dev.mysql.com/doc/connector-python/en/connector-python-api-mysqlcursordict.html)

### Cross join
- Interview questions: What does a cross join return?; How many rows does a cross join of 4 and 6 rows give?; Name one practical use.
- Adjacent concept: Cartesian product — the set-theory name, and the reason an inner join with a forgotten ON explodes.
- Trade-off or limit: output grows multiplicatively, so a cross join of large tables is a performance hazard — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
- Recognise on sight: `FROM agents AS a CROSS JOIN priorities AS p` or the old `FROM agents, priorities`.
- Claims:
  - CROSS JOIN, like an inner join or a comma with no join condition, produces the Cartesian product: every row of one table paired with every row of the other — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
  - A comma between tables in FROM is an implicit cross join, with lower precedence than the JOIN keywords — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
  - Usage note (follows from the Cartesian product above, not stated in the manual): a cross join generates every combination, such as a rota of every agent against every priority (4 agents by 3 priorities gives 12 rows).

### Equi and theta joins
- Interview questions: What is an equi join? (qc2.sql.R21); What is a theta join and give an example?; Is a natural join the same as an equi join?
- Adjacent concept: Self-join — joining a table to itself with two aliases, usually an equi or theta condition.
- Trade-off or limit: with no equality condition, the hash join has nothing to build its lookup on, so every pair of rows is compared and the theta condition is applied as a filter — [Hash Join Optimization](https://dev.mysql.com/doc/refman/8.4/en/hash-joins.html)
- Recognise on sight: `JOIN priorities AS p ON p.priority = t.priority` (equi) against `JOIN tickets AS b ON b.opened_at > a.opened_at` (theta).
- Claims:
  - An equi join's condition uses only =; a theta join uses any comparison operator — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
  - The ON clause may hold any condition valid in a WHERE clause — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
  - NATURAL JOIN matches on all same-named columns, so it silently changes if a column is added; explicit ON is safer — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)

### Inner join
- Interview questions: What does an inner join return? (qc2.sql.R21); What happens to a ticket whose customer_id has no match?; Does table order matter for an inner join?
- Adjacent concept: Joining three or more tables, and filtering the joined result with WHERE.
- Trade-off or limit: an inner join silently drops unmatched rows, so reports can under-count — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
- Recognise on sight: `SELECT t.title, c.name FROM tickets AS t INNER JOIN customers AS c ON c.customer_id = t.customer_id;`
- Claims:
  - INNER JOIN returns only rows where the ON condition is true — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
  - The word INNER is optional — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
  - For inner joins a condition in ON or in WHERE gives the same result — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)

### Left and right joins
- Interview questions: What is the difference between INNER and LEFT JOIN? (qc2.sql.R21); How do you find rows with no match?; When is RIGHT JOIN better than swapping the tables?
- Adjacent concept: Anti-join pattern — LEFT JOIN ... WHERE right.key IS NULL, the join form of NOT EXISTS.
- Trade-off or limit: a WHERE condition on the right table's columns turns a LEFT JOIN back into an inner join; the condition belongs in ON — [Outer Join Simplification](https://dev.mysql.com/doc/refman/8.4/en/outer-join-simplification.html)
- Recognise on sight: `FROM tickets AS t LEFT JOIN agents AS a ON a.agent_id = t.agent_id` with `a.name` NULL for unassigned tickets.
- Claims:
  - LEFT JOIN is shorthand for LEFT OUTER JOIN; the OUTER word is optional — [JOIN Clause](https://dev.mysql.com/doc/refman/8.4/en/join.html)
  - At the parser stage MySQL rewrites a RIGHT JOIN as the equivalent LEFT JOIN with the tables swapped — [Outer Join Simplification](https://dev.mysql.com/doc/refman/8.4/en/outer-join-simplification.html)
  - The connector converts each returned value to a Python object — [MySQL Connector/Python: MySQLCursor.fetchone()](https://dev.mysql.com/doc/connector-python/en/connector-python-api-mysqlcursor-fetchone.html)
  - A database driver hands SQL NULL to Python as None, so an unmatched agent name arrives as None — [PEP 249: Python Database API Specification v2.0](https://peps.python.org/pep-0249/)

### Outer join
- Interview questions: What is a full outer join, and does MySQL support it? (qc2.sql.R21); How do you emulate it?; What is the difference between UNION and UNION ALL? (qc2.sql.S08)
- Adjacent concept: Set operations — UNION combines result sets by column position; INTERSECT and EXCEPT exist in MySQL 8.0.31 and later (qc2.sql.S08).
- Trade-off or limit: UNION removes duplicates, which costs more than UNION ALL, so use ALL when duplicates are impossible or wanted — [UNION Clause](https://dev.mysql.com/doc/refman/8.4/en/union.html)
- Recognise on sight: `SELECT ... FROM a LEFT JOIN b ON ... UNION SELECT ... FROM a RIGHT JOIN b ON ...`
- Claims:
  - Column names in a UNION result come from the first SELECT — [UNION Clause](https://dev.mysql.com/doc/refman/8.4/en/union.html)
  - ORDER BY at the end of a UNION applies to the whole combined result — [UNION Clause](https://dev.mysql.com/doc/refman/8.4/en/union.html)
  - INTERSECT and EXCEPT are available in MySQL 8.0.31 and later — [INTERSECT Clause](https://dev.mysql.com/doc/refman/8.4/en/intersect.html)

### Transaction commit rollback isolation levels
- Interview questions: What do COMMIT and ROLLBACK do? (qc2.sql.R11); What are the four isolation levels and which anomaly does each allow? (qc2.sql.P07); What is MySQL's default level and what does it guarantee?
- Adjacent concept: Locking — InnoDB uses row locks and consistent-read snapshots to implement the levels; deadlocks are the cost and retrying is the fix.
- Trade-off or limit: stricter isolation reduces anomalies but increases blocking and deadlocks — [Transaction Isolation Levels](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)
- Recognise on sight: `START TRANSACTION; UPDATE ...; INSERT ...; COMMIT;` or `conn.start_transaction(isolation_level="READ COMMITTED")`.
- Claims:
  - READ UNCOMMITTED can see other transactions' uncommitted changes (dirty reads) — [Transaction Isolation Levels](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)
  - READ COMMITTED sees only committed data, but each read can see a newer commit (non-repeatable read) — [Transaction Isolation Levels](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)
  - REPEATABLE READ reads from the snapshot taken at the first read, so repeated reads agree — [Consistent Nonlocking Reads](https://dev.mysql.com/doc/refman/8.4/en/innodb-consistent-read.html)
  - SERIALIZABLE makes plain reads take shared locks when autocommit is off — [Transaction Isolation Levels](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)
  - SET TRANSACTION ISOLATION LEVEL changes the level for the next transaction or the session — [SET TRANSACTION Statement](https://dev.mysql.com/doc/refman/8.4/en/set-transaction.html)
  - On error, call conn.rollback() before the exception leaves the function — [MySQL Connector/Python: MySQLConnection.rollback()](https://dev.mysql.com/doc/connector-python/en/connector-python-api-mysqlconnection-rollback.html)

### What is a transaction
- Interview questions: What is a transaction and when do you use one? (qc2.sql.R10); Give an example where two statements must succeed together; What happens to a transaction if the connection drops?
- Adjacent concept: Unit of work — the application pattern that wraps one business action in one transaction.
- Trade-off or limit: long transactions hold locks and snapshots, so keep them short — [InnoDB Transaction Model](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-model.html)
- Recognise on sight: `START TRANSACTION; UPDATE tickets SET agent_id = 1 ...; INSERT INTO ticket_events ...; COMMIT;`
- Claims:
  - A transaction groups statements so all take effect or none do — [START TRANSACTION, COMMIT, and ROLLBACK](https://dev.mysql.com/doc/refman/8.4/en/commit.html)
  - A transaction left open when the connection closes is rolled back — [autocommit, Commit, and Rollback](https://dev.mysql.com/doc/refman/8.4/en/innodb-autocommit-commit-rollback.html)
  - Only transactional engines such as InnoDB roll back; MyISAM does not — [START TRANSACTION, COMMIT, and ROLLBACK](https://dev.mysql.com/doc/refman/8.4/en/commit.html)

### ACID properties
- Interview questions: What do atomicity, consistency, isolation and durability each guarantee? (qc2.sql.R17); Which ACID property do constraints serve?; Which one does the redo log serve?
- Adjacent concept: BASE and eventual consistency in distributed stores — what some systems trade away from ACID.
- Trade-off or limit: durability costs a disk flush per commit; innodb_flush_log_at_trx_commit can relax it at the risk of losing recent commits — [InnoDB Startup Options and System Variables](https://dev.mysql.com/doc/refman/8.4/en/innodb-parameters.html)
- Recognise on sight: a bank transfer or ticket assignment — debit and credit, or update and event row, as one unit.
- Claims:
  - Atomicity: all statements commit or none do — [InnoDB and the ACID Model](https://dev.mysql.com/doc/refman/8.4/en/mysql-acid.html)
  - Consistency: a committed transaction leaves the data satisfying the schema's constraints — [InnoDB and the ACID Model](https://dev.mysql.com/doc/refman/8.4/en/mysql-acid.html)
  - Isolation: concurrent transactions do not see each other's half-finished work, to a degree set by the isolation level — [InnoDB and the ACID Model](https://dev.mysql.com/doc/refman/8.4/en/mysql-acid.html)
  - Durability: once committed, a change survives a crash, through the redo log and doublewrite buffer — [InnoDB and the ACID Model](https://dev.mysql.com/doc/refman/8.4/en/mysql-acid.html)

### Transaction properties
- Interview questions: What is autocommit?; How do the ACID properties differ from the isolation anomalies? (qc2.sql.R17); What does a transaction do to the rows it changes until it commits?
- Adjacent concept: Savepoints (named in Tuesday's TCL) — partial rollback inside one transaction.
- Trade-off or limit: DDL ends a transaction with an implicit commit, so mixing DDL and DML in one transaction breaks atomicity — [Statements That Cause an Implicit Commit](https://dev.mysql.com/doc/refman/8.4/en/implicit-commit.html)
- Recognise on sight: `SET autocommit = 0;` at the top of a script, or `conn.autocommit = False` in Python.
- Claims:
  - START TRANSACTION turns autocommit off until COMMIT or ROLLBACK — [START TRANSACTION, COMMIT, and ROLLBACK](https://dev.mysql.com/doc/refman/8.4/en/commit.html)
  - Connector/Python leaves autocommit off by default, so a write needs conn.commit() — [MySQL Connector/Python: MySQLConnection.commit()](https://dev.mysql.com/doc/connector-python/en/connector-python-api-mysqlconnection-commit.html)
  - InnoDB keeps the old version of each row a transaction changes in the undo log, so a rollback can restore it and other transactions can still read it — [Undo Logs](https://dev.mysql.com/doc/refman/8.4/en/innodb-undo-logs.html)

### CRUD operations
- Interview questions: What does CRUD stand for and which SQL statement maps to each letter?; How do you pass values safely from Python?; What does cursor.rowcount tell you after an UPDATE?
- Adjacent concept: SQL injection — why %s placeholders and never f-strings.
- Trade-off or limit: UPDATE or DELETE without WHERE touches every row — [UPDATE Statement](https://dev.mysql.com/doc/refman/8.4/en/update.html)
- Recognise on sight: `cursor.execute("UPDATE tickets SET agent_id = %s WHERE ticket_id = %s", (agent_id, ticket_id))`
- Claims:
  - Usage note: CRUD (create, read, update, delete) is an industry name, not a MySQL keyword; its four letters map to INSERT, SELECT, UPDATE and DELETE, the four statements the manual lists under Data Manipulation Statements — [Data Manipulation Statements](https://dev.mysql.com/doc/refman/8.4/en/sql-data-manipulation-statements.html)
  - cursor.execute(sql, params) sends values separately from the SQL text — [MySQL Connector/Python: MySQLCursor.execute()](https://dev.mysql.com/doc/connector-python/en/connector-python-api-mysqlcursor-execute.html)
  - cursor.rowcount after an UPDATE is the number of rows changed, so setting a column to its current value gives 0 — [MySQL Connector/Python: MySQLCursor.rowcount](https://dev.mysql.com/doc/connector-python/en/connector-python-api-mysqlcursor-rowcount.html)

### Sequence
- Interview questions: How does MySQL generate ids (AUTO_INCREMENT)?; How do you get the id of the row just inserted?; Why can ids have gaps?
- Adjacent concept: Sequence objects in other databases (PostgreSQL, Oracle) — MySQL has no CREATE SEQUENCE.
- Trade-off or limit: a rolled-back INSERT still consumes its AUTO_INCREMENT value, so gaps are normal and ids are not a row count — [AUTO_INCREMENT Handling in InnoDB](https://dev.mysql.com/doc/refman/8.4/en/innodb-auto-increment-handling.html)
- Recognise on sight: `ticket_id INT AUTO_INCREMENT PRIMARY KEY` and `new_id = cursor.lastrowid`.
- Claims:
  - A table has at most one AUTO_INCREMENT column and it must be a key, typically the primary key — [Using AUTO_INCREMENT](https://dev.mysql.com/doc/refman/8.4/en/example-auto-increment.html)
  - LAST_INSERT_ID() is per connection, so another client's insert does not change your value — [Information Functions](https://dev.mysql.com/doc/refman/8.4/en/information-functions.html)
  - cursor.lastrowid exposes that value in Connector/Python — [MySQL Connector/Python: MySQLCursor.lastrowid](https://dev.mysql.com/doc/connector-python/en/connector-python-api-mysqlcursor-lastrowid.html)

## Glossary terms (3–8; one-sentence plain-language definitions; aka = alternate surface forms)

- subquery | A SELECT written inside another SQL statement whose result the outer statement uses as a value, a list or a temporary table. | aka: subqueries, nested query, inner query
- aggregate function | A SQL function such as COUNT, SUM or AVG that turns many rows into a single value per group. | aka: aggregate functions, aggregation
- outer join | A join that keeps rows with no match on one or both sides and fills the missing columns with NULL. | aka: left join, right join, left outer join, right outer join, full outer join
- isolation level | The setting that decides how much of other transactions' unfinished or newly committed work a transaction can see. | aka: isolation levels, transaction isolation
- scalar function | A SQL function such as CONCAT or DATE_ADD that returns one value for each input row. | aka: scalar functions
- dirty read | Reading a change that another transaction has made but not yet committed and may still undo. | aka: dirty reads
- common table expression | A named temporary result defined with WITH at the top of a query so later parts can read from it by name. | aka: CTE, CTEs, WITH clause
- window function | A function that computes over a set of related rows while still returning every row, unlike an aggregate that collapses them. | aka: window functions, OVER clause

## Common pitfalls (3–6; feed the runbook "where trainees get stuck" and quiz distractors)

- Using an aggregate in WHERE (WHERE COUNT(*) > 1) instead of HAVING, and selecting a non-grouped column so ONLY_FULL_GROUP_BY raises an error.
- Writing = NULL instead of IS NULL, and using NOT IN against a subquery that returns a NULL, which silently returns no rows.
- Filtering the right table in WHERE after a LEFT JOIN, which removes the NULL rows and turns it into an inner join; also typing FULL OUTER JOIN, which MySQL rejects.
- Forgetting conn.commit() in Connector/Python (autocommit is off, so the change vanishes on close), or calling start_transaction() on a connection that already ran a statement and getting "Transaction already in progress".
- Expecting ROLLBACK to undo CREATE or DROP (implicit commit) or to rewind AUTO_INCREMENT, then being surprised by gaps in ids.
- Reading the isolation demo backwards: under REPEATABLE READ a second connection's committed change stays invisible until the reader commits and starts a new transaction.
