## Claims (≥ metrics.research.claimsMin; each MUST carry a source on a full gate; light gate: source optional but recommended)

- Keyword engines "can only find documents based on lexical matches", while semantic search tries to match the meaning of the query; a short query against longer passages is "asymmetric" search — [Sentence Transformers: Semantic Search](https://sbert.net/examples/sentence_transformer/applications/semantic-search/README.html)
- Lexical search (full-text BM25 or sparse vectors) suits "specific terms like product codes, error strings, and names"; semantic (dense) search finds "an answer phrased with different words"; hybrid search "combines two or more retrieval signals" because "each method misses what the others catch" — [Pinecone: Hybrid search](https://docs.pinecone.io/guides/search/hybrid-search)
- `TfidfVectorizer` lowercases by default, keeps tokens of two or more letters or digits, uses no stop-word list by default, and `transform` uses only the vocabulary learned at `fit`, so a query word absent from the stored texts scores nothing — [scikit-learn: TfidfVectorizer](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html)
- `all-MiniLM-L6-v2` maps text to 384 numbers, truncates input longer than 256 word pieces, was trained by contrastive learning on over 1 billion sentence pairs (given one sentence, pick its true partner from a random set), and is Apache-2.0 — [Hugging Face: all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)
- `all-mpnet-base-v2` maps text to 768 numbers and truncates past 384 word pieces; the Sentence Transformers docs say it "provides the best quality" while MiniLM "is 5 times faster and still offers good quality" — [Hugging Face: all-mpnet-base-v2](https://huggingface.co/sentence-transformers/all-mpnet-base-v2), [Sentence Transformers: Pretrained Models](https://sbert.net/docs/sentence_transformer/pretrained_models.html)
- `encode` defaults to `batch_size=32` and `normalize_embeddings=False`, returns a 2-D numpy array of shape `[num_inputs, output_dimension]`, and `max_seq_length` is a property ("Longer inputs will be truncated"); the dimension method is `get_embedding_dimension()` — [Sentence Transformers: SentenceTransformer API](https://sbert.net/docs/package_reference/sentence_transformer/SentenceTransformer.html)
- DEPRECATED on Colab's 5.7.0: `get_sentence_embedding_dimension()` carries `@deprecated("The get_sentence_embedding_dimension method has been renamed to get_embedding_dimension.", category=FutureWarning)`; inside `encode` the inputs are sorted by length (`length_sorted_idx = np.argsort([-self._input_length(sen) for sen in inputs])`) before they are cut into batches — [sentence-transformers v5.7.0 source: sentence_transformer/model.py](https://raw.githubusercontent.com/huggingface/sentence-transformers/v5.7.0/sentence_transformers/sentence_transformer/model.py)
- Normalised (length-1) embeddings let a dot product serve as the cosine score; for millions of embeddings exact search is slow and approximate nearest-neighbour methods trade recall for speed — [Sentence Transformers: Semantic Search](https://sbert.net/examples/sentence_transformer/applications/semantic-search/README.html)
- The query vector must come from "the same embedding model you used at upsert" — [Pinecone: Semantic search](https://docs.pinecone.io/guides/search/semantic-search)
- The Sentence Transformers docs point to the MTEB leaderboard "as an inspiration of strong Sentence Transformer models"; MTEB scores embeddings on retrieval, clustering, classification, reranking and similarity tasks — [Sentence Transformers: Pretrained Models](https://sbert.net/docs/sentence_transformer/pretrained_models.html), [MTEB on GitHub](https://github.com/embeddings-benchmark/mteb), [MTEB Leaderboard](https://huggingface.co/spaces/mteb/leaderboard)
- `fetch_20newsgroups` defaults to `subset="train"`, `shuffle=True`, `random_state=42`, `remove=()`; `remove` may hold `"headers"`, `"footers"` (signature blocks) and `"quotes"`, and only `"headers"` "follows an exact standard; the other filters are not always correct"; the full set has 18,846 posts in 20 classes — [scikit-learn: fetch_20newsgroups](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.fetch_20newsgroups.html)

- A named entity is "a 'real-world object' that's assigned a name", read from `doc.ents` as spans with `label_`; `spacy.explain(label)` gives the description; the models "are statistical and strongly depend on the examples they were trained on" — [spaCy: Linguistic Features, Named Entities](https://spacy.io/usage/linguistic-features#named-entities)
- `en_core_web_sm` 3.8.0 is 12 MB, trained on OntoNotes 5, has 18 entity labels (CARDINAL, DATE, EVENT, FAC, GPE, LANGUAGE, LAW, LOC, MONEY, NORP, ORDINAL, ORG, PERCENT, PERSON, PRODUCT, QUANTITY, TIME, WORK_OF_ART) and NER precision 84.30, recall 84.36, F 84.33 — [spaCy models: en_core_web_sm-3.8.0 release](https://github.com/explosion/spacy-models/releases/tag/en_core_web_sm-3.8.0)
- `nlp.pipe` processes texts as a stream in batches, which is "usually more efficient"; `batch_size` is "The number of texts to buffer"; components you do not need can be skipped with `disable` — [spaCy: Processing Pipelines](https://spacy.io/usage/processing-pipelines), [spaCy API: Language.pipe](https://spacy.io/api/language#pipe)

### Semantic search
- Interview questions: How does semantic search differ from keyword search, and when does each find the better result? (qc4.vector-databases-chroma-and-pinecone.R19); Why does a TF-IDF search for "my car will not start when it is freezing" miss a sentence about an engine on cold mornings?; What is hybrid search and why would a team run both kinds? (qc4.vector-databases-chroma-and-pinecone.R19)
- Adjacent concept: the pipeline as a whole (load, prepare, clean, tag entities, build metadata, embed in batches, build records, upsert, query) — the interviewer's next question is "what has to happen before the first search works", and `### 1.3` is the map every later section follows.
- Trade-off or limit: semantic search finds paraphrases but blurs exact strings (part numbers, error codes, rare names), where lexical search wins — [Pinecone: Hybrid search](https://docs.pinecone.io/guides/search/hybrid-search)
- Recognise on sight: `TfidfVectorizer().fit_transform(texts)` plus `cosine_similarity(...)` is keyword search; `encoder.encode(texts, normalize_embeddings=True)` then `vectors @ query_vector` is semantic search.
- Claims:
  - Measured (local, Colab's pins) on eight hand-written sentences: TF-IDF's top hits for "my car will not start when it is freezing" are "When it is sunny, the park fills with families." (about 0.37) and "I will not pay that parking ticket." (about 0.35), sharing only "when it is" and "will not"; the engine sentence scores 0. MiniLM ranks "The engine struggles to turn over on cold mornings." first (about 0.36, next about 0.22); mpnet ranks it first at about 0.60 — source of the scores: measured locally on Colab's pins, 2026-11-24; why TF-IDF scores only words in the fitted vocabulary: [scikit-learn: TfidfVectorizer](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html); what MiniLM was trained to do: [Hugging Face: all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)
  - Measured: for the query "7731-B" over "part 7731-B / 7713-B / 1377-B fits the 20xx model", TF-IDF scores only the exact part (about 0.47, others 0) while MiniLM ranks 7713-B (about 0.23) above the exact 7731-B (about 0.21): keywords win on codes — source of the scores: measured locally on Colab's pins, 2026-11-24; that lexical search suits product codes and error strings: [Pinecone: Hybrid search](https://docs.pinecone.io/guides/search/hybrid-search)
  - Keyword engines match only shared words; semantic search matches meaning — [Sentence Transformers: Semantic Search](https://sbert.net/examples/sentence_transformer/applications/semantic-search/README.html)
  - Hybrid search merges a lexical and a dense signal; it is named here and not built — [Pinecone: Hybrid search](https://docs.pinecone.io/guides/search/hybrid-search)

### Data preprocessing
- Interview questions: How do you clean raw text before embedding it? (qc4.vector-databases-chroma-and-pinecone.P10); Why drop very short posts and exact duplicates? (qc4.vector-databases-chroma-and-pinecone.P10); A post is 55,000 characters long: what does the model actually read of it?
- Adjacent concept: truncation by the model — an embedding model cuts input past its word-piece limit without an error, so a team decides what the model sees instead of letting the cut fall anywhere; splitting into chunks is named for week 9 only.
- Trade-off or limit: removing quotes and signatures with `fetch_20newsgroups(remove=...)` is heuristic: "the other filters are not always correct", so signatures and e-mail addresses survive — [scikit-learn: fetch_20newsgroups](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.fetch_20newsgroups.html)
- Recognise on sight: `re.sub(r"\s+", " ", s).strip()`; `df[df["text"].str.len() >= 100]`; `df.drop_duplicates(subset="text")`; `s[:1000].rsplit(" ", 1)[0]`.
- Claims:
  - Measured: whitespace cleaning leaves 77 empty posts and 220 under 100 characters (out of 2,365); then 3 exact duplicates; 2,142 remain — source of the counts: measured locally on Colab's pins, 2026-11-24; why `remove=` leaves empty and short posts behind (the filters strip whole parts of a post): [scikit-learn: fetch_20newsgroups](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.fetch_20newsgroups.html)
  - Measured: after the 1,000-character cut the median post is about 129 MiniLM word pieces, and 63 of 1,000 still exceed 256, so the model truncates those further; 1,000 characters is a bound on what is stored, not a promise that the model reads it all — source of the counts: measured locally on Colab's pins, 2026-11-24; the 256-word-piece truncation: [Hugging Face: all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)
  - `max_seq_length` "Returns the maximal input sequence length for the model. Longer inputs will be truncated." — [Sentence Transformers: SentenceTransformer API](https://sbert.net/docs/package_reference/sentence_transformer/SentenceTransformer.html)
  - Calling the tokenizer directly on a long post prints a "Token indices sequence length is longer than the specified maximum sequence length for this model (393 > 256)" message; `encode` itself truncates silently — source of the message text: measured locally on Colab's pins, 2026-11-24; that longer inputs are truncated: [Sentence Transformers: SentenceTransformer API](https://sbert.net/docs/package_reference/sentence_transformer/SentenceTransformer.html)

### Preparing for upsert
- Interview questions: What goes into one record you upsert to a vector database? (qc4.vector-databases-chroma-and-pinecone.R18); What would you check before writing 1,000 records? - Adjacent concept: the vector database as one tool among several (qc4.vector-databases-chroma-and-pinecone.S01) — the originals stay in files or a SQL table keyed by the same id, the vector store holds id, vector and the metadata needed to filter and show, and a search returns ids that lead back to the original.

## Glossary terms (3–8; one-sentence plain-language definitions; aka = alternate surface forms)

- semantic search | Finding stored texts whose meaning is closest to a query by comparing their embeddings, so a match needs no shared word. | aka: meaning-based search, dense retrieval
- keyword search | Finding stored texts that contain the query's own words, ranked by a word score such as TF-IDF or BM25. | aka: lexical search, full-text search, BM25
- hybrid search | Running keyword search and semantic search on the same query and merging the two rankings, so exact codes and paraphrases are both found. | aka: hybrid retrieval
- named entity recognition | A model that finds the names of real-world things in text, such as organisations, people and places, and labels each one with its kind. | aka: NER, entity extraction, doc.ents
- sentence transformer | A model that turns a whole sentence or short passage into one fixed-length embedding, trained so texts that mean the same land close together. | aka: SentenceTransformer, sentence-transformers, embedding model, embedding models
- max sequence length | The most word pieces an embedding model reads from one text; anything past it is cut off without an error. | aka: max_seq_length, truncation, truncated
- relevance set | A list of test queries, each paired with the stored items a person judged correct, used to score a search with measures such as recall@k or MRR. | aka: check set, recall@k, MRR, mean reciprocal rank

## Common pitfalls (3–6; feed the runbook "where trainees get stuck" and quiz distractors)

- Embedding the query with a different model, or without `normalize_embeddings=True`, than the stored vectors: a different size fails loudly, but a different model of the same size returns confident nonsense with no error.
- Reading Chroma's distance as a similarity (lower is closer) or Pinecone's score as a distance (higher is closer), so "the best match" is read from the wrong end of the list.
- Writing metadata the database refuses: `None`, an empty list (`{"orgs": []}` raises `ValueError` in Chroma 1.5.9; 359 of the 1,000 posts have no organisation) or a mixed-type list; and passing a numpy array as Pinecone's `upsert` values or `query(vector=...)`, which on the pinned 9.1.0 raises `TypeError: Type is not JSON serializable` before any request is sent (use `.tolist()`).
- Believing a long post is embedded whole: MiniLM reads the first 256 word pieces and drops the rest silently, and 63 of the 1,000 posts still exceed that after the 1,000-character cut.
- Trusting NER output as clean facts: on forum text it tags e-mail addresses, "MSG" and "BP" as organisations and car models as ORG, so entity metadata needs a look before it becomes a filter.
- Rerunning the Chroma cell after removing the folder and getting `Collection [posts] already exists`, because Chroma caches the client per path inside the Python process; clear the cache first.
