## Claims (≥ metrics.research.claimsMin; each MUST carry a source on a full gate; light gate: source optional but recommended)

- Chroma's `add` needs a unique string `id` per record and either documents, embeddings or both; adding a record whose id already exists is "ignored without throwing an error", so changing a stored record takes `update` or `upsert` — [Adding data to Chroma collections (Chroma docs)](https://docs.trychroma.com/docs/collections/add-data)
- Chroma's `update` on a missing id logs an error and ignores that item; `upsert` creates the items whose ids are absent "as per `add`" and updates those that exist "as per `update`" — [Updating data in Chroma collections (Chroma docs)](https://docs.trychroma.com/docs/collections/update-data)
- If documents are sent to Chroma without embeddings, Chroma generates the embeddings with the collection's embedding function; precomputed embeddings sent with documents are stored as they are — [Adding data to Chroma collections (Chroma docs)](https://docs.trychroma.com/docs/collections/add-data)
- A Chroma collection's distance space is set at creation with `configuration={"hnsw": {"space": "cosine"}}`; the options are `l2`, `cosine` and `ip`, the default is `l2` (squared L2), cosine distance is 1 minus the cosine similarity, and `space` is not among the settings that can be changed after creation — [Configure (Chroma docs)](https://docs.trychroma.com/docs/collections/configure)
- `PersistentClient` saves the database to a local folder (`path`, default `.chroma`) and loads it on start if it exists; the in-memory client (`chromadb.Client()`) suits experiments where nothing has to persist — [Chroma Clients (Chroma docs)](https://docs.trychroma.com/docs/run-chroma/clients)
- Chroma's `where` filters support `$eq`, `$gt`, `$gte`, `$lte`, `$in`, `$nin`, `$and`, `$or`, and `$contains` / `$not_contains` on array metadata, where every element has one type and empty arrays are not allowed — [Metadata filtering (Chroma docs)](https://docs.trychroma.com/docs/querying-collections/metadata-filtering)
- Pinecone runs as a managed service on AWS, GCP and Azure, with writes and reads on separate paths that scale independently, and each namespace's data kept in distributed object storage — [Database architecture (Pinecone docs)](https://docs.pinecone.io/guides/get-started/database-architecture)
- In Pinecone, records are partitioned into namespaces, created automatically during upsert, and a query scans only its namespace's records; metadata is a flat JSON object of key-value fields "you filter on at query time", up to 40 KB per record, with no null values — [Indexing overview (Pinecone docs)](https://docs.pinecone.io/guides/index-data/indexing-overview)
- With your own vectors, Pinecone does not embed anything: "you embed each document before you upsert it and each query before you search, with the same model", and the index's dimension and metric match that model — [Indexing overview (Pinecone docs)](https://docs.pinecone.io/guides/index-data/indexing-overview)
- Upserting to Pinecone with an id that already exists "overwrites the entire document"; a batch request holds up to 1,000 documents and 2 MB — [Upsert data (Pinecone docs)](https://docs.pinecone.io/guides/index-data/upsert-data)
- Pinecone metadata filters use `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin` (up to 10,000 values), `$exists`, `$and`, `$or` and `$not`; a bare comparison operator cannot sit at the top level — [Filter by metadata (Pinecone docs)](https://docs.pinecone.io/guides/search/filter-by-metadata)
- Pinecone recommends one namespace per tenant for physical isolation; a metadata filter is the alternative when isolation is not strict or a search must cross tenants, but a filtered search scans the whole namespace, which costs more and takes longer; every operation targets one namespace — [Implement multitenancy (Pinecone docs)](https://docs.pinecone.io/guides/index-data/implement-multitenancy)
- Cosine similarity runs from -1 to 1, where 1 means the vectors point the same way; a small Euclidean distance means close vectors; the rule of thumb is to use the metric the embedding model was trained with — [Vector Similarity Explained (Pinecone Learn)](https://www.pinecone.io/learn/vector-similarity/)
- `all-MiniLM-L6-v2` maps sentences and paragraphs to a 384-dimensional dense vector space, is meant for retrieval, clustering and sentence similarity, and cuts input longer than 256 word pieces — [sentence-transformers/all-MiniLM-L6-v2 (Hugging Face)](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)
- Accuracy is the share of all classifications that were right; on a rare positive class a model that always predicts negative can score 99% while being useless; recall matters most when a missed positive costs more, precision when a positive prediction must be reliable — [Classification: accuracy, recall, precision (Google ML Crash Course)](https://developers.google.com/machine-learning/crash-course/classification/accuracy-precision-recall)
- A confusion matrix sorts predictions into true positives, false positives, false negatives and true negatives; raising the threshold generally lowers false positives and raises false negatives — [Thresholds and the confusion matrix (Google ML Crash Course)](https://developers.google.com/machine-learning/crash-course/classification/thresholding)
- `DummyClassifier` "makes predictions that ignore the input features" and "serves as a simple baseline to compare against other more complex classifiers"; with `strategy="most_frequent"` it always predicts the most common class — [sklearn.dummy.DummyClassifier (scikit-learn)](https://scikit-learn.org/stable/modules/generated/sklearn.dummy.DummyClassifier.html)
- The TensorFlow overfitting tutorial starts "with a simple model using only densely-connected layers ... as a baseline", then builds larger models and compares them; in its plots a lower validation loss means a better model — [Overfit and underfit (TensorFlow tutorial)](https://www.tensorflow.org/tutorials/keras/overfit_and_underfit)
- Data leakage uses information not available at prediction time and gives over-optimistic scores; "Test data should never be used to make choices about the model", the rule is "never call `fit` on the test data", and the data is split before any preprocessing — [Common pitfalls and recommended practices (scikit-learn)](https://scikit-learn.org/stable/common_pitfalls.html)
- Even with cross-validation, "A test set should still be held out for final evaluation"; tuning settings until the test score is best lets knowledge of the test set "leak" into the model, and the metrics then no longer report generalisation — [Cross-validation: evaluating estimator performance (scikit-learn)](https://scikit-learn.org/stable/modules/cross_validation.html)
- Validation and test sets "wear out" with repeated use: each decision taken on the same data tunes the model to it, leaving less confidence about new data — [Dividing the original dataset (Google ML Crash Course)](https://developers.google.com/machine-learning/crash-course/overfitting/dividing-datasets)
- `tf.keras.utils.set_random_seed(seed)` sets the Python, NumPy and TensorFlow seeds in one call and can make "almost any Keras program fully deterministic", with limits around some non-deterministic GPU ops — [tf.keras.utils.set_random_seed (TensorFlow)](https://www.tensorflow.org/api_docs/python/tf/keras/utils/set_random_seed)
- A model card reports a model's performance under varied conditions (including across relevant groups), the context it is intended for, and how it was evaluated, so it is not used where it is poorly suited — [Model Cards for Model Reporting (Mitchell et al., arXiv)](https://arxiv.org/abs/1810.03993)
- Define an audience by role, then by proximity to the knowledge; experts' "expert understanding of a topic ruins their explanations to newcomers", and "as your target audience widens, assume that you must explain more" — [Audience (Google Technical Writing One)](https://developers.google.com/tech-writing/one/audience)
- A chart's headline title "should communicate the headline message of the chart", and if its message cannot be told over the phone in a few sentences the chart needs rethinking — [Data visualisation: charts (Government Analysis Function)](https://analysisfunction.civilservice.gov.uk/policy-store/data-visualisation-charts/)
- The assertion-evidence approach builds each slide on a succinct sentence message rather than a phrase topic, supported by visual evidence rather than a bulleted list — [The Assertion-Evidence Approach (Penn State)](https://www.assertion-evidence.com/)
- Being upfront about limitations protects the integrity of findings; overstated certainty risks "inappropriate decisions", so an analyst explains "how any limitations ... feed through into the decisions that users take" — [Communicating quality, uncertainty and change (Government Analysis Function)](https://analysisfunction.civilservice.gov.uk/policy-store/communicating-quality-uncertainty-and-change/)

- Recognise on sight: `collection.query(query_embeddings=embed([q]), n_results=5, where={"category": "billing"})` against `index.query(vector=embed([q])[0].tolist(), top_k=5, namespace="web", filter={"category": {"$eq": "billing"}}, include_metadata=True)`; a `distance` column rising down the Chroma table and a `score` column falling down the Pinecone table for the same top results.

## Glossary terms (3–8; one-sentence plain-language definitions; aka = alternate surface forms)

- baseline | The simplest model or rule a real model is compared against, such as always predicting the most common class, so a score means something. | aka: baseline model, majority-class baseline, DummyClassifier
- error analysis | Looking at the examples a model gets wrong and asking what they have in common, to learn where it fails and why. | aka: misclassified examples, wrong predictions
- model card | A short document that says what a model is for, how it was evaluated, how well it does and where it should not be used. | aka: model cards, model report
- speaker notes | Private notes attached to each slide that the presenter sees and the audience does not. | aka: presenter notes, presenter view
- reproducibility | The property of a notebook that reruns from top to bottom on a fresh runtime and lands on the same, or very close, numbers. | aka: reproducible, rerun from the top
- mixed audience | Listeners with different roles and different distance from the work, such as engineers and managers in one meeting. | aka: non-technical audience, mixed technical audience

## Common pitfalls (3–6; feed the runbook "where trainees get stuck" and quiz distractors)

- A results slide titled "Results" carrying a table of five metrics, led by accuracy on an imbalanced target; a manager cannot tell whether it is good. Title the slide with the finding, say one number in plain words (recall or the cost the problem cares about), and name the baseline beside it.
- A number on a slide that no cell prints: typed from an earlier run, rounded differently, or changed by a rerun without fixed seeds. Every slide number is copied from the final Run all, and the seed call sits at the top.
- The test set looked at more than once (a test-set evaluate after each change, or a threshold tuned on it), then reported as an unseen score; or a scaler fitted before the split. Choices are made on validation data, and the test set is used once at the end.
- An improvement attempt left out, or spun, because it did not help. It is reported honestly with a before-and-after row and one sentence on why; a reviewer trusts the rest of the deck more for it.
- Over-running the slot: ten slides read aloud at seven minutes with no time left for the question. Rehearse twice against a clock to the slot set at the setup check, spend the time on results, errors and the improvement, and answer the one question in two sentences.
- In the VectorDB review: reading Chroma's distance as if higher were better (it is a distance, lower is closer; Pinecone's score is a similarity, higher is closer); expecting `add` to replace an existing id (Chroma ignores it silently; `upsert` replaces); or querying with a different model from the one that embedded the records.
