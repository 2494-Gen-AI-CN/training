## Claims (≥ metrics.research.claimsMin; each MUST carry a source on a full gate; light gate: source optional but recommended)

- An embedding is a vector representation of data, and the distance between two embeddings can be read as a measure of how alike the two items are; Google's course places foods as points such as (0.5, 0.3) to show it. — [Embeddings: Embedding space and static embeddings (Google ML Crash Course)](https://developers.google.com/machine-learning/crash-course/embeddings/embedding-space)
- `all-MiniLM-L6-v2` maps a sentence or paragraph to a 384-dimensional dense vector, is meant for semantic search and clustering, and truncates input longer than 256 word pieces. — [sentence-transformers/all-MiniLM-L6-v2 (model card)](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)
- `SentenceTransformer.encode(..., normalize_embeddings=True)` returns vectors of length 1 as a NumPy array of shape (number of texts, 384), so a dot product of two of them equals their cosine similarity. — [SentenceTransformer API reference](https://sbert.net/docs/package_reference/sentence_transformer/SentenceTransformer.html)
- A vector database indexes and stores vector embeddings for fast retrieval and similarity search; a traditional database looks for rows whose value exactly matches the query, a vector database applies a similarity metric to find the most similar vectors. — [What is a Vector Database (Pinecone Learn)](https://www.pinecone.io/learn/vector-database/)
- Vector databases find near vectors with approximate nearest-neighbour indexes (HNSW graphs, product quantization, locality-sensitive hashing) instead of comparing the query with every stored vector, and they store metadata with each vector for filtering. — [What is a Vector Database (Pinecone Learn)](https://www.pinecone.io/learn/vector-database/)
- In retrieval-augmented generation the application retrieves context from a vector database by semantic search and gives it to the language model with the question (named on Tuesday only; taught in week 9). — [Retrieval-Augmented Generation (Pinecone Learn)](https://www.pinecone.io/learn/retrieval-augmented-generation/)
- Python's `sqlite3` module is a lightweight disk-based database with no separate server; values must be bound with `?` placeholders rather than string formatting to avoid SQL injection, an `INSERT` opens a transaction that `commit()` saves, and SQLite `BLOB` maps to Python `bytes`. — [sqlite3 (Python documentation)](https://docs.python.org/3/library/sqlite3.html)
- `ndarray.tobytes()` copies an array's raw bytes and `np.frombuffer(blob, dtype=...)` reads them back as a 1-D array whose dtype defaults to float64, so a float32 vector must be read back with `dtype=np.float32`. — [numpy.frombuffer](https://numpy.org/doc/stable/reference/generated/numpy.frombuffer.html)
- Chroma's single-node store keeps documents and metadata in SQLite and each collection's HNSW index in RAM, persisting both to disk; inserts and queries take longer as a collection grows. — [Single-Node Performance (Chroma Docs)](https://docs.trychroma.com/guides/performance/single-node)
- Chroma's client constructors are `EphemeralClient` (in-memory, for local use), `PersistentClient(path=...)` (stores data on disk in that directory), `HttpClient(host, port)` (connects to a Chroma server) and `CloudClient`; `heartbeat()` returns the server time in nanoseconds and is used to check the server is alive. — [Client (Chroma Python reference)](https://docs.trychroma.com/reference/python/client)
- A collection's distance space is set with `configuration={"hnsw": {"space": "cosine"}}`; the default is `l2` (squared L2), and the cosine distance is d = 1 - (A·B)/(|A||B|), so lower means closer. — [Configure Collections (Chroma Docs)](https://docs.trychroma.com/docs/collections/configure)
- Chroma's default embedding function uses the all-MiniLM-L6-v2 model, runs locally and downloads its model files automatically, and is attached to every collection created without an `embedding_function`. — [Embedding Functions (Chroma Docs)](https://docs.trychroma.com/docs/embeddings/embedding-functions)
- In Chroma, `add` with an id that already exists is ignored without an error, embeddings of the wrong dimension raise, and metadata values are strings, integers, floats, booleans or non-empty lists of one type. — [Adding Data to Chroma Collections (Chroma Docs)](https://docs.trychroma.com/docs/collections/add-data)
- Chroma's `update` changes any field of existing records, an id that is not found is logged and ignored, and documents sent without embeddings are re-embedded with the collection's embedding function. — [Update Data (Chroma Docs)](https://docs.trychroma.com/docs/collections/update-data)
- Chroma's `query` ranks by nearest-neighbour similarity and returns 10 results per query unless `n_results` says otherwise, column-major (one inner list per query); by default it includes documents, metadatas and distances, while `get` returns records by id or filter with no ranking. — [Query and Get (Chroma Docs)](https://docs.trychroma.com/docs/querying-collections/query-and-get)
- Chroma runs as a server in Docker with `docker run -v ./chroma-data:/data -p 8000:8000 chromadb/chroma`, and a Python program connects with `chromadb.HttpClient(host='localhost', port=8000)`. — [Docker (Chroma Docs)](https://docs.trychroma.com/guides/deploy/docker)
- Pinecone nests an organization, its projects, each project's indexes, and each index's namespaces; serverless Pinecone keeps data in object storage, separates the write and read paths, and reads check an in-memory table so new data is searchable right after a write. — [Pinecone architecture (Pinecone Docs)](https://docs.pinecone.io/guides/get-started/database-architecture)

### Vector overview
- Interview questions: What is a vector embedding, and how does it represent data in a machine-readable form? (qc4.vector-databases-chroma-and-pinecone.R03); What does cosine similarity measure, and what range does it take? (qc4.vector-databases-chroma-and-pinecone.R03); Why does cosine similarity ignore a vector's length, and what does a score of 0 mean?
- Adjacent concept: Euclidean distance from week 6's k-means, recalled in one line — the straight-line distance between two points; comparing it with cosine is Wednesday's.
- Trade-off or limit: a hand-made vector of two features (the four films) carries only what its features say; a learned embedding's 384 numbers have no names, so a single number cannot be read alone — [Embeddings: Embedding space and static embeddings (Google ML Crash Course)](https://developers.google.com/machine-learning/crash-course/embeddings/embedding-space)
- Recognise on sight: `np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))`; `scores = kb_vectors @ query_vector` on unit vectors.
- Claims:
  - An embedding is a vector representation of data, and closeness in the embedding space reads as similarity — [Embeddings: Embedding space and static embeddings (Google ML Crash Course)](https://developers.google.com/machine-learning/crash-course/embeddings/embedding-space)
  - By hand: cos([3, 4], [6, 8]) = (18 + 32) / (5 × 10) = 1.0 and cos([3, 4], [4, -3]) = (12 - 12) / 25 = 0.0 (run: NumPy prints 1.0 and 0.0) — [Configure Collections (Chroma Docs)](https://docs.trychroma.com/docs/collections/configure) (the cosine formula)
  - Cosine similarity runs from -1 (opposite) through 0 (unrelated directions) to 1 (same direction); Chroma's cosine distance is 1 minus it — [Configure Collections (Chroma Docs)](https://docs.trychroma.com/docs/collections/configure)
  - For vectors of length 1 the dot product is the cosine similarity, which is why `embed` normalises — [SentenceTransformer API reference](https://sbert.net/docs/package_reference/sentence_transformer/SentenceTransformer.html)

### Storing and retrieving data in SQLite
- Interview questions: How would you store a vector in a relational table?; Why use `?` placeholders instead of building the SQL string?; What happens to search time as the table grows from 50,000 to 100,000 rows, and why?
- Adjacent concept: week 3's SQL `WHERE` — `WHERE category = 'billing'` narrows the rows before the comparison, which is what a vector database's metadata filter does at scale (operators are Wednesday's).
- Trade-off or limit: SQLite has no vector index, so every search reads every row and compares in Python; time grows in step with the row count — [sqlite3 (Python documentation)](https://docs.python.org/3/library/sqlite3.html)
- Recognise on sight: `vector BLOB` in a `CREATE TABLE`; `con.execute("INSERT INTO articles VALUES (?, ?, ?, ?, ?, ?, ?)", (..., vector.tobytes()))`; `np.frombuffer(blob, dtype=np.float32)`.
- Claims:
  - SQLite needs no server and keeps a whole database in one file; Python ships the `sqlite3` module — [sqlite3 (Python documentation)](https://docs.python.org/3/library/sqlite3.html)
  - `executemany` runs one parameterised statement per row, and `commit()` saves the transaction the `INSERT` opened — [sqlite3 (Python documentation)](https://docs.python.org/3/library/sqlite3.html)
  - `tobytes()` writes 384 float32 numbers as 1,536 bytes; reading with the default dtype (float64) gives 192 wrong numbers and no error — [numpy.frombuffer](https://numpy.org/doc/stable/reference/generated/numpy.frombuffer.html) and [numpy.ndarray.tobytes](https://numpy.org/doc/stable/reference/generated/numpy.ndarray.tobytes.html)

## Glossary terms (3–8; one-sentence plain-language definitions; aka = alternate surface forms)

- cosine similarity | A number from -1 to 1 that says how closely two vectors point the same way, ignoring their lengths, with 1 meaning the same direction. | aka: cosine similarities, cosine score
- similarity search | Finding the stored vectors closest to a query's vector and returning them in order, nearest first. | aka: nearest-neighbour search, nearest neighbor search, vector search
- brute-force search | Comparing a query with every stored vector one by one, which is exact but takes longer with every row added. | aka: exhaustive search, linear scan
- approximate nearest neighbour index | A structure, such as an HNSW graph, that finds vectors close to a query without comparing it with every stored one, trading a little accuracy for speed. | aka: ANN index, HNSW index, HNSW
- PersistentClient | The Chroma client that keeps its collections in a folder on disk, so they are still there after the program restarts. | aka: persistent client, chromadb.PersistentClient
- serverless index | A Pinecone index whose storage and computing are run and scaled by Pinecone and billed by use, with no hardware chosen in advance. | aka: serverless indexes, ServerlessSpec
- Colab Secrets | The key-icon panel in Colab that stores named values such as an API key for your account, read in a cell with userdata.get and never saved in the notebook. | aka: Secrets panel, userdata.get
- CRUD | Short for create, read, update and delete, the four basic operations on stored records. | aka: CRUD operations

## Common pitfalls (3–6; feed the runbook "where trainees get stuck" and quiz distractors)

- Reading Chroma's number as a score: a cosine distance of 0.54 is a similarity of about 0.46, so lower is closer in Chroma and higher is closer in Pinecone; learners sort the wrong way or say the "0.55" article is the best Chroma match.
- Sending a changed text without its vector: on `embedding_function=None` Chroma 1.5.9 raises `ValueError: You must provide an embedding function to compute embeddings...`, and on a collection left on the default function the text is silently embedded by Chroma's own MiniLM copy; relatedly, `add` with an existing id and `update` with a missing id both do nothing and raise nothing, so the count is the check.
- Typing the Pinecone key into a cell "just to test", printing `userdata.get(...)`, or saving a copy to GitHub with a key in it: the repositories are public and bots scan them; the fix is to delete the key in the console at once and make a new one. The two Colab errors are different fixes: `SecretNotFoundError` means the secret's name is wrong or missing, `NotebookAccessError` means Notebook access is off.
- Passing NumPy straight to Pinecone: on 9.1.0 an array in `upsert`'s `values` raises `TypeError: Type is not JSON serializable: numpy.float32`, an array in `query(vector=...)` raises `... numpy.ndarray`, and a NumPy integer in metadata raises `... numpy.int64`; the fix is `.tolist()` on every vector and metadata from the `KB` dicts; every call is keyword-only (a positional call raises `TypeError: Index.query() takes 1 positional argument ...`), and `include_metadata=True` must be set or the titles come back as `None`.
- Reading `describe_index_stats()` straight after `upsert` and seeing 0 or an old count, then upserting again: Pinecone is eventually consistent, so the notebook waits with `wait_for_count`; similarly a fetch straight after `update(set_metadata=...)` can still show the old value.
- `np.frombuffer(blob)` without `dtype=np.float32` returns 192 meaningless float64 numbers with no error, and `np.argsort(scores)[:3]` returns the three WORST articles (ascending); the notebook uses `dtype=np.float32` and `np.argsort(-scores)[:3]` (Colab's NumPy 2.4.6 has no `descending=`).
