## Claims (≥ metrics.research.claimsMin; each MUST carry a source on a full gate; light gate: source optional but recommended)

- Encoder models use only the encoder of a Transformer, read the whole sentence in both directions and suit understanding tasks such as sentence classification; decoder models use only the decoder, are auto-regressive and suit text generation, predicting one token at a time — [Transformer Architectures](https://huggingface.co/learn/llm-course/chapter1/6)
- BERT is a bidirectional transformer pretrained to predict masked tokens and whether one sentence follows another; its representations are adapted to other tasks by fine-tuning an additional layer or head — [BERT (Transformers docs)](https://huggingface.co/docs/transformers/model_doc/bert)
- Google released BERT in November 2018 as "the first deeply bidirectional, unsupervised language representation", fine-tuned on small-data tasks like question answering and sentiment analysis — [Open Sourcing BERT](https://research.google/blog/open-sourcing-bert-state-of-the-art-pre-training-for-natural-language-processing/)
- GPT-2 is a causal transformer language model pretrained to predict the next word from all the previous words; each token attends only to earlier tokens, which suits text generation — [GPT-2 (Transformers docs)](https://huggingface.co/docs/transformers/model_doc/gpt2)
- Llama 3.1 is "an auto-regressive language model that uses an optimized transformer architecture", released by Meta under the Llama 3.1 Community License, whose terms must be accepted before the weights download — [meta-llama/Llama-3.1-8B-Instruct](https://huggingface.co/meta-llama/Llama-3.1-8B-Instruct)
- Meta's Llama docs cover getting the models from Hugging Face and Kaggle and self-hosting them, and list Llama 4, Llama 3 (3.1, 3.2, 3.3) and Llama 2, each with its own licence and use policy — [Get started with Llama](https://dev.meta.ai/llama/)
- Claude is a family of models reached through the Claude API and cloud platforms (Amazon Bedrock, Google Cloud, Microsoft Foundry); each model has an API ID such as `claude-haiku-5-5`, priced per million input and output tokens — [Models overview](https://platform.claude.com/docs/en/about-claude/models/overview)
- API usage is billed per token: "MTok: Million tokens. $5 / MTok is $5 for every million tokens"; input and output tokens are priced separately — [Pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- A program reaching a hosted model sends its key with every request; Anthropic's quickstart exports the key as `ANTHROPIC_API_KEY` and its SDK reads that variable automatically — [Get started with Claude](https://platform.claude.com/docs/en/get-started)
- OpenAI's GPT models are hosted and reached through its API by model ID (the models page currently recommends `gpt-6-astra`); model IDs change between versions, so a page names the family, not a version — [Models | OpenAI API](https://developers.openai.com/api/docs/models)
- An API key must never be committed to a repository or shipped in a browser or mobile app; OpenAI recommends an environment variable, a unique key per team member, expiry and rotation — [Best practices for API key safety](https://help.openai.com/en/articles/5112595-best-practices-for-api-key-safety)
- GitHub Copilot is "an AI assistant that helps you write, understand, and ship software", offering code completion, chat and an agent, with a free plan, in VS Code, Visual Studio, JetBrains IDEs, Eclipse and Xcode — [About GitHub Copilot](https://docs.github.com/en/copilot/get-started/what-is-github-copilot) and [Where to use GitHub Copilot](https://docs.github.com/en/copilot/get-started/where-to-use-github-copilot)
- Copilot's own application card states that generated code "may not actually be semantically or syntactically correct", that users "are responsible for reviewing and validating suggestions before accepting them", and that suggestions can match public training code — [Application card: GitHub Copilot inline suggestions](https://docs.github.com/en/copilot/responsible-use/copilot-code-completion)
- Codeium rebranded as Windsurf ("Codeium is now Windsurf"; "All the extensions have been renamed to the Windsurf Plugin") in the April 2025 changelist — [Changelist: April 2025](https://devin.ai/blog/changelist-apr25)
- On June 2, 2026 Cognition renamed the Windsurf editor Devin Desktop ("the next generation of Windsurf: Devin Desktop"); plans, pricing and extensions stayed the same — [Windsurf is now Devin Desktop](https://devin.ai/blog/windsurf-is-now-devin-desktop/)
- Windsurf Plugins bring Autocomplete, Chat and Command to JetBrains IDEs; the JetBrains plugin is in maintenance mode — [Welcome to Windsurf Plugins](https://docs.devin.ai/windsurf/plugins/getting-started)
- An agentic coding tool is a different category from an editor assistant: Claude Code "reads your codebase, edits files, runs commands", and creates commits and pull requests — [Claude Code overview](https://code.claude.com/docs/en/overview)
- Chain of thought is "a series of intermediate reasoning steps", and prompting for it significantly improves large language models on complex reasoning — [Chain-of-Thought Prompting Elicits Reasoning in Large Language Models](https://arxiv.org/abs/2201.11903)
- Reasoning models "generate an internal chain of thought", so they do better with high-level guidance, while GPT-style models benefit from explicit step instructions; delimiters such as XML tags mark where supplied content begins and ends — [Prompt engineering (OpenAI)](https://developers.openai.com/api/docs/guides/prompt-engineering)
- Manual chain-of-thought (asking the model to think through the problem before it answers) is a fallback when a model's built-in thinking is off; explicit prompt chaining is still useful "when you need to inspect intermediate outputs or enforce a specific pipeline structure" — [Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)
- Prompt files are reusable Markdown prompts with the `.prompt.md` extension, stored by default in a workspace's `.github/prompts` folder, with an optional YAML header and a body — [Use prompt files in VS Code](https://code.visualstudio.com/docs/copilot/customization/prompt-files)
- Repository-wide custom instructions for Copilot live in `.github/copilot-instructions.md` and apply to every request made in the context of that repository — [Custom instructions for GitHub Copilot](https://docs.github.com/en/copilot/concepts/prompting/response-customization)
- OpenAI recommends pinning production applications to model snapshots and building evaluation suites that measure prompt behaviour as prompts change, and is deprecating reusable prompt objects in favour of prompts kept in application code — [Prompt engineering (OpenAI)](https://developers.openai.com/api/docs/guides/prompt-engineering)
- Prompt injection "occurs when user prompts alter the LLM's behavior or output in unintended ways"; indirect injection occurs when the model accepts input from external sources such as websites or files — [LLM01:2025 Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)
- OWASP's mitigations for prompt injection include constraining model behaviour, defining and validating output formats, segregating and identifying external content, human approval for high-risk actions and least privilege, and it states "it is unclear if there are fool-proof methods of prevention" — [LLM01:2025 Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)
- Sensitive information disclosure covers PII, financial details, health records and confidential business data; users should be guided to avoid entering sensitive information — [LLM02:2025 Sensitive Information Disclosure](https://genai.owasp.org/llmrisk/llm022025-sensitive-information-disclosure/)
- Consumer tier: "On personal workspaces with ChatGPT Free, Plus, or Pro, data sharing is enabled by default." Temporary chats are not used for training but "may be retained for up to 30 days for safety purposes" — [Data controls in ChatGPT](https://help.openai.com/en/articles/7730893-data-controls-in-chatgpt)
- Business and API tier: "By default, we do not use your business data for training our models", and OpenAI "may securely retain API inputs and outputs for up to 30 days to provide the services and to identify abuse" — [Enterprise privacy at OpenAI](https://openai.com/enterprise-privacy/)

### LLMs (GPT, BERT, Claude, Llama, Copilot, Codeium)
- Interview questions: What is the difference between an encoder model like BERT and a decoder model like GPT, and which would you use to write a triage reason for a ticket? What does "open weights" mean for Llama compared with a hosted model like GPT or Claude, and what does each mean for where your data goes? Name the four ways a developer reaches a model (chat assistant, editor assistant, agentic coding tool, API access) and give an example of each; follow-up (a level beyond): your team wants an editor assistant for the employer's code. What do you check first: which tier the vendor's data terms cover, whether the employer has approved it, and how the API key or seat is managed?
- Adjacent concept: Model versus product — GPT, Claude and Llama are model families, while ChatGPT, GitHub Copilot and Codeium (now Windsurf) are products built on models, which is why a product's data terms and a model's architecture are two separate questions an interviewer asks next.
- Trade-off or limit: an open-weights model keeps prompts on the team's own machine or server but the team supplies the hardware, the updates and the safety work, and the weights still come with a licence to accept; a hosted model needs no hardware but every prompt crosses the network to the provider under its data terms — [meta-llama/Llama-3.1-8B-Instruct](https://huggingface.co/meta-llama/Llama-3.1-8B-Instruct) and [Enterprise privacy at OpenAI](https://openai.com/enterprise-privacy/)
- Recognise on sight: a model card that says "fill-mask" or "text-classification" (encoder, BERT-style) against one that says "text-generation" or "causal LM" (decoder); in config, a model id such as `claude-haiku-5-5` next to an environment variable name such as `ANTHROPIC_API_KEY` (API access), never the key's value.
- Claims:
  - Encoder models read the full sentence in both directions and suit understanding tasks such as classification, while decoder models suit generation; BERT is the encoder example: it predicts masked tokens and is adapted to tasks by fine-tuning a head, so out of the box it labels or fills in text and does not write a paragraph — [Transformer Architectures](https://huggingface.co/learn/llm-course/chapter1/6) and [BERT (Transformers docs)](https://huggingface.co/docs/transformers/model_doc/bert)
  - GPT-style models are causal: each token sees only earlier tokens, the shape of next-token generation taught on Monday — [GPT-2 (Transformers docs)](https://huggingface.co/docs/transformers/model_doc/gpt2)
  - Claude models are hosted and reached through the Claude API and partner clouds by model ID — [Models overview](https://platform.claude.com/docs/en/about-claude/models/overview)
  - Llama weights download from Hugging Face or Kaggle under Meta's licence and can be self-hosted — [Get started with Llama](https://dev.meta.ai/llama/)
  - API access is billed per million input and output tokens, and the key that pays for it is a credential kept in an environment variable, the same pattern as week 3's `DESK_DB_PASSWORD` — [Pricing](https://platform.claude.com/docs/en/about-claude/pricing) and [Best practices for API key safety](https://help.openai.com/en/articles/5112595-best-practices-for-api-key-safety)
  - Editor assistant examples: GitHub Copilot (completion, chat, agent; free plan) and Codeium, now Windsurf Plugins for JetBrains (Autocomplete, Chat, Command) — [About GitHub Copilot](https://docs.github.com/en/copilot/get-started/what-is-github-copilot) and [Welcome to Windsurf Plugins](https://docs.devin.ai/windsurf/plugins/getting-started)

### Use cases for LLMs
- Interview questions: Give three tasks where you would use an assistant on a data team and one where you would not; how do you check a regular expression an assistant wrote for ticket ids? Who decides which slowly changing dimension type `dim_customer` uses, and why is it not the model? Follow-up (a level beyond): a colleague asks an assistant which customers' data may be sent to a vendor. What is wrong with the question, and who owns that decision?
- Adjacent concept: Verification cost — a use case is a good fit when checking the answer is cheap (a test, a doc, a diff a reviewer reads), which is why a generated regex with a failing test is a better fit than a generated architecture decision nobody can test.
- Trade-off or limit: an assistant drafts fast but its output may look valid and still be wrong, and the developer assumes the risk of bugs, vulnerabilities and IP infringement in what they accept — [Application card: GitHub Copilot inline suggestions](https://docs.github.com/en/copilot/responsible-use/copilot-code-completion)
- Recognise on sight: a pull request description or commit message that restates the diff in fluent general terms ("improves robustness") without naming what changed or why, a sign of an unedited generated draft.
- Claims:

  - Good fit: explaining existing code to a new teammate, drafting commit messages and tests; agentic tools advertise exactly these chores, and the output is still reviewed — [Claude Code overview](https://code.claude.com/docs/en/overview)
  - An assistant is "a brilliant but new employee who lacks context on your norms and workflows", so a use case needs the code, the error and the constraint in the prompt — [Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)

### LLM best practices
- Interview questions: What is iterative prompting, and what changes between one round and the next? (qc3.genai-in-development.R04); What is chain-of-thought prompting, and why does asking for the steps before the answer make a reply easier to check? (qc3.genai-in-development.R04); What is sequential prompting (prompt chaining), and when would you split one big prompt into a chain? (qc3.genai-in-development.R04); How would a team share and review the prompts it relies on? (prompt library in the repository, prompt changes as pull requests) (qc3.genai-in-development.P01); Follow-up (a level beyond): a prompt in the team's `prompts/` folder starts giving worse triage labels after a teammate's edit. How do you find the change, prove it is worse and roll it back? (git history of the prompt file, a fixed set of example tickets with expected labels, revert in a pull request) (qc3.genai-in-development.P01, qc3.genai-in-development.R04)
- Adjacent concept: Evaluation set — once prompts live in version control, the next question is how a change is judged: a fixed set of inputs with expected outputs (Monday's three held-out titles and their expected labels are a tiny one), the prompt equivalent of a unit test.
- Trade-off or limit: chain-of-thought and chaining cost more tokens and time; models with built-in reasoning already think internally and do better with high-level guidance, and some Claude models may decline a request to write out their reasoning, so the visible steps are asked for when a person must check them — [Prompt engineering (OpenAI)](https://developers.openai.com/api/docs/guides/prompt-engineering) and [Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)
- Recognise on sight: a repository folder `prompts/` (or `.github/prompts/*.prompt.md`) with one file per prompt, and a pull request diff on such a file, for example `-Answer with high, normal or low.` / `+Answer with exactly one of high, normal, low or unsure, then one reason line.`
- Claims:
  - Chain of thought is a series of intermediate reasoning steps the model writes before its answer — [Chain-of-Thought Prompting Elicits Reasoning in Large Language Models](https://arxiv.org/abs/2201.11903)
  - Manual chain-of-thought: ask the model to reason through the problem before it answers and put the final answer in a marked place so it can be extracted — [Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)
  - Worked check for the ticket 2 pair (verified locally with `py` on 2026-11-03): `sql/seed.sql` at 55f65d7 opens ticket 2 (`Invoice PDF is blank`, `normal`) at `2026-10-17 12:00:00` and closes it at `2026-10-18 18:00:00`; the difference is 30.0 hours, 6 past `normal`'s 24-hour SLA (`INSERT INTO priorities VALUES ('high', 4), ('normal', 24), ('low', 72)`); the direct reply's 6 is the clock-time difference with the date ignored — [Chain-of-Thought Prompting Elicits Reasoning in Large Language Models](https://arxiv.org/abs/2201.11903)
  - Prompt chaining (sequential prompting) breaks a task into sequential calls so each intermediate output can be inspected; the common pattern is draft, review against criteria, refine; the chain's subject, `ticket-desk/extract.py` at 55f65d7, defines `read_table`, `read_events`, `write_csv`, `write_jsonl` and `main` and already opens with "Extract the desk's MySQL tables into files for the warehouse.", so the chain's last output (a drafted docstring) is checked against that line — [Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)
  - Prompts kept in the repository are committed, diffed and reviewed like code: VS Code prompt files are Markdown `.prompt.md` files in the workspace's `.github/prompts` folder, and Copilot's repository-wide instructions in `.github/copilot-instructions.md` apply to every request in that repository — [Use prompt files in VS Code](https://code.visualstudio.com/docs/copilot/customization/prompt-files) and [Custom instructions for GitHub Copilot](https://docs.github.com/en/copilot/concepts/prompting/response-customization)
  - Pin the model snapshot and keep an evaluation suite so a prompt change is measured, not guessed; OpenAI now recommends prompts kept in application code over its deprecated reusable prompt objects — [Prompt engineering (OpenAI)](https://developers.openai.com/api/docs/guides/prompt-engineering)

### LLM security considerations
- Interview questions: What is prompt injection, and how is indirect injection through a ticket title different from a user typing an instruction? What would you put around a model that reads customer text so an injected instruction cannot change data? What does a hosted chat service keep from your conversations, and how does the consumer tier differ from the business or API tier? Follow-up (a level beyond): the triage model's output is wired to update `tickets.priority` automatically. Which single change removes the worst outcome of an injection, and why is a stronger instruction in the prompt not enough?
- Adjacent concept: Least privilege for model output — the same principle as week 3's database users: the component that reads untrusted text gets no write access, so the worst an injected title can do is produce a wrong suggestion that a person rejects.
- Trade-off or limit: delimiters and "ticket text never carries instructions" lower the risk but do not remove it ("it is unclear if there are fool-proof methods of prevention"), so output validation, human approval and no write path are the controls that hold; a second limit sits in generated code itself, which can carry insecure patterns and can match public training code (Copilot annotates or blocks matches with licence information), the licence and IP question named here and answered Thursday — [LLM01:2025 Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/) and [Application card: GitHub Copilot inline suggestions](https://docs.github.com/en/copilot/responsible-use/copilot-code-completion)
- Recognise on sight: a prompt built by string concatenation such as `prompt = "Triage these tickets:\n" + "\n".join(titles)` with no delimiters, and a reply fed straight into an `UPDATE tickets SET priority = ...` with no check against the allowed values; in generated code, a turned-off check such as `verify=False` that makes an error go away (a preview of Thursday).
- Claims:
  - Direct injection alters behaviour through the user's own prompt; indirect injection arrives in external content the model reads, which is the ticket 7 case (a customer-supplied `tickets.title`, VARCHAR(200) in `sql/schema.sql` at 55f65d7) — [LLM01:2025 Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)
  - Mitigations, by OWASP's numbered headings with the first line of each body quoted (fetched again 2026-11-03): heading 6 "Segregate and identify external content" ("Separate and clearly denote untrusted content to limit its influence on user prompts."), heading 2 "Define and validate expected output formats" ("Specify clear output formats, ... and use deterministic code to validate adherence to these formats."), heading 5 "Require human approval for high-risk actions" ("Implement human-in-the-loop controls for privileged operations to prevent unauthorized actions."), and heading 4 "Enforce privilege control and least privilege access"; these map to fencing the titles, checking the output against `high`, `normal`, `low`, `unsure`, a person approving any priority change, and the model's output having no write path to `tickets` — [LLM01:2025 Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)
  - Delimiters such as XML tags mark where supplied content begins and ends, the provider-documented way to fence data in a prompt — [Prompt engineering (OpenAI)](https://developers.openai.com/api/docs/guides/prompt-engineering)
  - Data leakage, consumer tier (verbatim, printed in the runbook and pair pack; URL https://help.openai.com/en/articles/7730893-data-controls-in-chatgpt, the old `7730893-data-controls-faq` link redirects there): "On personal workspaces with ChatGPT Free, Plus, or Pro, data sharing is enabled by default." / temporary chats "are not used to improve OpenAI models" and "may be retained for up to 30 days for safety purposes" / "If you choose to provide feedback, such as selecting thumbs up or thumbs down on a response, the entire conversation associated with that feedback may be used to train OpenAI models." / a deleted chat (verbatim, URL https://help.openai.com/en/articles/8983778-chat-and-file-retention-in-chatgpt): "OpenAI schedules it for permanent deletion from its systems within 30 days, unless the chat was already de-identified and disassociated from your account or OpenAI must retain it longer for security or legal obligations." — [Data controls in ChatGPT](https://help.openai.com/en/articles/7730893-data-controls-in-chatgpt) and [Chat and file retention in ChatGPT](https://help.openai.com/en/articles/8983778-chat-and-file-retention-in-chatgpt)
  - Data leakage, business and API tier (verbatim; URL https://openai.com/enterprise-privacy/, covering ChatGPT Business, Enterprise, Healthcare, Edu, Teachers and the API Platform): "By default, we do not use your business data for training our models." / "Except for certain endpoints and features listed in our platform documentation, OpenAI may securely retain API inputs and outputs for up to 30 days to provide the services and to identify abuse."; the API platform doc answers the same question (verbatim, URL https://developers.openai.com/api/docs/guides/your-data): "As of March 1, 2023, data sent to the OpenAI API is not used to train or improve OpenAI models" / "By default, abuse monitoring logs are generated for all API feature usage and retained for up to 30 days" — [Enterprise privacy at OpenAI](https://openai.com/enterprise-privacy/) and [Data controls in the OpenAI platform](https://developers.openai.com/api/docs/guides/your-data)

## Glossary terms (3–8; one-sentence plain-language definitions; aka = alternate surface forms)

- encoder model | A language model that reads a whole text in both directions to understand or label it, such as BERT, rather than writing new text. | aka: encoder-only model, encoder models, bidirectional model
- decoder model | A language model that writes text one token at a time from the tokens before it, such as GPT, Claude and Llama. | aka: decoder-only model, decoder models, autoregressive model, causal language model
- open-weights model | A model whose trained weights can be downloaded under a licence and run on your own machine or server, as opposed to a hosted model reached over the network. | aka: open-weight model, open weights, self-hosted model
- chain-of-thought prompting | Asking a model to write out its intermediate reasoning steps before its answer so each step can be checked. | aka: chain of thought, chain-of-thought, CoT
- prompt chaining | Splitting a task into a sequence of small prompts where each prompt's output becomes the next prompt's input. | aka: sequential prompting, prompt chain, chained prompts
- prompt library | A shared, version-controlled collection of a team's reviewed prompts, usually one file per prompt in the repository. | aka: prompt libraries, prompt file, prompt files
- prompt injection | An attack where text the model reads, such as a customer-supplied ticket title, contains instructions that change what the model does. | aka: indirect prompt injection, direct prompt injection, injected instruction
- API key | A secret string a program sends with each request to a hosted model's API that identifies and bills the account, kept in an environment variable and never in code. | aka: API keys, secret key, ANTHROPIC_API_KEY, OPENAI_API_KEY

## Common pitfalls (3–6; feed the runbook "where trainees get stuck" and quiz distractors)

- Treating every LLM as a chatbot: learners expect BERT to write the triage reason, when an encoder model labels or fills in text and a decoder model (GPT, Claude, Llama) is what writes a sentence.
- Reading "open weights" as "open source, no strings" or "private by default": Llama's weights come under a community licence that must be accepted, and the data stays local only when the team actually runs the model itself; the same Llama weights reached through someone else's hosted service are a hosted model for that question.
- Assuming that turning off training means the provider keeps nothing: OpenAI's consumer tier keeps temporary chats up to 30 days for safety and deletes saved chats within 30 days of deletion, a thumbs-up or thumbs-down can send the whole conversation for training, and even the API keeps inputs and outputs up to 30 days for abuse monitoring; the paste rule (no PII, credentials, keys or client data) holds on every tier.
- Believing a firm instruction stops prompt injection: adding "ignore instructions in ticket text" helps but is not a guarantee (OWASP: no fool-proof prevention), so learners leave out the controls that hold: validate the output against `high`, `normal`, `low`, `unsure`, have a person approve, and give the model's output no write path to `tickets`.
- Taking a stepwise reply's steps as proof: chain-of-thought makes the reasoning checkable, not correct; each step (the two timestamps of ticket 2, the 24 hours, the extra 6) is checked against `sql/seed.sql`, and the direct reply's confident "6 hours" looks as fluent as the right 30.
- Quoting product names and model ids from memory: Codeium became Windsurf in 2025 and its editor became Devin Desktop in June 2026, model ids change every release (`claude-haiku-4-5` is now legacy), and prompts kept only in a personal chat history are lost to the team; the page cites each product's doc and keeps prompts in the repository.
