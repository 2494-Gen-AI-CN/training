## Glossary terms (3–8; one-sentence plain-language definitions; aka = alternate surface forms)

- pair programming | Two people working on one task at one screen, one typing (the driver) while the other reviews and steers (the navigator). | aka: pairing, driver, navigator
- inline suggestion | Dimmed code an editor assistant shows at the cursor as you type, added to the file only if you accept it. | aka: inline suggestions, code completion, ghost text
- next edit suggestion | An editor assistant's guess at where your next change goes and what it is, based on the edit you just made. | aka: next edit suggestions, NES
- content exclusion | A Copilot setting that stops the assistant from reading chosen files, so they never inform its suggestions or chat replies. | aka: excluded files, file exclusion
- telemetry | Usage and error data a program sends back to its maker, controlled in VS Code by one setting and separately by each extension. | aka: usage data, telemetryLevel
- off-by-one error | A bug where a comparison or count is wrong by exactly one step, such as `<` written where `<=` was meant at a boundary. | aka: off-by-one, boundary bug, fencepost error
- slash command | A short command typed in an assistant's chat panel, such as `/tests` or `/explain`, that runs a ready-made request on the selected code. | aka: slash commands

## Common pitfalls (3–6; feed the runbook "where trainees get stuck" and quiz distractors)

- Treating "all generated tests pass" as proof the code is right: the assistant wrote `assert ticket_age_band(24) == "over 24"` from the buggy code, so the suite passes and the requirement (24 is `4 to 24`) is still broken; the test that matters comes from the requirement, not the code.
- Zero-shotting a function prompt with no boundaries or expected outputs, then blaming the model for guessing the edge; the round-2 prompt that names 3, 4, 24 and 25 and their outputs is the fix.
- Trusting a confident keyword (`QueryJobConfig(params=...)`) because it looks plausible and reads well; the reference lists `query_parameters` and the real library raises `AttributeError: Property params is unknown`.
- Accepting a drafted docstring or README because it is fluent: `after` is an `event_id` watermark (`event_id > %s`), not a timestamp, and the `--dry-run` flag does not exist because no desk file reads `sys.argv` or imports `argparse`.
- Believing the editor's telemetry switch or content exclusion covers everything: extensions keep their own telemetry, exclusion does not apply in Edit and Agent modes, and a free personal Copilot account may train on interactions unless the setting is disabled.
- Writing the second product as "Codeium (now Windsurf)" from memory: Windsurf has been Devin Desktop since 2026-06-02 and its JetBrains plugin is in maintenance mode; a product fact comes from the vendor's current doc.
