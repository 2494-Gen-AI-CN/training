# Runbook critic — PASS criteria

You are judging `trainer/<week>/<day>/runbook.md`. You are NOT the author. Return `pass=false` with specific critiques if ANY item fails.

1. Headings present: `# <id> runbook`, `## Day at a glance`, `## Objectives`, `## Setup check`, then the teaching blocks in the order the day runs them: one `## Demo: <walkthrough>` per walkthrough block of the day (`<walkthrough>` exactly as the week plan's ladder names it plus `.md`, e.g. `01-desk-modules.md`, the file in `trainer/<week>/demos/`; AM before PM) and one `## Facilitation N: <subtopic> (M min)` per concept subtopic that has no demo (on a `demoFormat: none` day every block is a Facilitation block and there is no Demo block); on a `demoFormat: notebook` day (D-0085) there is no Demo block and ONE `## Notebook: <file>.ipynb` overview section followed by its `## Notebook part k: §a–§b (M min)` sections takes its place (item 3c), with Facilitation blocks only for the subtopics the notebook does not cover, `## Notes page handoff`, `## Sprint / project work`, `## Common questions`, `## If running long / short`. On `feedback: true` days also `## Feedback form`; on `kind: review` days also `## Review agenda`. A trailing `## Delivery record (<date>)` section is appended by `harness/close_day.py` after the day (D-0050, D-0055); it is allowed and never judged.
1a. Presentation order (D-0096, runbooks authored from 2026-11-18): after `## Objectives` the file has one `##` section per row of the glance table, in the row order, so reading down the file is reading the day. A `Break` or `Lunch` row has its own short section (`## Break (N min)`, `## Lunch (N min)`) where it falls; `## Feedback form` and `## Review agenda` sit where they run. The only `##` sections with no glance row are the `## Notebook: <file>.ipynb` overview (directly above part 1), `## Common questions` and `## If running long / short`, and the last two are the last two sections of the file. FAIL a section that is out of day order, a glance row with no section, or a notebook pass kept as one section when a break, lunch or Facilitation block falls inside it.
1b. Line 3 links every artifact as markdown links (D-0027, D-0055): the notes page on the public site (`config.siteUrl`), the week's walkthrough folder relatively (`../demos/`), the research brief on the public repo (`config.repoUrl`, absolute, since the trainer repo is separate) and, from 2026-11-18 (D-0096), the day's crib sheet relatively (`crib-sheet.md`). On a `demoFormat: notebook` day from 2026-11-18 (D-0097) line 3 also links the notebook's direct Colab URL, `https://colab.research.google.com/github/<demoRepo.org>/<demoRepo.name>/blob/<demoRepo.branch>/<notebook path>`. Paths match the day's `rel` exactly.
2. "Day at a glance" is a markdown table with a Minutes column; the minutes sum to `metrics.runbook.dayMinutesMin..dayMinutesMax` (330–390). Breaks and lunch are included (a break inside a walkthrough is named in its row, not a row of its own), and one row is `Sprint / project work`. When the prompt carries week-plan rows (D-0034): each walkthrough row's minutes equal the plan's ladder minutes for that block, and the AM/PM order follows the plan's day shape.
3. Each `## Demo:` section is a pointer, not a second copy of the walkthrough: the walkthrough path (`../demos/NN-<slug>.md`, relative to the runbook), its Time and slot, its commit message on the prep branch (the plan's block row), the room state it needs before it starts (the previous block it starts from and what is on screen and in the repo, or "cold"), the stop point if the day runs long (a step number matching the plan's Stop points row, and where the remainder resumes), ≥2 checkpoint questions for the room, and ≥1 pitfall drawn from the research brief. The talk track lives in the walkthrough; a runbook that re-states the steps fails.
3c. Notebook day (D-0085, D-0096): the `## Notebook: <file>.ipynb` section is a short overview: the notebook's path in the demo repo (`notebooks/week-WW/NN_<weekday>_<slug>.ipynb` on `main`), how the trainer opens it in Google Colab and runs the setup cell first, the total time and its parts, and the stop point if the day runs long. The same direct Colab URL as line 3 is written out in this overview and in the Setup check step where learners open the notebook, as the link to paste in the chat (D-0097). The pass itself is in the `## Notebook part k: §a–§b (M min)` sections, one per notebook row of the glance table, each placed where it runs; between them they make a timed pass through the notebook's `##` sections in order, one `### <section> (M min)` each (the headings as the notebook has them; while the notebook is not written yet, the sections the subtopics imply plus one line saying the notebook is authored after the research brief), each opening with content notes (D-0096, runbooks authored from 2026-11-18): a `**Covering:**` line listing the ideas and terms the section introduces, then one `- **<Term>.**` bullet per item saying what it is in a plain sentence, how it works and the values the cells print for it. The test: a substitute trainer who has not prepared can teach the section from these bullets. Then `**With the room:**` with the run order, one "Predict before running:" question with its answer, the "Try changing:" prompt with what the room should see, a "Trap:" line, three to five "If asked:" lines (a likely hard question with its answer in one to three sentences, sourced from the brief or the notes page; the full list lives in `crib-sheet.md`; D-0092) and a "Heads-up:" line only where the notes page and the notebook differ. The last part closes with the Recap and the Quick check questions to ask aloud. FAIL any "Teach:" or "Say:" line and any quoted line for the trainer to recite other than a question. It never copies the notebook's code cell by cell. Each glance notebook row equals the section minutes of its part.
3b. Each `## Facilitation N: <subtopic> (M min)` section is the presenter's lecture notes for that subtopic (D-0089), not an activity plan and not a script (D-0096). The test: a substitute trainer who has opened neither the brief nor the notes page can teach the subtopic from this section alone. In order: `**Goal:**` (what the room can do after); `**Topics introduced, in order:**` (the 2–6 ideas or terms new to the room in this block); one `### Topic k: <idea> (M min)` per listed topic, in that order, each with `**Notes:**` (4–8 sub-bullets of content, not lines to recite: each new term in bold and defined in one plain sentence, the problem it solves or why it exists, how it works, and the concrete example, number or date from the brief), `**On screen:**` (the literal text, table rows or code the trainer types or pastes on the shared screen, written so it can be pasted; D-0090) and `**Ask:**` (≥1 question with the answer the trainer steers toward and the wrong answer to expect); at most one `### Activity: <what> (M min)`, placed after the topic it practises, with the task as a plain instruction, its materials written out in full, the answer key and the debrief; then `**If asked:**` (about three likely hard questions, each with its answer), `**Misconception to surface:**` (≥1 from the brief, and how to surface it) and `**What the room writes down:**` (the lines themselves). Across the block ≥2 Ask questions. FAIL any line that names an activity or a topic without its content: "draw a timeline and fill it as you talk", "discuss the history", "ask the first two questions below", "explain how X works", an On screen line that describes a picture instead of giving the text to paste, a Notes bullet that says what to cover without saying it, a `**Teach:**` or `**Bridge:**` label, a `Say:` line. Topic and Activity minutes sum to the heading's minutes, which match the glance table. Where the brief and the notes page are thin on a topic the notes may be thin, provided they say so and point to the crib sheet. Runbooks delivered before 2026-11-18 keep the earlier shape (Goal, Sequence, Ask the room) and are not re-judged.
4. Objectives (3–5) match the notes page `#goals-modal` list in substance. From exitCriteria.fromWeek (D-0063) the Objectives section ends with a table "Exit criteria mapped to today" (ID | Tier | Criterion | Where) equal to the prompt's exit rows, Required rows first; absent when the prompt carries no rows.
5. `## Sprint / project work` (D-0068) names what the room works on (the current sprint or official project spec on the site's Projects section), where trainees hand in: `<week-dir>/hackathon/` for a sprint, or for an official project the hand-in folder its spec names and never the week's hackathon folder (D-0094), in their own `<FirstnameLastname>` repository (D-0051, quoted in the prompt as LEARNER REPO), never a new per-day or personal-account repository, how the trainer circulates, and ≥2 likely stuck points. Its minutes match the glance table.
6. Every fact or version stated traces to the research brief, or to the day's notes page (which is written from the brief). Lecture notes (the Notes of item 3b, the Covering bullets of 3c, every If asked answer) add no fact from outside the two, and no line carries a † (general-knowledge background lives in the crib sheet only, D-0092).
7. Tone: direct instructions to the trainer, present tense, no filler. Setup steps, recap, activities, breaks and wrap-up are plain instructions; the only quoted sentences are questions put to the room and the learner questions of an If asked line (D-0096).
8. Remote delivery (D-0090, runbooks authored from 2026-11-18): the course is delivered over a video call with a shared screen. Learners working on their own paper is fine.
